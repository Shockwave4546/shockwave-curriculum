## Algorithms

An algorithm is just a set of ordered steps to solve a problem — a recipe, directions to a house, and a Java program are all algorithms. Steps run in order, one at a time. The word sounds intimidating; the idea isn't new to you at all.

## Your First Java Program

Every Java program lives inside a `class`, and every class you run needs a `main` method — that's where the program starts running.

```java
public class MyClass
{
    public static void main(String[] args)
    {
        System.out.println("Hi there!");
    }
}
```

Every open curly brace `{` needs a matching close `}`. The file itself has to be named the same as the class — `MyClass.java` for `public class MyClass`.

## Every Statement Ends With a Semicolon

Each individual instruction is a **statement**, and every statement ends with `;` — think of it like a period ending a sentence.

```java
System.out.println("Hi there!");
```

Miss it, and the program won't compile. This is one of the most common mistakes when you're starting out — expect it, don't stress about it.

Not everything ends in `;`. A line that opens a block, like the `class` or `main` line above, has no semicolon before its `{`.

## Compiling: How Your Code Actually Runs

Computers don't understand Java directly. A **compiler** checks your code for mistakes and translates it into something the computer can run. If it finds a mistake, it stops and tells you — that's a **syntax error**.

For this course, you have two options for actually writing and running your code:

- **Use a real IDE**, like [VS Code](https://code.visualstudio.com/) with the Java extension. This is genuinely how most FRC teams write real robot code, so it's good practice either way.
- **Use this course's built-in checker** — write your code, then paste the finished version in during an exercise to have it checked. This inline checker is still being built. For now: write and run your code in a real IDE (or an online one, like [Replit](https://replit.com/)), then paste the result in when an exercise asks for it.

Either works. Use whichever feels less annoying to switch between.

## Keywords

Words like `public`, `class`, and `void` are **keywords** — reserved words with a fixed meaning in Java. Keywords are always lowercase. Class names, like `String` or a class you write yourself, are capitalized.

## Syntax Errors vs. Run-Time Errors

- A **syntax error** is caught by the compiler, before your program ever runs — a missing `;`, an unmatched `{` or `"`.
- A **run-time error** happens while the program is running, after it already compiled — like dividing by zero.

Both are normal. Finding and fixing errors is called **debugging** — informally, an error is a "bug." If you're stuck, explaining your code line-by-line out loud — even to an inanimate object, a real technique called "rubber duck debugging" — often reveals the problem before you finish explaining it.

## Comments

`//` starts a comment that runs to the end of the line; `/* ... */` comments out everything in between, even across multiple lines. The compiler ignores comments completely — they exist to explain your code to yourself and your teammates.

```java
// this line is ignored by the compiler
int score = 10; // so is this part, after the //
```

## Common Pitfalls

- **Missing a semicolon.** The single most common first error — check the end of the line the compiler points at, and the line just before it.
- **Mismatched capitalization.** `System` is capitalized; `public`, `class`, `void` are not. Java is case-sensitive everywhere.
- **Trusting the error's line number completely.** The compiler tells you where it *noticed* the problem, which is sometimes a line or two after where the actual mistake is.

## Key Takeaways

- An algorithm is an ordered set of steps — you already use these outside of code.
- Every Java program has a `class`, and a `main` method where it starts running.
- Every statement ends with `;`.
- A compiler checks your code and translates it to run; a syntax error is a mistake it catches before your program ever runs.
- Write and run code in a real IDE (like VS Code) or an online one, then paste it in when an exercise asks for it.
- `//` and `/* */` are comments — the compiler ignores them completely.
