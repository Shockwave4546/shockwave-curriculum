# Objects — Instances of Classes

## Class as Blueprint, Object as Instance

A **class** is a blueprint; an **object** is one specific thing built from it — the way a cookie cutter (class) stamps out cookies (objects), all the same shape but each its own cookie. `DriveMotor` is a class; `leftMotor` and `rightMotor` are two separate objects built from it.

`DriveMotor` stands for your team's own motor class — assume it already exists in your robot project (you'll write classes like it yourself in Ch.7). Its constructor takes the PWM channel the motor is plugged into.

```java
DriveMotor leftMotor;
DriveMotor rightMotor;
```

A class also defines a new *type*, the same way `int` or `double` do — `DriveMotor leftMotor;` declares a variable exactly like `int score;` does, just holding a `DriveMotor` instead of a whole number.

## Attributes and Behaviors, Revisited

Every object has:

- **Attributes** — the data it holds (its PWM channel, its current throttle).
- **Behaviors** — what it can do, defined as methods (`setThrottle()`, `getThrottle()`).

The class defines *what* attributes and behaviors exist; each individual object has its *own* values for them. `leftMotor` and `rightMotor` are both `DriveMotor` objects, but each has its own PWM channel and its own current throttle.

## Reference Variables

A variable like `leftMotor` doesn't hold the motor object directly — it holds a **reference** to it, like a tracking number pointing at where the real object lives in memory. This is different from a primitive variable (`int`, `double`), which holds its value directly with nothing in between.

You can create as many objects from one class as you need:

```java
DriveMotor leftMotor = new DriveMotor(1);
DriveMotor rightMotor = new DriveMotor(2);
DriveMotor intakeMotor = new DriveMotor(3);
```

Three separate objects, one class.

## Common Pitfalls

- **Confusing the class name with an object's name.** `DriveMotor` is always the class (capitalized, PascalCase); `leftMotor` is a specific object (camelCase). Mixing these up is a common early error.
- **Assuming two objects of the same class share state.** `leftMotor` and `rightMotor` are both `DriveMotor` objects, but changing one's throttle has zero effect on the other — each object's attributes are entirely its own.

## Key Takeaways

- A class is a blueprint; an object is one specific instance built from it.
- A class defines a new type, just like `int` or `double` — a class variable declares a variable of that type.
- Attributes are an object's data; behaviors are what it can do, defined as methods.
- A reference variable holds a pointer to an object, not the object's data directly.
- Many objects can be created from the same class, each with its own independent attribute values.
