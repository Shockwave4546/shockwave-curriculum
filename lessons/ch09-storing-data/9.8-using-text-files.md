# Using Text Files

**Outline ref:** 9.8 — Using Text Files (CSA 4.6)
**Status:** new — authored lesson (fuller depth than the teaser slide)

## Why Read From a File

A file's data persists even when the program isn't running — useful for loading configuration or data that's too large (or too changeable) to hard-code into your source. A robot might load a table of autonomous starting positions from a file instead of hardcoding them.

## Opening a File

`File` (from `java.io`) represents the file itself; `Scanner` (from `java.util` — the same class used for keyboard input) reads from it:

```java
import java.io.*;
import java.util.*;

File configFile = new File("auto_config.csv");
Scanner scan = new Scanner(configFile); // can throw FileNotFoundException
```

Since opening a file can fail (wrong name, missing file), Java requires you to acknowledge that. The simplest way: add `throws IOException` to the method's header — if the file genuinely can't be found, the program terminates with an error instead of continuing silently:

```java
public static void main(String[] args) throws IOException
{
    File configFile = new File("auto_config.csv");
    Scanner scan = new Scanner(configFile);
    // ...
    scan.close();
}
```

## Reading Line by Line

```java
while (scan.hasNext())
{
    String line = scan.nextLine();
    // process this line
}
scan.close(); // always close when done
```

`hasNext()` is `true` as long as there's more to read — the standard loop condition for "read until the file ends."

## Splitting a CSV Line

A CSV (comma-separated values) file packs several fields into one line. `String`'s `split(",")` breaks a line into a `String[]` around the commas:

```java
// One line of auto_config.csv: "3-Piece-Left,14.2,BlueAlliance"
String line = scan.nextLine();
String[] fields = line.split(",");
String routeName = fields[0];       // "3-Piece-Left"
double routeTime = Double.parseDouble(fields[1]); // "14.2" -> 14.2
String alliance = fields[2];        // "BlueAlliance"
```

## Reading Into an Array or ArrayList

If you know the line count in advance, an array works; otherwise, `ArrayList` (Ch.9.2) avoids needing to know the size up front:

```java
ArrayList<String> configLines = new ArrayList<String>();
while (scan.hasNext())
{
    configLines.add(scan.nextLine());
}
```

## Reading Into Objects

Rather than working with raw `String[]` rows, define a class matching the file's columns and build one object per row — the same has-a/object-per-record idea from Ch.7:

```java
ArrayList<AutoRoute> routes = new ArrayList<AutoRoute>();
while (scan.hasNext())
{
    String[] fields = scan.nextLine().split(",");
    routes.add(new AutoRoute(fields[0], Double.parseDouble(fields[1]), fields[2]));
}
```

## Common Pitfalls

- **Forgetting `throws IOException` (or a try/catch).** Java won't compile file-reading code unless you've acknowledged that opening the file might fail.
- **Forgetting to `close()` the scanner.** A small leak that adds up in a program that opens many files.
- **Trying to parse a header row as data.** The first line of a CSV is often column names, not values — skip it (e.g. `if (i == 0) scan.nextLine();`) before parsing rows as real data.

## Key Takeaways

- `File` represents the file; `Scanner` reads from it — both can throw exceptions if the file can't be opened, which Java requires you to acknowledge (`throws IOException`, or try/catch).
- `hasNext()` combined with a `while` loop is the standard pattern for reading an entire file, line by line.
- `String.split(",")` breaks a CSV line into fields.
- Reading rows into custom objects (one object per line) is cleaner than working with raw split arrays once the data has real structure.
