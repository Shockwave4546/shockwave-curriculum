# super Keyword — Worked Example

## Problem

Every drivetrain on the team prints a basic status line, `Drivetrain: wheels ready`. A `TankDrive` is a kind of `Drivetrain`, and its status check should print that same basic line *and then* add one line of its own: `TankDrive: left and right sides linked`. Don't copy the basic line's code into `TankDrive` — reuse `Drivetrain`'s version.

## Step 1: Write the Superclass

```java
class Drivetrain
{
    public void printStatus()
    {
        System.out.println("Drivetrain: wheels ready");
    }
}
```

## Step 2: Override — and Call the Original with `super`

A plain override would *replace* `Drivetrain`'s `printStatus()` entirely. To keep the original behavior and add to it, the override calls `super.printStatus()` explicitly, then adds its own line:

```java
class TankDrive extends Drivetrain
{
    @Override
    public void printStatus()
    {
        super.printStatus(); // runs Drivetrain's version first
        System.out.println("TankDrive: left and right sides linked");
    }
}
```

`super.printStatus()` means "the `printStatus()` my superclass has" — it's a regular method call, so it can go anywhere in the body. Putting it first here is what makes the basic line print before the tank-specific one.

## Step 3: Put It Together in `main`

```java
public class StatusCheck
{
    public static void main(String[] args)
    {
        TankDrive drive = new TankDrive();
        drive.printStatus();
    }
}

class Drivetrain
{
    public void printStatus()
    {
        System.out.println("Drivetrain: wheels ready");
    }
}

class TankDrive extends Drivetrain
{
    @Override
    public void printStatus()
    {
        super.printStatus(); // runs Drivetrain's version first
        System.out.println("TankDrive: left and right sides linked");
    }
}
```

## What It Prints

```
Drivetrain: wheels ready
TankDrive: left and right sides linked
```

## Step 4: Trace the Method Lookup

1. `drive` was created with `new TankDrive()`, so the lookup for `printStatus()` starts in `TankDrive`. It finds `TankDrive`'s override there and runs it.
2. The first statement is `super.printStatus()`. That tells Java to skip `TankDrive` and use the version one level up, `Drivetrain.printStatus()`, which prints `Drivetrain: wheels ready`.
3. When `Drivetrain`'s version finishes, execution returns to the next line of `TankDrive.printStatus()`, which prints `TankDrive: left and right sides linked`.

## What Forgetting `super.printStatus()` Would Look Like

If the override were written without the `super` call:

```java
@Override
public void printStatus()
{
    System.out.println("TankDrive: left and right sides linked");
}
```

the program would print only:

```
TankDrive: left and right sides linked
```

Unlike `super(...)` in a constructor, which Java inserts for you if you leave it out, `super.printStatus()` is never called automatically. An override without it throws the superclass's version away completely.

## Recap

- `super.method()` calls the superclass's version of a method from inside an override, so a subclass can extend inherited behavior instead of replacing it.
- It's an ordinary method call — where you put it in the body decides when the superclass's version runs.
- Method lookup starts at the object's actual class; `super.method()` sends just that one call up to the superclass's version, then execution returns to the override.
- `super.method()` never happens automatically — leave it out and the override fully replaces the inherited method.
