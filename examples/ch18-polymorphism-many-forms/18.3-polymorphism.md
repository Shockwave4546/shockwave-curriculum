# Polymorphism — Worked Example

## Problem

The team has several autonomous routines. Every routine has a `run()` method; a plain `AutoRoutine` just sits still, while `LeaveZone` drives out of the starting zone and `ScoreOne` scores a preloaded game piece. Write **one** method, `startAuto`, that can start any routine it's handed — without checking which kind of routine it is.

## Step 1: The Superclass and Two Subclasses

```java
class AutoRoutine
{
    public void run()
    {
        System.out.println("Auto: sitting still");
    }
}

class LeaveZone extends AutoRoutine
{
    @Override
    public void run()
    {
        System.out.println("Auto: driving out of the starting zone");
    }
}

class ScoreOne extends AutoRoutine
{
    @Override
    public void run()
    {
        System.out.println("Auto: scoring the preloaded piece");
    }
}
```

Each subclass overrides `run()` (Lesson 18.1) with its own behavior.

## Step 2: One Method, Typed Against the Superclass

`startAuto`'s parameter is declared as `AutoRoutine`, so it accepts an `AutoRoutine` *or any subclass of it* (Lesson 17.3):

```java
public static void startAuto(AutoRoutine routine)
{
    System.out.println("Starting autonomous...");
    routine.run();
}
```

Inside `startAuto`, `routine`'s **declared** type is always `AutoRoutine`. The compiler checks that `AutoRoutine` has a `run()` method — it does — so the call compiles. Which `run()` actually executes is decided later, at runtime, by the **actual** object passed in.

## Step 3: Put It Together in `main`

```java
public class AutoSelector
{
    public static void startAuto(AutoRoutine routine)
    {
        System.out.println("Starting autonomous...");
        routine.run();
    }

    public static void main(String[] args)
    {
        AutoRoutine picked = new ScoreOne(); // declared AutoRoutine, actually a ScoreOne

        startAuto(new AutoRoutine());
        startAuto(new LeaveZone());
        startAuto(picked);
    }
}

class AutoRoutine
{
    public void run()
    {
        System.out.println("Auto: sitting still");
    }
}

class LeaveZone extends AutoRoutine
{
    @Override
    public void run()
    {
        System.out.println("Auto: driving out of the starting zone");
    }
}

class ScoreOne extends AutoRoutine
{
    @Override
    public void run()
    {
        System.out.println("Auto: scoring the preloaded piece");
    }
}
```

## What It Prints

```
Starting autonomous...
Auto: sitting still
Starting autonomous...
Auto: driving out of the starting zone
Starting autonomous...
Auto: scoring the preloaded piece
```

The same line of code, `routine.run()`, produced three different behaviors — one per actual object type. `picked` is declared `AutoRoutine`, but the object it refers to was built with `new ScoreOne()`, so `ScoreOne`'s override is what runs. There's no `if`/`else` anywhere checking which routine it is.

## Step 4: The Declared Type Still Decides What Compiles

Say `ScoreOne` also had a method of its own that `AutoRoutine` doesn't:

```java
public int getPieceCount()
{
    return 1;
}
```

Calling it through `picked` doesn't compile:

```java
AutoRoutine picked = new ScoreOne();
picked.getPieceCount(); // COMPILE ERROR — AutoRoutine has no getPieceCount()
```

```
error: cannot find symbol
        picked.getPieceCount();
              ^
  symbol:   method getPieceCount()
  location: variable picked of type AutoRoutine
```

The real object *is* a `ScoreOne` and genuinely has `getPieceCount()` — but the compiler only looks at the declared type, `AutoRoutine`, which never promised that method. Polymorphism works for `run()` because `AutoRoutine` declares `run()`; the subclasses only change *which version* runs.

## Recap

- A parameter (or variable) declared as a superclass type can hold any subclass object; one method like `startAuto` then works for every kind of routine.
- The compiler checks method calls against the **declared** type only — a subclass-only method can't be called through a superclass-typed variable.
- Once a call compiles, the **actual** object's type decides which override runs, at runtime.
- That's polymorphism: one line of code, `routine.run()`, many possible behaviors, with no type-checking `if`/`else` chain.
