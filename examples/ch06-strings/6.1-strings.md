# Strings — Worked Example

**Outline ref:** 6.1 — Strings (CSA 1.15)
**Pairs with:** [`lessons/ch06-strings/6.1-strings.md`](../../lessons/ch06-strings/6.1-strings.md)
**Status:** new — authored worked example (fully solved, walked step by step — not a problem to attempt)

## Problem

Your scouting app logs a station code like `"R2-1622"` — a station and a team number, joined by one dash. Pull the two pieces apart, print a readable summary, and confirm the extracted team number matches the one you expected.

## Step 1: Plan It First

1. Find the dash and split the code into two pieces: station and team number.
2. Build a readable summary string from the pieces.
3. Compare the extracted team number against an expected value with `.equals()`, not `==`.

## Step 2: Set Up the Class and `main`

```java
public class StationCode
{
    public static void main(String[] args)
    {
        String code = "R2-1622";
    }
}
```

`code` is created with a string literal — the normal way to make a `String`, no `new` needed.

## Step 3: Find the Dash with `indexOf`

```java
int dashIndex = code.indexOf("-"); // 2
```

## Step 4: Extract the Two Pieces with `substring`

```java
String station = code.substring(0, dashIndex);    // "R2"
String teamNumber = code.substring(dashIndex + 1); // "1622"
```

`substring(0, dashIndex)` takes everything up to (not including) the dash. `substring(dashIndex + 1)` with one argument takes everything after it, to the end.

## Step 5: Make Sure the Team Number Isn't Empty

`length()` catches a code that was missing its second half:

```java
if (teamNumber.length() == 0)
{
    System.out.println("Missing team number!");
}
```

## Step 6: Build the Summary with Concatenation

```java
String summary = "Station " + station + " has team " + teamNumber;
System.out.println(summary);
```

Output:

```
Station R2 has team 1622
```

## Step 7: Compare the Team Number with `.equals()`, Not `==`

```java
String expectedTeam = "1622";
System.out.println(teamNumber == expectedTeam);       // false — different objects, even though the text matches
System.out.println(teamNumber.equals(expectedTeam));  // true — same characters
```

`teamNumber` was built with `substring`, not a string literal, so it's a different object from the literal `expectedTeam` even though both hold `"1622"`. `==` compares object identity and gets it wrong here; `.equals()` compares the actual characters and correctly reports `true`.

## Step 8: The Immutability Pitfall

```java
summary.toUpperCase();                          // does nothing useful — the result is thrown away
String shoutedSummary = summary.toUpperCase();   // this is how you actually keep it
System.out.println(shoutedSummary);
```

Output:

```
STATION R2 HAS TEAM 1622
```

`summary` itself never changed — `shoutedSummary` is a brand-new `String` holding the uppercase version.

## Recap

- `String` is a class; `code` here was created with a string literal.
- `indexOf()` and `substring()` split the code into its two pieces; `length()` checked that the team number wasn't empty.
- `+` concatenated the extracted pieces and literal text into one readable summary.
- `.equals()` correctly compared the extracted team number to the expected value by content; `==` would have compared object identity instead.
- Strings are immutable — `toUpperCase()` had to be reassigned to a variable to keep its result.
