# Scope and Access — Worked Example

## Problem

Write a `BatteryMonitor` for the pit crew. It has a label (like `"Main battery"`) that's set once and never changes. It records voltage readings as they come in and reports the lowest reading so far. Along the way, identify the scope of every variable, and use `final` wherever something should never be reassigned.

## Step 1: Plan It First

1. Declare the fields (class scope): the label, and a list of readings.
2. Decide which fields should be `final`.
3. Write a constructor whose parameter has the same name as a field, and handle the shadowing.
4. Write `lowest()` using a method-scope variable and a block-scope variable, and check which can be used where.

## Step 2: The Fields, and Which Are `final`

```java
private final String label;
private final ArrayList<Double> readings = new ArrayList<Double>();
```

Both are instance variables, so both have **class scope**: every method in `BatteryMonitor` can use them. Both are `private`, which doesn't shrink that scope at all. It only stops code *outside* the class from reaching them.

Both are also `final`, for two different reasons:

- `label` should never change once the monitor is built, so it can be assigned exactly once.
- `readings` should always be the same list. Nobody should be able to swap in a different list object. `final` locks that *reference*, but the list itself can still have readings added to it, as Step 4 shows.

## Step 3: The Constructor and Shadowing

```java
public BatteryMonitor(String label)
{
    this.label = label;
}
```

The parameter `label` has **method scope**. It exists only while this constructor runs. It also shares its name with the field `label`, so inside the constructor the parameter *shadows* the field. A bare `label` means the parameter. `this.label` reaches the field instead (the fix from Ch.8). This is also the one and only assignment the `final` field `label` ever gets.

## Step 4: Recording a Reading

```java
public void record(double volts)
{
    readings.add(volts);
}
```

`readings` is `final`, and this still compiles. `add` changes what's *inside* the list, not which list `readings` refers to. `volts` is another method-scope parameter: it exists for one call to `record` and is gone afterward.

## Step 5: The Lowest Reading, and Block Scope

```java
public double lowest()
{
    double lowestSoFar = readings.get(0);
    for (int i = 1; i < readings.size(); i++)
    {
        double sample = readings.get(i);
        if (sample < lowestSoFar)
        {
            lowestSoFar = sample;
        }
    }
    return lowestSoFar;
}
```

There are three scopes at work here:

- `lowestSoFar` is declared at the top of the method, so it has **method scope**. It lives until the method returns, which is why `return lowestSoFar;` after the loop can still use it.
- `i` and `sample` are declared by and inside the `for` loop, so they have **block scope**. They stop existing the moment the loop's closing brace is reached.
- `readings` is a field, so it has **class scope**, and it's reachable here too.

## Step 6: The Whole Program

```java
import java.util.ArrayList;

class BatteryMonitor
{
    private final String label;
    private final ArrayList<Double> readings = new ArrayList<Double>();

    public BatteryMonitor(String label)
    {
        this.label = label;
    }

    public void record(double volts)
    {
        readings.add(volts);
    }

    public double lowest()
    {
        double lowestSoFar = readings.get(0);
        for (int i = 1; i < readings.size(); i++)
        {
            double sample = readings.get(i);
            if (sample < lowestSoFar)
            {
                lowestSoFar = sample;
            }
        }
        return lowestSoFar;
    }

    public String getLabel()
    {
        return label;
    }
}

public class BatteryCheck
{
    public static void main(String[] args)
    {
        BatteryMonitor monitor = new BatteryMonitor("Main battery");
        monitor.record(12.6);
        monitor.record(11.9);
        monitor.record(12.2);

        System.out.println(monitor.getLabel() + " lowest reading: " + monitor.lowest() + " V");
    }
}
```

## What It Prints

```
Main battery lowest reading: 11.9 V
```

`lowestSoFar` starts at the first reading, `12.6`. The loop then drops it to `11.9`. `12.2` isn't lower than that, so `11.9` is what gets returned.

## What Breaking Each Rule Would Look Like

Each of these edits fails to compile, and each failure matches one rule from the lesson:

- **Using a block-scope variable after its block.** Adding `System.out.println(sample);` just before `return lowestSoFar;` gives `cannot find symbol ... variable sample`. `sample` stopped existing when the loop's `}` closed.
- **Reassigning a `final` reference.** Replacing `record`'s body with `readings = new ArrayList<Double>();` gives `cannot assign a value to final variable readings`. Adding to the list was fine, but pointing `readings` at a different list isn't.
- **Reassigning a `final` field after construction.** Replacing `record`'s body with `label = "Spare battery";` gives `cannot assign a value to final variable label`. The constructor already used up its one assignment.

## Recap

- Fields have class scope: every method in the class can use them, whether they're `public` or `private`.
- Parameters and variables declared at the top of a method have method scope. They last for one call.
- Variables declared inside a loop or other block have block scope. They're gone once the block's `}` is reached, so anything needed afterward must be declared outside the block.
- A parameter with the same name as a field shadows it. `this.fieldName` reaches the field.
- `final` allows exactly one assignment. On an object reference like `readings`, it locks which object is referred to, not what's inside that object.
