# Calling Class Methods — Worked Example

## Problem

Write a `void` class method that prints a formatted header for a subsystem, and a non-void class method that converts a number of full wheel rotations into encoder ticks (2048 ticks per rotation). Call both from `main`, then see what happens when the non-void method's return value is ignored.

## Step 1: Plan It First

1. Write a `void` method that prints a header — it has an effect (printing), nothing to return.
2. Write a non-void method that computes ticks from rotations and returns that value.
3. Call the `void` method for its effect.
4. Call the non-void method and actually use what it returns.
5. Call the non-void method again, but throw the result away, and see that Java lets this compile anyway.

## Step 2: Write the Void Method

A `void` method doesn't return anything — you call it purely for its effect:

```java
public static void printSubsystemHeader(String subsystemName)
{
    System.out.println("=== " + subsystemName + " ===");
}
```

## Step 3: Call It

```java
public class DrivetrainSetup
{
    public static void main(String[] args)
    {
        printSubsystemHeader("Drivetrain");
    }

    public static void printSubsystemHeader(String subsystemName)
    {
        System.out.println("=== " + subsystemName + " ===");
    }
}
```

`printSubsystemHeader` is a **class method** (also called a **static method**) — it belongs to the `DrivetrainSetup` class itself, not to any object. Because `main` is defined in the same class, it's called bare, with no class name in front.

## Step 4: Write the Non-Void Method

A non-void method computes and returns a value, which the caller must actually use:

```java
public static int rotationsToTicks(double rotations)
{
    int ticks = (int)(rotations * 2048);
    return ticks;
}
```

`2048` is the encoder's ticks-per-rotation count. `rotations * 2048` is a `double`, so the `(int)` cast (Ch.2.4) truncates it down to a whole number of ticks before `return` sends it back to whoever called the method — and ends the method immediately.

## Step 5: Call It and Use the Result

```java
public class DrivetrainSetup
{
    public static void main(String[] args)
    {
        printSubsystemHeader("Drivetrain");

        int ticks = rotationsToTicks(3.0);
        System.out.println("3.0 rotations = " + ticks + " ticks");
    }

    public static void printSubsystemHeader(String subsystemName)
    {
        System.out.println("=== " + subsystemName + " ===");
    }

    public static int rotationsToTicks(double rotations)
    {
        int ticks = (int)(rotations * 2048);
        return ticks;
    }
}
```

This prints:

```
=== Drivetrain ===
3.0 rotations = 6144 ticks
```

`ticks` stores the returned value, which is then used in the `println` call — exactly what a non-void method's result has to do: get stored or used, not just dropped.

## Step 6: See What Happens When the Return Value Is Ignored

```java
rotationsToTicks(1.5); // compiles, but the returned value is silently thrown away
```

This line calls the method, computes `3072`, and then discards it — nothing stores it, nothing prints it. Java doesn't force a non-void method's result to be used, which is exactly why forgetting to do something with it is such an easy mistake to miss; the compiler won't flag it.

## Recap

- A `static` method is a class method, called via the class name (or bare, from inside the same class) — `printSubsystemHeader` and `rotationsToTicks` were both called bare from `main`.
- A `void` method (`printSubsystemHeader`) returns nothing; a non-void method (`rotationsToTicks`) computes a value that must be stored or used.
- `return` sends a value back to the caller and ends the method immediately — nothing after it runs.
- Calling `rotationsToTicks(1.5);` alone compiled fine even though its result went unused — a non-void method's return value being ignored is a real, easy-to-miss bug.
