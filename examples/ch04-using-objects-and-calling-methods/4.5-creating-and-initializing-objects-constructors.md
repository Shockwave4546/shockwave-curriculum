# Creating & Initializing Objects: Constructors — Worked Example

## Problem

Set up the robot's starting `Pose2d` for autonomous using both of `Pose2d`'s constructors — the default one and the explicit one — and declare a `climberMotor` reference (the team's own `DriveMotor` class, from Lesson 4.4 — assume it exists in the same package) that starts out `null` because the climber subsystem isn't turned on until later in the match, constructing it only once it is.

## Step 1: Plan It First

1. Build a starting pose using `Pose2d`'s no-argument constructor.
2. Build a second pose using `Pose2d`'s explicit constructor, being careful about argument order.
3. Declare `climberMotor` as `null` — no object yet.
4. Later, once the climber is enabled, construct it with `new`.

## Step 2: Build a Pose with the No-Argument Constructor

A **constructor** initializes a new object's attributes when it's created. `new` followed by the class name is a call to the constructor:

```java
Pose2d defaultStart = new Pose2d();
```

`Pose2d()` with no arguments is one constructor this class offers — it defaults to `(0, 0, facing 0°)`.

## Step 3: Build a Pose with the Explicit Constructor

A class can offer more than one constructor — the same **overloading** concept from methods (Lesson 4.1), applied to constructors:

```java
Pose2d matchStart = new Pose2d(2.5, 1.0, new Rotation2d());
```

This constructor takes `x`, `y` (both in meters), and a heading, in that exact order. Argument order matters — swapping which number means `x` and which means `y` produces a real, silent bug: the code still compiles, but the object ends up with the wrong position.

## Step 4: Declare a Reference That Isn't Built Yet

The climber subsystem doesn't get enabled until partway through the match, so its motor reference can be declared now without being constructed yet:

```java
DriveMotor climberMotor = null;
```

`null` means "doesn't refer to anything." `climberMotor` exists as a variable, but there's no `DriveMotor` object behind it yet.

## Step 5: Construct It Once the Climber Is Enabled

```java
import org.wpilib.math.geometry.Pose2d;
import org.wpilib.math.geometry.Rotation2d;

public class AutonomousSetup
{
    public static void main(String[] args)
    {
        Pose2d defaultStart = new Pose2d();
        Pose2d matchStart = new Pose2d(2.5, 1.0, new Rotation2d());

        DriveMotor climberMotor = null;

        // ... later, once the climber subsystem is enabled for the match ...
        climberMotor = new DriveMotor(9);
    }
}
```

The two `import` lines bring in WPILib's `Pose2d` and `Rotation2d` from `org.wpilib.math.geometry` (Lesson 3.3); `DriveMotor` is in the program's own package, so it needs none. `climberMotor` now refers to a real `DriveMotor` object on PWM channel `9`. Notice the type name `DriveMotor` wasn't written again on the left side — `climberMotor` already exists as a variable; this line just points it at a newly constructed object.

## Step 6: What Would Happen Without That Assignment

If code tried to use `climberMotor` before it was ever assigned a real object —

```java
climberMotor.setThrottle(0.5); // climberMotor is still null here
```

— this would throw a `NullPointerException` at runtime. It would compile fine, because the compiler only checks that `climberMotor` is declared as a `DriveMotor` and was given a value (`null` counts); it has no way to know it's still `null` until the program actually runs and tries to use it. (Lesson 4.6 covers calling methods like `setThrottle` in detail.)

## Recap

- `new ClassName(arguments)` calls a constructor to build and initialize an object — used here for both `Pose2d` and `DriveMotor`.
- A class can have multiple overloaded constructors, differing in their parameter lists — `Pose2d()` and `Pose2d(double, double, Rotation2d)` are two examples.
- A reference variable can be `null` — pointing at no object at all — until it's assigned a real one with `new`, as `climberMotor` was.
- Calling a method on a `null` reference throws a `NullPointerException`.
- Constructor argument order must match the constructor's signature exactly — `Pose2d(2.5, 1.0, new Rotation2d())` means `x`, then `y`, then heading, in that order.
