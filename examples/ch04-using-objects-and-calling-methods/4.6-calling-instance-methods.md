# Calling Instance Methods — Worked Example

## Problem

Construct a motor object (the team's own `DriveMotor` class from Lesson 4.4 — assume it exists in the same package), call an instance method on it to command a throttle, and call a getter to read that throttle back. Then compare that against a second motor reference that was set to `null` and never constructed, to see the `NullPointerException` it throws.

## Step 1: Plan It First

1. Construct a motor object.
2. Call an instance method on it to set its throttle.
3. Call a getter on it to read the throttle back, and use the returned value.
4. Declare a second motor reference as `null`, but never construct it.
5. See what calling a method on that second, unconstructed reference would do.

## Step 2: Construct the Motor

```java
DriveMotor frontLeftMotor = new DriveMotor(1);
```

## Step 3: Call an Instance Method to Set Its Throttle

An **instance method** is called on a specific object, and it reads or changes *that object's* attributes:

```java
frontLeftMotor.setThrottle(0.5);
```

Unlike `Math.sqrt(9)`, which doesn't care which object called it (there is no object), `frontLeftMotor.setThrottle(0.5)` only makes sense applied to this one specific motor. `0.5` here is the argument, saved into `setThrottle`'s own parameter — the same argument/parameter relationship from Lesson 4.1, just called on an object this time instead of bare.

## Step 4: Call a Getter to Read the Throttle Back

A method that just reports one of an object's attributes — no side effects, just returns a value — is a **getter** (formally, an accessor). By convention its name starts with `get`, and its return value should actually be used. `getThrottle()` reports the last throttle this motor was told to run at:

```java
double currentThrottle = frontLeftMotor.getThrottle();
System.out.println("Current throttle: " + currentThrottle);
```

Put together so far:

```java
public class DriveCheck
{
    public static void main(String[] args)
    {
        DriveMotor frontLeftMotor = new DriveMotor(1);

        frontLeftMotor.setThrottle(0.5);

        double currentThrottle = frontLeftMotor.getThrottle();
        System.out.println("Current throttle: " + currentThrottle);
    }
}
```

This prints:

```
Current throttle: 0.5
```

## Step 5: Declare a Second Motor That's Never Constructed

```java
DriveMotor backupMotor = null;
```

Declared and explicitly set to `null`, but never assigned a `new DriveMotor(...)` — exactly like `climberMotor` before its assignment in Lesson 4.5's worked example.

(Leaving off the `= null` — writing just `DriveMotor backupMotor;` — would be a different problem: Java refuses to compile any code that reads a local variable before it's been given a value, with the error "variable backupMotor might not have been initialized." Writing `= null` gives it a value, so the code compiles — and the problem moves to runtime.)

## Step 6: What Calling a Method on It Would Do

```java
backupMotor.setThrottle(0.5); // backupMotor still holds null
```

This line compiles without complaint — the compiler only checks that `backupMotor` is declared as a `DriveMotor` and has been given a value. But at runtime, calling `setThrottle` on it throws a `NullPointerException`, because `backupMotor` doesn't refer to a real object. This is one of the most common real bugs in object-oriented code: a reference that looks fine at compile time but was never actually built with `new`.

## Recap

- An instance method is called on a specific object and can read/change that object's own attributes — `frontLeftMotor.setThrottle(0.5)` and `frontLeftMotor.getThrottle()` both acted on `frontLeftMotor` specifically.
- Calling a method on a `null` reference throws a `NullPointerException` — `backupMotor.setThrottle(0.5)` would have crashed because `backupMotor` held `null` and was never constructed.
- A getter (accessor) reports one of an object's attributes; its return value should be used, not ignored — `currentThrottle` stored what `getThrottle()` returned before it was printed.
