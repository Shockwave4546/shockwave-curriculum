# Calling Instance Methods — Worked Example

## Problem

Construct a motor object, call an instance method on it to command a speed, and call a getter to read back its current velocity. Then compare that against a second motor reference that was never constructed, to see the `NullPointerException` it throws.

## Step 1: Plan It First

1. Construct a motor object.
2. Call an instance method on it to set its speed.
3. Call a getter on it to read its velocity, and use the returned value.
4. Declare a second motor reference, but never construct it.
5. See what calling a method on that second, unconstructed reference would do.

## Step 2: Construct the Motor

```java
TalonFX frontLeftMotor = new TalonFX(1);
```

## Step 3: Call an Instance Method to Set Its Speed

An **instance method** is called on a specific object, and it reads or changes *that object's* attributes:

```java
frontLeftMotor.set(0.5);
```

Unlike `Math.sqrt(9)`, which doesn't care which object called it (there is no object), `frontLeftMotor.set(0.5)` only makes sense applied to this one specific motor. `0.5` here is the argument, saved into `set`'s own parameter — the same argument/parameter relationship from Lesson 4.1, just called on an object this time instead of bare.

## Step 4: Call a Getter to Read Its Velocity

A method that just reports one of an object's attributes — no side effects, just returns a value — is a **getter** (formally, an accessor). By convention its name starts with `get`, and its return value must actually be used:

```java
double currentVelocity = frontLeftMotor.getVelocity();
System.out.println("Current velocity: " + currentVelocity);
```

Put together so far:

```java
public class DriveCheck
{
    public static void main(String[] args)
    {
        TalonFX frontLeftMotor = new TalonFX(1);

        frontLeftMotor.set(0.5);

        double currentVelocity = frontLeftMotor.getVelocity();
        System.out.println("Current velocity: " + currentVelocity);
    }
}
```

## Step 5: Declare a Second Motor That's Never Constructed

```java
TalonFX backupMotor;
```

Declared, but never assigned a `new TalonFX(...)` — so it's still `null` behind the scenes, exactly like `climberMotor` before its assignment in Lesson 4.5.

## Step 6: What Calling a Method on It Would Do

```java
backupMotor.set(0.5); // backupMotor was never constructed
```

This line compiles without complaint — the compiler only checks that `backupMotor` is declared as a `TalonFX`. But at runtime, calling `set` on it throws a `NullPointerException`, because `backupMotor` doesn't refer to a real object yet. This is one of the most common real bugs in object-oriented code: a reference that looks fine at compile time but was never actually built with `new`.

## Recap

- An instance method is called on a specific object and can read/change that object's own attributes — `frontLeftMotor.set(0.5)` and `frontLeftMotor.getVelocity()` both acted on `frontLeftMotor` specifically.
- Calling a method on a `null` reference throws a `NullPointerException` — `backupMotor.set(0.5)` would have crashed because `backupMotor` was never constructed.
- A getter (accessor) reports one of an object's attributes; its return value must be used, not ignored — `currentVelocity` stored what `getVelocity()` returned before it was printed.
