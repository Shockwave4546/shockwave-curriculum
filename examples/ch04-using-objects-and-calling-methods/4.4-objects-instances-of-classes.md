# Objects — Instances of Classes — Worked Example

## Problem

Model the four drive motors of a swerve drivetrain as objects of the team's own `DriveMotor` class (from Lesson 4.4 — assume it already exists in the same package as this program, so it needs no import): declare a reference variable for each motor, construct each one, and confirm that all four are independent objects even though they're all built from the same class.

## Step 1: Plan It First

1. Declare four reference variables, one per motor, all of type `DriveMotor`.
2. Construct each one with `new`, giving each its own PWM channel.
3. Confirm that each object keeps its own identity separately from the others.

## Step 2: Declare the Class as a Type

`DriveMotor` is a class — a blueprint. Just like `int` or `double`, it also defines a *type*, so declaring a variable of type `DriveMotor` works exactly like declaring one of any other type:

```java
DriveMotor frontLeftMotor;
DriveMotor frontRightMotor;
DriveMotor backLeftMotor;
DriveMotor backRightMotor;
```

Four reference variables declared, but none of them assigned anything yet — not even `null`. Java won't let you read a variable in this state at all (it's a compile error), so each one needs a real object before it's used.

## Step 3: Construct Each Object

```java
public class SwerveSetup
{
    public static void main(String[] args)
    {
        DriveMotor frontLeftMotor = new DriveMotor(1);
        DriveMotor frontRightMotor = new DriveMotor(2);
        DriveMotor backLeftMotor = new DriveMotor(3);
        DriveMotor backRightMotor = new DriveMotor(4);
    }
}
```

Four separate objects, all built from the one `DriveMotor` class, each given a different PWM channel (`1` through `4`) as its constructor argument.

## Step 4: What Each Reference Variable Actually Holds

`frontLeftMotor` doesn't hold the motor object itself — it holds a **reference** to it, like a tracking number pointing at where the real object lives in memory. This is different from a primitive variable (`int`, `double`), which holds its value directly with nothing in between. All four of these variables hold references to four separate, real `DriveMotor` objects.

## Step 5: Confirm the Objects Are Independent

`DriveMotor` defines what attributes and behaviors *exist* for any motor built from it — things like a PWM channel and a current throttle, and methods to read or change them. But each object gets its *own* values for those attributes. `frontLeftMotor` was built with PWM channel `1`, and `frontRightMotor` with PWM channel `2` — two objects from the same class, holding entirely separate state. (Lesson 4.6 covers actually calling methods on these objects to read or change that state — for now, it's enough to know each one keeps its own.)

## Recap

- A class is a blueprint; an object is one specific instance built from it — `frontLeftMotor`, `frontRightMotor`, `backLeftMotor`, and `backRightMotor` are four instances of `DriveMotor`.
- A class defines a new type, just like `int` or `double` — `DriveMotor frontLeftMotor;` declares a variable of that type.
- Attributes are an object's data (like a PWM channel); behaviors are what it can do, defined as methods.
- A reference variable holds a pointer to an object, not the object's data directly.
- Many objects can be created from the same class, each with its own independent attribute values — one `DriveMotor` class, four separate motors.
