# Objects — Instances of Classes — Worked Example

## Problem

Model the four drive motors of a swerve drivetrain as objects of the given `TalonFX` class: declare a reference variable for each motor, construct each one, and confirm that all four are independent objects even though they're all built from the same class.

## Step 1: Plan It First

1. Declare four reference variables, one per motor, all of type `TalonFX`.
2. Construct each one with `new`, giving each its own CAN ID.
3. Confirm that each object keeps its own identity separately from the others.

## Step 2: Declare the Class as a Type

`TalonFX` is a class — a blueprint. Just like `int` or `double`, it also defines a *type*, so declaring a variable of type `TalonFX` works exactly like declaring one of any other type:

```java
TalonFX frontLeftMotor;
TalonFX frontRightMotor;
TalonFX backLeftMotor;
TalonFX backRightMotor;
```

Four reference variables, none of them pointing at an object yet.

## Step 3: Construct Each Object

```java
public class SwerveSetup
{
    public static void main(String[] args)
    {
        TalonFX frontLeftMotor = new TalonFX(1);
        TalonFX frontRightMotor = new TalonFX(2);
        TalonFX backLeftMotor = new TalonFX(3);
        TalonFX backRightMotor = new TalonFX(4);
    }
}
```

Four separate objects, all built from the one `TalonFX` class, each given a different CAN ID (`1` through `4`) as its constructor argument.

## Step 4: What Each Reference Variable Actually Holds

`frontLeftMotor` doesn't hold the motor object itself — it holds a **reference** to it, like a tracking number pointing at where the real object lives in memory. This is different from a primitive variable (`int`, `double`), which holds its value directly with nothing in between. All four of these variables hold references to four separate, real `TalonFX` objects.

## Step 5: Confirm the Objects Are Independent

`TalonFX` defines what attributes and behaviors *exist* for any motor built from it — things like a CAN ID and a current speed, and methods to read or change them. But each object gets its *own* values for those attributes. `frontLeftMotor` was built with CAN ID `1`, and `frontRightMotor` with CAN ID `2` — two objects from the same class, holding entirely separate state. (Chapter 4.6 covers actually calling methods on these objects to read or change that state — for now, it's enough to know each one keeps its own.)

## Recap

- A class is a blueprint; an object is one specific instance built from it — `frontLeftMotor`, `frontRightMotor`, `backLeftMotor`, and `backRightMotor` are four instances of `TalonFX`.
- A class defines a new type, just like `int` or `double` — `TalonFX frontLeftMotor;` declares a variable of that type.
- Attributes are an object's data (like a CAN ID); behaviors are what it can do, defined as methods.
- A reference variable holds a pointer to an object, not the object's data directly.
- Many objects can be created from the same class, each with its own independent attribute values — one `TalonFX` class, four separate motors.
