# Methods, Signatures & Parameters — Worked Example

## Problem

Write a static method that announces a requested drivetrain speed, then add a second, overloaded version that also announces which side of the drivetrain it's for. Along the way, confirm that changing a parameter inside a method never changes the value the caller passed in.

## Step 1: Plan It First

In plain English:

1. Write a method that takes a requested speed and prints a message about it.
2. Call that method from `main` with a real speed value.
3. Prove the method only got a *copy* of that value.
4. Write a second version of the same method name that also takes which side it's for.
5. Call both versions and let Java pick the right one.

## Step 2: Write the Method's Signature

A method's **signature** is its name plus its parameter types. Here's the header for the first version, with no body yet:

```java
public static void announceSpeed(double requestedSpeed)
{

}
```

`requestedSpeed` is a **parameter** — a variable declared in the method's own header, usable inside the method's body. The signature here is `announceSpeed(double)`.

## Step 3: Fill In the Body and Call It

```java
public class DriveAnnouncer
{
    public static void main(String[] args)
    {
        double commandedSpeed = 0.75;
        announceSpeed(commandedSpeed);
    }

    public static void announceSpeed(double requestedSpeed)
    {
        System.out.println("Setting drivetrain speed to " + requestedSpeed);
    }
}
```

`commandedSpeed` is the caller's variable; `0.75` is the value stored in it. When `announceSpeed(commandedSpeed)` runs, `0.75` is the **argument** — the real value being passed in. Parameter and argument name the same slot from two different sides: `requestedSpeed` is the variable *inside* the method, `commandedSpeed` (holding `0.75`) is the value *at the call site*.

## Step 4: Confirm Call by Value

Java copies the argument's value into the parameter — **call by value**. To see this, have the method reassign its own parameter, then check `commandedSpeed` back in `main` afterward:

```java
public class DriveAnnouncer
{
    public static void main(String[] args)
    {
        double commandedSpeed = 0.75;
        announceSpeed(commandedSpeed);
        System.out.println("Back in main, commandedSpeed is still: " + commandedSpeed);
    }

    public static void announceSpeed(double requestedSpeed)
    {
        System.out.println("Setting drivetrain speed to " + requestedSpeed);
        requestedSpeed = 0.0;
        System.out.println("Inside the method, requestedSpeed is now: " + requestedSpeed);
    }
}
```

This prints:

```
Setting drivetrain speed to 0.75
Inside the method, requestedSpeed is now: 0.0
Back in main, commandedSpeed is still: 0.75
```

Only a copy went into `requestedSpeed`. Reassigning it inside the method never touches `commandedSpeed` back in `main`.

## Step 5: Add an Overload

Two methods can share the same name if their parameter lists differ in number or type — this is **overloading**. Add a second `announceSpeed` that also takes which side of the drivetrain it's for:

```java
public static void announceSpeed(String side, double requestedSpeed)
{
    System.out.println("Setting " + side + " side speed to " + requestedSpeed);
}
```

This is a different signature — `announceSpeed(String, double)` — even though the name is identical.

## Step 6: Call Both Overloads

```java
public class DriveAnnouncer
{
    public static void main(String[] args)
    {
        double commandedSpeed = 0.75;
        announceSpeed(commandedSpeed);
        System.out.println("Back in main, commandedSpeed is still: " + commandedSpeed);

        announceSpeed("left", 0.5);
        announceSpeed("right", 0.6);
    }

    public static void announceSpeed(double requestedSpeed)
    {
        System.out.println("Setting drivetrain speed to " + requestedSpeed);
        requestedSpeed = 0.0;
        System.out.println("Inside the method, requestedSpeed is now: " + requestedSpeed);
    }

    public static void announceSpeed(String side, double requestedSpeed)
    {
        System.out.println("Setting " + side + " side speed to " + requestedSpeed);
    }
}
```

Java looks at the arguments at each call site — a lone `double` versus a `String` followed by a `double` — and picks the matching signature automatically. Calling `announceSpeed("left", 0.5)` with the arguments in the wrong order, like `announceSpeed(0.5, "left")`, wouldn't compile: no signature matches a `double` followed by a `String`.

## Recap

- A method's signature is its name plus its parameter types — `announceSpeed(double)` and `announceSpeed(String, double)` are two different signatures sharing one name.
- A parameter (`requestedSpeed`) is a variable in the method's own header; an argument (`commandedSpeed`, or the literal `0.75`) is the actual value passed in at the call site.
- Java uses call by value — `announceSpeed` only ever received a copy of `commandedSpeed`; reassigning its parameter never changed the caller's variable.
- Overloading means multiple methods share a name but differ in their parameter lists; Java picks the matching one based on the call's arguments.
