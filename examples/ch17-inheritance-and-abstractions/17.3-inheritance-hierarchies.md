# Inheritance Hierarchies — Worked Example

## Problem

Before a match, the robot collects any problems it finds into a list of alerts: a low battery, a CAN device that isn't responding, or a general message like a disconnected camera. Each kind builds its message differently, but all of them are displayed the same way. Write one method that shows every alert, whatever kind it is.

## Step 1: Write the Superclass

```java
class Alert
{
    private String message;

    public Alert(String message)
    {
        this.message = message;
    }

    public void show()
    {
        System.out.println("[ALERT] " + message);
    }
}
```

This is the one place the display format lives. A general alert, like a disconnected camera, can be a plain `Alert` object.

## Step 2: Write Two Subclasses

Each subclass takes the value it cares about and builds its message from it. The message is passed up with `super(...)` (Lesson 17.2):

```java
class BatteryAlert extends Alert
{
    public BatteryAlert(double volts)
    {
        super("Battery low: " + volts + "V");
    }
}

class CanAlert extends Alert
{
    public CanAlert(int deviceId)
    {
        super("CAN device " + deviceId + " not responding");
    }
}
```

`Alert`, `BatteryAlert`, and `CanAlert` now form a small hierarchy: two subclasses sharing one superclass, and `Object` above all of them.

## Step 3: Hold a Subclass Object in a Superclass Variable

Because a `BatteryAlert` *is an* `Alert`, an `Alert`-typed variable can hold one:

```java
Alert first = new BatteryAlert(11.4);   // legal — a BatteryAlert IS-AN Alert
```

The reverse doesn't compile, since not every `Alert` is a battery alert:

```java
BatteryAlert b = new Alert("Camera disconnected"); // error: incompatible types
```

## Step 4: One Method for the Whole Hierarchy

Type the method's parameter against the superclass, and it accepts an array holding any mix of `Alert` and its subclasses:

```java
public static void showAll(Alert[] alerts)
{
    for (Alert a : alerts)
    {
        a.show();
    }
}
```

Inside the loop, `a` is typed `Alert`, so all the loop knows is that every element has a `show()` method — which every element does, because `BatteryAlert` and `CanAlert` both inherit it.

## Step 5: Put It Together

```java
public class AlertDemo
{
    public static void showAll(Alert[] alerts)
    {
        for (Alert a : alerts)
        {
            a.show();
        }
    }

    public static void main(String[] args)
    {
        Alert[] activeAlerts = { new BatteryAlert(11.4), new CanAlert(12), new Alert("Camera disconnected") };
        showAll(activeAlerts);
    }
}

class Alert
{
    private String message;

    public Alert(String message)
    {
        this.message = message;
    }

    public void show()
    {
        System.out.println("[ALERT] " + message);
    }
}

class BatteryAlert extends Alert
{
    public BatteryAlert(double volts)
    {
        super("Battery low: " + volts + "V");
    }
}

class CanAlert extends Alert
{
    public CanAlert(int deviceId)
    {
        super("CAN device " + deviceId + " not responding");
    }
}
```

`activeAlerts` is one `Alert[]` array holding three different classes side by side, and `showAll` never needs to know which is which.

## What It Prints

```
[ALERT] Battery low: 11.4V
[ALERT] CAN device 12 not responding
[ALERT] Camera disconnected
```

Adding a new kind of alert later (say, a `BrownoutAlert`) wouldn't require touching `showAll` at all — as long as the new class extends `Alert`, the existing method already accepts it.

## The Same Idea with an ArrayList

An `ArrayList<Alert>` works the same way, if the alerts are collected one at a time while the robot checks itself (with `import java.util.ArrayList;` at the top of the file, as in Ch.9):

```java
ArrayList<Alert> alertList = new ArrayList<Alert>();
alertList.add(new BatteryAlert(11.4));
alertList.add(new CanAlert(12));
```

Both `add` calls are legal for the same reason as the array: each object is an `Alert`.

## Recap

- Two or more subclasses of one superclass form an inheritance hierarchy, with `Object` at the top.
- A superclass-typed variable, array, or `ArrayList` can hold objects of any subclass — `Alert first = new BatteryAlert(11.4);` — but never the reverse.
- A method whose parameter is typed against the superclass (`showAll(Alert[] alerts)`) works for every class in the hierarchy, including ones written later.
