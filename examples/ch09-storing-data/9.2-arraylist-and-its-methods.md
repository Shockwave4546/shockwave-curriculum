# ArrayList and its Methods — Worked Example

## Problem

During a match, keep a running list of notable events ("Note Scored", "Climbed") as they happen — you don't know ahead of time how many there will be. After the match, insert a boot-time entry at the very start, fix a misspelled entry, and delete one that turned out to be a false alarm.

## Step 1: Plan It First

1. Create a list that can grow as events happen.
2. Add events to the end, in order, as they occur.
3. Insert a "Match Started" entry at the very front, after the fact.
4. Fix a misspelled entry in place.
5. Remove a false-alarm entry.
6. Print how many entries remain.

## Step 2: Create the List

An array can't do this — its size is fixed forever once created. `ArrayList` is Java's resizable alternative, for exactly this situation: you don't know the final size up front.

```java
import java.util.ArrayList;

ArrayList<String> matchLog = new ArrayList<String>();
```

`ArrayList<String>` — the type in angle brackets says this list holds `String` objects.

## Step 3: Add Events as They Happen

```java
matchLog.add("Note Scored");
matchLog.add("Note Scoared"); // typo, will fix in a later step
matchLog.add("Climbed");
```

`add(...)` with no index always appends to the end.

## Step 4: Insert at the Front

`add(index, obj)` inserts at a specific position, shifting everything else right:

```java
matchLog.add(0, "Match Started");
// matchLog is now: "Match Started", "Note Scored", "Note Scoared", "Climbed"
```

## Step 5: Fix the Misspelled Entry

`get(index)` reads an element; `set(index, obj)` replaces it:

```java
System.out.println(matchLog.get(2)); // "Note Scoared" — confirms which index has the typo
matchLog.set(2, "Note Scored");      // corrected in place
```

## Step 6: Remove the False Alarm

Say "Climbed" was reported by mistake — `remove(index)` deletes it, shifting later elements left:

```java
matchLog.remove(3);
// matchLog is now: "Match Started", "Note Scored", "Note Scored"
```

## Step 7: Check How Many Entries Remain

```java
System.out.println(matchLog.size()); // 3 — a method call, unlike an array's .length field
```

## Bonus: Logging a Number Instead of Text

If you wanted to log the elapsed match time (a number) for each event instead of a description, `ArrayList` can only hold objects — not primitives directly — so a list of numbers uses the wrapper type `Double`, and Java converts back and forth automatically (autoboxing):

```java
ArrayList<Double> eventTimes = new ArrayList<Double>();
eventTimes.add(12.4); // the double 12.4 is autoboxed into a Double
```

## Recap

- `ArrayList` is a resizable list — use it when the size isn't known up front or will change at runtime, unlike an array.
- The type parameter (`ArrayList<Type>`) says what it holds; primitives need their wrapper type (`Integer`, `Double`), converted automatically via autoboxing.
- Core methods: `size()`, `add()`, `add(index, obj)`, `get(index)`, `set(index, obj)`, `remove(index)`.
- Arrays use `.length` and `[]`; `ArrayList` uses `.size()` and `get`/`set`.
