# 2D Array Traversals: Nested Loops — Worked Example

## Problem

The robot has a small status LED panel, 2 rows by 3 columns, and each LED's brightness is stored as a number from 0 (off) to 255 (full). Print the panel one row at a time, then one column at a time, then print it again without using any indices. Finally, turn every LED off (set it to 0), and make sure the array really changes.

## Step 1: Plan It First

1. Row by row: outer loop over rows, inner loop over columns (row-major).
2. Column by column: outer loop over columns, inner loop over rows (column-major).
3. No indices needed: nested for-each.
4. Turning LEDs off changes stored values, so for-each won't work. An indexed nested loop is needed.

```java
int[][] ledBrightness = { {255, 0, 128}, {64, 255, 0} };
```

## Step 2: Row by Row — Row-Major

The outer loop picks a row, and the inner loop walks every column in that row before the outer loop moves on. `System.out.print` keeps a row's values on one line, and the `println()` after the inner loop ends that line:

```java
for (int row = 0; row < ledBrightness.length; row++)
{
    for (int col = 0; col < ledBrightness[0].length; col++)
    {
        System.out.print(ledBrightness[row][col] + " ");
    }
    System.out.println();
}
```

Output:

```
255 0 128 
64 255 0 
```

The outer bound is `ledBrightness.length` (2 rows), and the inner bound is `ledBrightness[0].length` (3 columns). Swapping just the inner bound to `ledBrightness.length` would make the inner loop stop after only 2 of the 3 columns (it would compile, but silently skip data); swapping both bounds throws `ArrayIndexOutOfBoundsException` once `row` reaches 2, since there is no third row.

## Step 3: Column by Column — Column-Major

Swapping which index the *outer* loop controls changes the order. Now each printed line is one column: the top LED, then the bottom LED below it:

```java
for (int col = 0; col < ledBrightness[0].length; col++)
{
    for (int row = 0; row < ledBrightness.length; row++)
    {
        System.out.print(ledBrightness[row][col] + " ");
    }
    System.out.println();
}
```

Output:

```
255 64 
0 255 
128 0 
```

Same 6 values, visited in a different order. Neither order is "correct." Row-major answers "what does each row of the panel look like," and column-major answers "what does each column look like."

## Step 4: No Indices Needed — Nested For-Each

For printing, the row and column numbers are never actually used, so a nested for-each works too. The outer variable is one whole row (an `int[]`), and the inner variable is one element (an `int`):

```java
for (int[] ledRow : ledBrightness)
{
    for (int brightness : ledRow)
    {
        System.out.print(brightness + " ");
    }
    System.out.println();
}
```

Output (same as row-major, since for-each always goes row by row):

```
255 0 128 
64 255 0 
```

## Step 5: Turning Every LED Off — Why For-Each Won't Work

A tempting first attempt:

```java
for (int[] ledRow : ledBrightness)
{
    for (int brightness : ledRow)
    {
        brightness = 0; // compiles, runs, and changes nothing
    }
}
System.out.println(ledBrightness[0][0]); // still 255
```

`brightness` is a local copy of each `int`. Reassigning it never touches the array, which is the same rule as 1D for-each loops.

## Step 6: Turning Every LED Off — Indexed Nested Loop That Works

Writing into the array needs the real `[row][col]` position, so this needs indices:

```java
for (int row = 0; row < ledBrightness.length; row++)
{
    for (int col = 0; col < ledBrightness[0].length; col++)
    {
        ledBrightness[row][col] = 0;
    }
}
System.out.println(ledBrightness[0][0]); // 0
System.out.println(ledBrightness[1][1]); // 0
```

## Recap

- Traversing a whole 2D array takes nested loops. The outer loop's bound is the row count (`arr.length`), and the inner loop's bound is the column count (`arr[0].length`), or the other way around for column-major.
- Row-major (rows in the outer loop) finishes a row before moving on. Column-major (columns in the outer loop) finishes a column before moving on.
- A nested for-each traverses in row-major order with no indices. Its outer variable is a 1D array (a row), and its inner variable is one element.
- For-each can't change a primitive 2D array's stored values. Use an indexed nested loop to write into `arr[row][col]`.
