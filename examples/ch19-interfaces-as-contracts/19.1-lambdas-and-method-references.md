# Lambdas & Method References — Worked Example

## Problem

New drivers practice with a speed limit on the drivetrain. The drive code passes every joystick value through a "speed rule" before sending it to the motors. Write a speed rule that cuts the input in half — first as a named class, then as a lambda — then a stricter rule that also caps the result at `0.4`. Finally, hand the driver a "warn" action (a horn beep) as a ready-made `Runnable`, written both as a lambda and as a method reference.

## Step 1: The Functional Interface

A speed rule takes one `double` and returns one `double`. That's one abstract method, so this is a **functional interface**:

```java
interface SpeedRule
{
    double apply(double input);
}
```

## Step 2: The Long Way — A Named Class

With only what Lesson 19 covered, implementing it means writing a whole class:

```java
class HalfSpeed implements SpeedRule
{
    @Override
    public double apply(double input)
    {
        return input * 0.5;
    }
}
```

```java
SpeedRule rookieRule = new HalfSpeed();
```

That's a class declaration, an `@Override`, a method signature, and braces — all to say "multiply by 0.5."

## Step 3: The Same Rule as a Lambda

A lambda writes just the one method's body, right where it's needed:

```java
SpeedRule rookieRule = input -> input * 0.5;
```

- `input` is the parameter. Its type (`double`) isn't written — the compiler already knows it from `SpeedRule`'s `apply(double input)`.
- There's only one parameter, so the parentheses around it can be dropped.
- The body is a single expression, so its value is returned automatically — no `return` keyword.

Both versions give `SpeedRule` objects that behave identically: `rookieRule.apply(0.8)` returns `0.4` either way.

## Step 4: A Multi-Statement Lambda

The stricter rule halves the input *and* caps it at `0.4`. That takes more than one statement, so the body needs braces and an explicit `return`:

```java
SpeedRule cappedRule = input -> {
    double halved = input * 0.5;
    return Math.min(halved, 0.4);
};
```

Leave out `return` here and it won't compile — only a single-expression body returns its value automatically.

## Step 5: A Ready-Made Interface and a Method Reference

The horn beep takes nothing and returns nothing, so there's no need to declare a new interface — Java's built-in `Runnable` (in `java.lang`, so no import is needed) has exactly that shape. Its one abstract method is `run()`:

```java
class Horn
{
    public void beep()
    {
        System.out.println("BEEP!");
    }
}
```

```java
Horn horn = new Horn();
Runnable warnLambda = () -> horn.beep(); // a lambda that only calls horn.beep()...
Runnable warnRef = horn::beep;           // ...is exactly what this method reference says
```

`() -> ...` is the empty parameter list, since `run()` takes nothing. Because the lambda's entire body is one call to an existing method, `horn::beep` ("the `beep` method, called on `horn`") says the same thing more directly.

## Step 6: Put It Together

Both versions of the half-speed rule appear side by side here, so they get separate names — `classRule` (Step 2's named class) and `lambdaRule` (Step 3's lambda):

```java
class Horn
{
    public void beep()
    {
        System.out.println("BEEP!");
    }
}

interface SpeedRule
{
    double apply(double input);
}

class HalfSpeed implements SpeedRule
{
    @Override
    public double apply(double input)
    {
        return input * 0.5;
    }
}

public class DriverPractice
{
    public static void main(String[] args)
    {
        SpeedRule classRule = new HalfSpeed();
        SpeedRule lambdaRule = input -> input * 0.5;
        SpeedRule cappedRule = input -> {
            double halved = input * 0.5;
            return Math.min(halved, 0.4);
        };

        System.out.println("Named class: " + classRule.apply(0.8));
        System.out.println("Lambda:      " + lambdaRule.apply(0.8));
        System.out.println("Capped:      " + cappedRule.apply(1.0));

        Horn horn = new Horn();
        Runnable warnLambda = () -> horn.beep();
        Runnable warnRef = horn::beep;

        warnLambda.run();
        warnRef.run();
    }
}
```

## What It Prints

```
Named class: 0.4
Lambda:      0.4
Capped:      0.4
BEEP!
BEEP!
```

The named class and the lambda give the same result for the same input. The capped rule, given a full-speed `1.0`, halves it to `0.5` and then caps it at `0.4`. Calling `run()` on either `Runnable` beeps the horn — the lambda and the method reference are interchangeable.

## Recap

- A functional interface has exactly one abstract method; a lambda implements it inline, without writing a class.
- `input -> input * 0.5`: parameter types are inferred, a single parameter needs no parentheses, and a single-expression body returns automatically.
- A multi-statement body needs `{ }` and an explicit `return`.
- Ready-made functional interfaces like `Runnable` (no arguments, no return value) mean you often don't need to declare your own.
- `horn::beep` is exact shorthand for `() -> horn.beep()` — a method reference only replaces a lambda that does nothing but call one existing method.
