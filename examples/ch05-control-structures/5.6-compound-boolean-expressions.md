# Compound Boolean Expressions — Worked Example

**Outline ref:** 5.6 — Compound Boolean Expressions (CSA 2.5)
**Pairs with:** [`lessons/ch05-control-structures/5.6-compound-boolean-expressions.md`](../../lessons/ch05-control-structures/5.6-compound-boolean-expressions.md)
**Status:** new — authored worked example (fully solved, walked step by step — not a problem to attempt)

## Problem

The shooter is cleared to fire when it's spun up to speed **and** a target is locked — unless the driver holds an override switch, which clears it by itself. Separately, an optional distance sensor object should only be checked for a fault if it actually exists.

## Step 1: Start From the Inputs

```java
boolean rpmReady = true;
boolean targetLocked = false;
boolean overrideSwitch = true;
```

## Step 2: Combine with `&&` and `||`

`&&` needs both sides true; `||` needs at least one side true. "Spun up and locked, or overridden" is exactly one `&&` grouped inside one `||`:

```java
boolean clearedToFire = (rpmReady && targetLocked) || overrideSwitch;
System.out.println(clearedToFire);
```

With these values: `rpmReady && targetLocked` is `true && false`, which is `false` — but `false || overrideSwitch` is `false || true`, which is `true`. Output: `true`. The override switch alone was enough.

## Step 3: Parentheses Make the Grouping Explicit

`&&` binds tighter than `||` on its own, so `rpmReady && targetLocked || overrideSwitch` would actually group the same way without the parentheses — but writing them anyway makes the intent ("these two together, OR this one alone") readable at a glance instead of relying on remembering precedence rules.

## Step 4: Short-Circuit Evaluation for a Null-Safe Check

Separately, suppose an optional distance sensor might not be installed on this robot, represented as a possibly-`null` variable:

```java
DistanceSensor climberSensor = null;

if (climberSensor != null && climberSensor.isFaulty())
{
    System.out.println("Climber sensor fault");
}
```

`&&` stops checking as soon as the left side is false. Here `climberSensor != null` is `false`, so `climberSensor.isFaulty()` is never even evaluated — which is exactly what avoids a `NullPointerException` on a sensor that isn't there. If the two sides were swapped —

```java
if (climberSensor.isFaulty() && climberSensor != null)  // wrong order
```

— the method call happens first, before the null check ever runs, and this crashes the moment `climberSensor` is `null`.

## Step 5: Adding `!`

If the team instead wants to log a warning whenever the shooter is *not* cleared, `!` flips the boolean:

```java
if (!clearedToFire)
{
    System.out.println("Not cleared to fire");
}
```

## Recap

- `&&` requires both sides true; `||` requires at least one; `!` flips a boolean.
- Short-circuit evaluation skips the right side once the left side already determines the result — order a null-check first specifically to exploit this.
- `!` has higher precedence than `&&`, which has higher precedence than `||`; use parentheses when the default grouping isn't what you mean.
