# While Loops — Worked Example

## Problem

Before autonomous starts, the elevator needs to reach its zeroed (home) height. Simulate waiting for it: starting at a known height, keep lowering it one step at a time until it reaches `0`, or until 5 attempts have passed — printing each attempt.

## Step 1: Identify Why `for` Doesn't Fit Well Here

A `for` loop fits naturally when the number of iterations is already known up front. Here, the number of steps needed depends on where the elevator starts — this is waiting for a *condition*, which is exactly when `while` fits better.

## Step 2: Lay Out the Three Steps

Every loop — `for` or `while` — needs the same three ingredients: initialize, test, update. A `while` just spreads them across three separate lines instead of packing them into one header:

```java
double elevatorHeight = 3.0;  // 1. initialize
int attempts = 0;

while (elevatorHeight > 0.0 && attempts < 5)  // 2. test
{
    elevatorHeight -= 1.0;
    attempts++;                                // 3. update
}
```

## Step 3: Add the Print Inside the Loop

```java
double elevatorHeight = 3.0;
int attempts = 0;

while (elevatorHeight > 0.0 && attempts < 5)
{
    elevatorHeight -= 1.0;
    attempts++;
    System.out.println("Attempt " + attempts + ": height = " + elevatorHeight);
}
```

## Step 4: Trace It by Hand

The condition is checked *before* every pass, including the first:

| check | `elevatorHeight > 0.0 && attempts < 5`? | body runs? | printed |
|---|---|---|---|
| `elevatorHeight=3.0, attempts=0` | true | yes | `Attempt 1: height = 2.0` |
| `elevatorHeight=2.0, attempts=1` | true | yes | `Attempt 2: height = 1.0` |
| `elevatorHeight=1.0, attempts=2` | true | yes | `Attempt 3: height = 0.0` |
| `elevatorHeight=0.0, attempts=3` | false | no | — |

The loop stops after 3 attempts because `elevatorHeight > 0.0` became false — the 5-attempt cap never even came into play this time, but it's there in case the elevator gets stuck and never reaches `0`.

## Step 5: What Forgetting the Update Would Do

If Step 2's decrement line were left out —

```java
while (elevatorHeight > 0.0 && attempts < 5)
{
    attempts++;
    // elevatorHeight -= 1.0;  missing!
}
```

— `elevatorHeight` would stay `3.0` forever, but `attempts < 5` still eventually becomes false after 5 passes, so this particular loop would still stop — just after doing nothing useful. If the `attempts` cap weren't there *and* the height update were missing, the loop would never end at all, freezing anything that runs after it. This is exactly why a `while` loop needs something inside it, on every path, that eventually makes the condition false.

## Recap

- Every loop needs three steps: initialize, test, update — `while` just doesn't bundle them into one line like `for` does.
- A `while` loop's condition is checked before every pass, including the first — if it starts false, the body never runs.
- Forgetting to update the loop variable is the classic cause of an infinite loop, which can freeze a robot's control code.
- `while` fits naturally when you're waiting for a condition rather than counting a known number of iterations.
