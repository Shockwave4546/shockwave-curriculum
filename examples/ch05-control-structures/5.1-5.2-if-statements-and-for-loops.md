# if Statements & For Loops — Worked Example

## Problem

Team 1622 bench-tested the intake motor at five different power settings and recorded the current draw (in amps) at each one. Given that array of readings, print each reading followed by `SAFE` if it's under the 40.0 amp limit, or `OVER_LIMIT` if it's at or above it.

## Step 1: Start From the Data

The five readings already exist as an array — this problem is about processing them, not building them:

```java
double[] currentDraw = {18.5, 26.0, 39.9, 40.0, 45.2};
```

## Step 2: Loop Over Every Reading

A `for` loop's three parts — initialize, test, update — visit every valid index once. Starting at `0` pairs with `<`, so `i < currentDraw.length` stops exactly after the last element:

```java
for (int i = 0; i < currentDraw.length; i++)
{

}
```

## Step 3: Add the Two-Way Selection

Inside the loop, an `if`/`else` picks one of two branches based on a boolean condition — here, whether the reading is under the limit:

```java
for (int i = 0; i < currentDraw.length; i++)
{
    if (currentDraw[i] < 40.0)
    {
        System.out.println(currentDraw[i] + " SAFE");
    }
    else
    {
        System.out.println(currentDraw[i] + " OVER_LIMIT");
    }
}
```

Both branches are wrapped in curly braces even though each is a single statement — that's what keeps the "which line is actually inside the `if`" question from ever coming up.

## Step 4: Trace It by Hand

Reading the condition against each array element, in order:

| `i` | `currentDraw[i]` | `< 40.0`? | printed |
|---|---|---|---|
| 0 | 18.5 | true | `18.5 SAFE` |
| 1 | 26.0 | true | `26.0 SAFE` |
| 2 | 39.9 | true | `39.9 SAFE` |
| 3 | 40.0 | false | `40.0 OVER_LIMIT` |
| 4 | 45.2 | false | `45.2 OVER_LIMIT` |

Note `40.0` lands in `OVER_LIMIT` — the condition is `<`, not `<=`, so a reading exactly at the limit does not count as safe.

## Step 5: What the `=` vs. `==` Mistake Would Look Like Here

If Step 3 had accidentally been typed as an assignment instead of a comparison —

```java
if (currentDraw[i] = 40.0)   // does NOT compile: double isn't a boolean
```

— for a `double` this particular typo actually fails to compile, because an `if` requires a `boolean` and `currentDraw[i] = 40.0` is a `double`. The dangerous version of this bug is on an actual `boolean` variable (like `isOverLimit = true`), where the assignment compiles and silently makes the condition always true — worth remembering even though this exact program wouldn't trigger it.

## Recap

- An `if` runs its body only when its condition is true; an `else` gives it a second branch for when it's false.
- Always use curly braces around a conditional or loop body.
- `==` tests equality; `=` assigns. Confusing them compiles but silently breaks the logic.
- A `for` loop's header has three parts — initialize, test, update — always in that order, separated by semicolons.
