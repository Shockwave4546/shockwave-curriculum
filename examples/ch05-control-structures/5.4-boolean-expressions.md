# Boolean Expressions — Worked Example

## Problem

Given the final score for team 1622's alliance and for the opposing alliance in a match, print three diagnostic boolean values: whether the alliance won, whether their score is exactly a multiple of 10 (a scouting "round number" flag), and whether the two scores are tied.

## Step 1: Start From the Two Scores

```java
int allianceScore = 130;
int opponentScore = 118;
```

## Step 2: Test the Win Condition

`>` is a relational operator — it always produces `true` or `false`, never a number:

```java
System.out.println(allianceScore > opponentScore);  // true
```

## Step 3: Test for a Round-Number Score

`%` (from Ch.2) gives the remainder of a division. A score is a multiple of 10 exactly when dividing it by 10 leaves no remainder:

```java
System.out.println(allianceScore % 10 == 0);  // true  — 130 % 10 is 0
System.out.println(opponentScore % 10 == 0);  // false — 118 % 10 is 8
```

This is the same `% ... == 0` shape used to test for even numbers — divisibility by 10 instead of divisibility by 2.

## Step 4: Test for a Tie

`==` on these two variables compares actual numeric values, because `int` is a primitive — exactly what "tied" means here:

```java
System.out.println(allianceScore == opponentScore);  // false
```

If both scores had been declared as some object type instead of `int`, `==` would compare whether the two variables point at the *same object* in memory, not whether the scores inside them match — two separately-built scouting-report objects with identical numbers would still be `==`-unequal. That distinction doesn't come up for `int` here, but it's why `==` needs a second look once objects are involved (full treatment in Ch.6).

## Step 5: Put It Together

```java
int allianceScore = 130;
int opponentScore = 118;

System.out.println(allianceScore > opponentScore);   // win?
System.out.println(allianceScore % 10 == 0);          // round-number score?
System.out.println(allianceScore == opponentScore);   // tied?
```

Output:

```
true
true
false
```

## Step 6: A Divisibility Pitfall to Avoid

A divisibility test should always compare the remainder to `0`, never to a specific nonzero value, because a negative number's remainder is negative:

```java
System.out.println(-3 % 2);       // -1, not 1
System.out.println(-3 % 2 == 1);  // false — the "== 1" oddness test misses -3
System.out.println(-3 % 2 != 0);  // true  — "!= 0" works for both signs
```

Match scores are never negative, so `allianceScore % 10 == 0` is safe here either way — but the `== 0` / `!= 0` shape is the one that works for every sign, so it's the habit worth building.

## Recap

- Relational operators (`== != < > <= >=`) always produce a boolean result.
- `==` on primitives compares values; `==` on objects compares identity (same object), not content.
- `%` tests divisibility — `num % 2 == 0` for even, `num % 2 != 0` for odd (not `== 1`, which breaks on negatives).
