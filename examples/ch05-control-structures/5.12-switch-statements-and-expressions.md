# switch Statements and Expressions — Worked Example

## Problem

The robot's LED strip shows the drive team what mode the robot is in. A status code picks the color: `0` (disabled) is `ORANGE`, `1` (autonomous) is `PURPLE`, `2` (teleop) and `3` (endgame) are both `GREEN`, and any other code means something is wrong, so it's `RED`. Print the color for a given status code — first with a classic `switch` statement, then as a `switch` expression.

## Step 1: Start From the Data

```java
int statusCode = 3;
```

One variable, compared against several fixed values — exactly the shape a `switch` is built for. An `else if` chain would repeat `statusCode ==` four times.

## Step 2: Write the Classic switch Statement

Each case prints its color and then `break`s out. `2` and `3` share one case, listed with a comma, and `default` catches every other code:

```java
switch (statusCode)
{
    case 0:
        System.out.println("ORANGE");
        break;
    case 1:
        System.out.println("PURPLE");
        break;
    case 2, 3:
        System.out.println("GREEN");
        break;
    default:
        System.out.println("RED");
        break;
}
```

With `statusCode` set to `3`, Java jumps straight to `case 2, 3:`, prints `GREEN`, and the `break` ends the `switch`.

## Step 3: What a Missing break Would Do

Suppose the `break` after `PURPLE` had been forgotten, and `statusCode` were `1`:

```java
    case 1:
        System.out.println("PURPLE");
        // break forgotten here
    case 2, 3:
        System.out.println("GREEN");
        break;
```

| step | what runs | printed |
|---|---|---|
| jump to the matching label | `case 1:` | — |
| run case 1's statement | `println("PURPLE")` | `PURPLE` |
| no `break`, so fall through | `println("GREEN")` | `GREEN` |
| reach a `break` | the `switch` ends | — |

The drive team would see two colors for one mode. Nothing about `case 2, 3:` stops the fall-through — labels are only jump targets, not walls.

## Step 4: Rewrite It as a switch Expression

The only thing that differs between the cases is *which color* gets printed. That's a value, so a `switch` expression can pick it, and a single `println` can print it afterward. The arrow form also removes every `break`, so Step 3's bug can't happen:

```java
String color = switch (statusCode)
{
    case 0 -> "ORANGE";
    case 1 -> "PURPLE";
    case 2, 3 -> "GREEN";
    default -> "RED";
};

System.out.println(color);
```

The `default` isn't optional here: `statusCode` is an `int`, so without it the `switch` wouldn't produce a value for codes like `7`, and it wouldn't compile. The semicolon after the closing brace ends the `String color = ...` assignment.

## Step 5: Put It Together

```java
public class LedStatus
{
    public static void main(String[] args)
    {
        int statusCode = 3;

        String color = switch (statusCode)
        {
            case 0 -> "ORANGE";
            case 1 -> "PURPLE";
            case 2, 3 -> "GREEN";
            default -> "RED";
        };

        System.out.println(color);
    }
}
```

Output:

```
GREEN
```

Change `statusCode` to `7` and it prints `RED`, from the `default` case.

## Recap

- A `switch` matches one value against fixed case labels; it works on `int`, `char`, `String` and enum values.
- In the colon form, each case needs a `break`; without one, execution falls through into the next case. `default` catches every value no label matched.
- The arrow form (`case 1 ->`) never falls through, and `case 1, 2` lists several labels for one action.
- A `switch` expression produces a value and must cover every possible input, so `int` and `String` switch expressions need a `default`.
