# Nested if Statements — Worked Example

## Problem

Given the number of game pieces team 1622's robot scored in a match, print a performance tier: `"ELITE"` for 8 or more, `"SOLID"` for 5 to 7, and `"DEVELOPING"` for anything below that.

## Step 1: Start From the Data

```java
int piecesScored = 6;
```

## Step 2: Chain the Branches with `else if`

Three tiers need three paths, and only one should ever run. Chaining `else if` checks each condition in order and stops at the first true one:

```java
String tier;

if (piecesScored >= 8)
{
    tier = "ELITE";
}
else if (piecesScored >= 5)
{
    tier = "SOLID";
}
else
{
    tier = "DEVELOPING";
}

System.out.println(tier);
```

With `piecesScored = 6`: the first condition (`>= 8`) is false, so control moves to the `else if`; `6 >= 5` is true, so `tier` becomes `"SOLID"` and the trailing `else` never runs. Output: `SOLID`.

Notice the middle branch doesn't need to also check `piecesScored < 8` — by the time `else if (piecesScored >= 5)` is reached, the first condition has already failed, so being here already means it's under 8.

## Step 3: Why It Can't Be Separate `if`s

Writing three unconnected `if` statements instead would check all three independently, and a later one can silently overwrite an earlier assignment:

```java
// NOT connected — every condition is checked independently
if (piecesScored >= 8)  { tier = "ELITE"; }
if (piecesScored >= 5)  { tier = "SOLID"; }       // an 8 would ALSO hit this,
if (piecesScored < 5)   { tier = "DEVELOPING"; }  // overwriting "ELITE" with "SOLID"!
```

With a score of `8`, the chained version correctly stops at `"ELITE"`. This unconnected version would first set `tier` to `"ELITE"`, then immediately overwrite it with `"SOLID"` on the very next line, since `8 >= 5` is also true. `else if` is what makes the branches mutually exclusive.

## Step 4: The Trailing `else` Isn't Optional Busywork

Leaving off the final `else` means "do nothing" becomes a real possible outcome — if neither condition had matched, `tier` would never be assigned at all, and the `println` below it wouldn't even compile (Java requires a local variable to be definitely assigned before it's read). Keeping the plain `else` guarantees every possible score lands in exactly one tier.

## Recap

- `else if` chains pick exactly one branch — the first condition that's true, and nothing after it.
- Unconnected, separate `if` statements are checked independently and can overwrite each other's results.
- An `else` always attaches to the nearest unmatched `if` — braces are the only reliable way to control this.
