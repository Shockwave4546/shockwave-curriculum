# Constructors & "this" — Worked Example

**Pairs with:** [`lessons/ch08-constructors-and-this/8.1-8.2-constructors-and-this.md`](../../lessons/ch08-constructors-and-this/8.1-8.2-constructors-and-this.md)
**Status:** new — authored worked example (fully solved, walked step by step — not a problem to attempt)

## Problem

Model a single drivetrain motor for a robot. It needs a `motorPort` and a `speed`. Teammates should be able to build a motor by specifying both the port and a starting speed, or by specifying just the port — in which case the motor starts stopped, at speed `0.0`.

## Step 1: Sketch the Class and Its Fields

Start with just the instance variables — no constructor yet:

```java
public class DriveMotor
{
    private int motorPort;
    private double speed;
}
```

Right now, this class has no constructor written at all, so Java hands it a free no-argument one behind the scenes: it sets `motorPort` to `0` and `speed` to `0.0`, the defaults for `int` and `double`. That's not useful here — a motor with no known port isn't in a valid state — so the next steps replace it.

## Step 2: Write the Two-Argument Constructor

A constructor's job is to leave the object in a valid state. This one takes both values a motor needs and assigns them. Naming the parameters the same as the instance variables makes the constructor read clearly — the tradeoff is that `motorPort` (the parameter) now shadows `motorPort` (the instance variable), so `this` is required to reach the instance variable:

```java
public class DriveMotor
{
    private int motorPort;
    private double speed;

    public DriveMotor(int motorPort, double speed) // same name as the class, no return type
    {
        this.motorPort = motorPort;
        this.speed = speed;
    }
}
```

`this.motorPort` unambiguously means "this object's `motorPort`"; the bare `motorPort` on the right is the parameter. The moment this constructor exists, the free default constructor from Step 1 is gone — `DriveMotor` now only builds the way this constructor says it can.

## Step 3: Add an Overloaded Constructor for a Default Speed

A teammate building a motor that should just start stopped shouldn't have to type `0.0` every time. Add a second constructor, distinguished by its parameter list — the same overloading concept as overloaded methods (Ch.4.1):

```java
public class DriveMotor
{
    private int motorPort;
    private double speed;

    public DriveMotor(int motorPort, double speed)
    {
        this.motorPort = motorPort;
        this.speed = speed;
    }

    public DriveMotor(int motorPort)
    {
        this.motorPort = motorPort;
        this.speed = 0.0; // sensible default: starts stopped
    }
}
```

Both constructors leave the object in a valid state — they just differ in how much the caller has to supply.

## Step 4: Put It Together in `main`

```java
public class DriveMotor
{
    private int motorPort;
    private double speed;

    public DriveMotor(int motorPort, double speed)
    {
        this.motorPort = motorPort;
        this.speed = speed;
    }

    public DriveMotor(int motorPort)
    {
        this.motorPort = motorPort;
        this.speed = 0.0; // sensible default: starts stopped
    }

    public static void main(String[] args)
    {
        DriveMotor leftDrive = new DriveMotor(3, 0.8);   // port 3, starts at 0.8
        DriveMotor rightDrive = new DriveMotor(5);        // port 5, starts stopped

        System.out.println("Left drive  - port: " + leftDrive.motorPort + ", speed: " + leftDrive.speed);
        System.out.println("Right drive - port: " + rightDrive.motorPort + ", speed: " + rightDrive.speed);
    }
}
```

`leftDrive` is built with the two-argument constructor from Step 2; `rightDrive` is built with the one-argument constructor from Step 3. Java picks which constructor runs by matching the argument list at the `new` call — that's overload resolution, the same as for methods. `main` can read `motorPort` and `speed` straight off either object even though both fields are `private`: `private` hides a field from *other* classes, not from other methods of the *same* class, and this `main` lives inside `DriveMotor` itself.

## What It Prints

```
Left drive  - port: 3, speed: 0.8
Right drive - port: 5, speed: 0.0
```

`rightDrive` never had a speed passed in, so its `speed` shows the `0.0` default from Step 3 instead.

## Step 5: Pass `this` to Another Method

`this` isn't just for disambiguating fields — it's a full reference to the current object, so it can be passed anywhere an object of that type is expected, like any other argument. Add one static method that logs any `DriveMotor`, and one instance method that hands itself over:

```java
public static void logStatus(DriveMotor motor)
{
    System.out.println("[LOG] port " + motor.motorPort + ", speed " + motor.speed);
}

public void reportStatus()
{
    logStatus(this); // pass the current object itself
}
```

Then call it from `main`:

```java
leftDrive.reportStatus();
```

`reportStatus()` doesn't build a new `DriveMotor` or know its own port/speed by name — it just hands `this` (whichever `DriveMotor` it was called on) to `logStatus`, which reads `motor.motorPort` and `motor.speed` off whatever object it was given. `logStatus` is `static`, so it has no `this` of its own — it only knows about the motor because one was passed in.

Output adds one line:

```
[LOG] port 3, speed 0.8
```

## What Forgetting `this` Would Look Like

If Step 2's constructor had been written without `this`:

```java
public DriveMotor(int motorPort, double speed)
{
    motorPort = motorPort; // bug: parameter assigned to itself
    speed = speed;         // bug: parameter assigned to itself
}
```

Both lines compile — `motorPort` and `speed` are valid names on both sides. But without `this`, the compiler always means the closest name in scope, which is the parameter. `motorPort = motorPort;` just assigns the parameter to itself; the instance variable `motorPort` never gets touched and stays at its default, `0`. Every `DriveMotor` built this way would silently think it's on port `0`, no matter what the caller passed in — and nothing about it would look wrong until the robot tried to drive the wrong motor.

## Recap

- A constructor's signature has no return type and always matches the class's name; its job is to leave the object in a valid state.
- With no constructor written, Java provides a default one that zeroes/nulls every instance variable — writing any constructor yourself removes that default.
- Constructors can be overloaded, just like methods, distinguished by parameter lists.
- `this` refers to the current object inside an instance method or constructor — essential for disambiguating a parameter from an instance variable of the same name.
- Java picks which overloaded constructor runs by matching the argument list at the `new` call — the same overload resolution used for methods.
- `this` can be passed as an argument, like any other object reference — `logStatus(this)` hands the current object to a method that takes one. Static methods have no `this` of their own.
