# Packages & Imports — Worked Example

## Problem

Your team keeps robot code organized into packages by what it does. Write a small diagnostics file, living in the package `frc.robot.diagnostics`, that uses WPILib's `Timer` class (from a different package) to time how long a startup self-test takes and print the result.

## Step 1: Declare This File's Package

```java
package frc.robot.diagnostics;
```

The `package` line always comes first in the file. It says this file lives in `frc.robot.diagnostics` — the same way a folder groups related files, this package groups related classes. On disk, this file would sit inside a `frc/robot/diagnostics/` folder.

## Step 2: Try Using `Timer` Without Importing It

```java
package frc.robot.diagnostics;

public class SelfTest
{
    public static void main(String[] args)
    {
        Timer testClock = new Timer();
    }
}
```

`Timer` lives in WPILib's `edu.wpi.first.wpilibj` package — a different package from `frc.robot.diagnostics`. Without telling this file where to find `Timer`, this is a compile error: the compiler has no idea what `Timer` refers to.

## Step 3: Add the Import

```java
package frc.robot.diagnostics;

import edu.wpi.first.wpilibj.Timer;

public class SelfTest
{
    public static void main(String[] args)
    {
        Timer testClock = new Timer();
    }
}
```

The `import` line brings `Timer` in from `edu.wpi.first.wpilibj`, so the rest of the file can refer to it by its short name, `Timer`, instead of writing `edu.wpi.first.wpilibj.Timer` every time.

## Step 4: Use It

```java
package frc.robot.diagnostics;

import edu.wpi.first.wpilibj.Timer;

public class SelfTest
{
    public static void main(String[] args)
    {
        Timer testClock = new Timer();
        testClock.start();

        double elapsed = testClock.get();
        System.out.println(elapsed);
    }
}
```

Same `Timer` behaviors as before — `start()` and `get()` — now available because of the import.

## Step 5: What Didn't Need an Import

`System` never needed an import, even though it isn't declared anywhere in `frc.robot.diagnostics`. `System` is in `java.lang`, which is always available in every Java file with no `import` needed — that's why `System.out.println` has worked since the very first program, before packages ever came up. (`double` isn't a class at all — it's a primitive type, so importing never applies to it.)

## Recap

- A package groups related classes together, the way a folder groups related files. This file's `frc.robot.diagnostics` package would live in a `frc/robot/diagnostics/` folder.
- `import` brings a class from another package into your file so you can use its short name — `import edu.wpi.first.wpilibj.Timer;` is what makes plain `Timer` work here.
- `java.lang` (which includes `String` and `System`) never needs an import — it's always available, which is why `System.out.println` needed nothing extra.
