# Casting & Ranges of Values — Worked Example

## Problem

Given a total encoder tick count collected over several samples, compute the exact average ticks per sample as a decimal for internal math, and a rounded whole-number version for a simple driver-station readout.

## Step 1: Plan It First

1. Store the total ticks and the number of samples (both whole numbers).
2. Compute the exact average as a decimal, casting *before* dividing.
3. Compute a rounded whole-number version of that average.
4. Print both.

## Step 2: Set Up the Class and `main`

```java
public class EncoderAverage
{
    public static void main(String[] args)
    {

    }
}
```

## Step 3: Declare the Whole-Number Inputs

```java
int totalTicks = 1450;
int sampleCount = 6;
```

Both `int` — encoder ticks and a sample count are counted things, never fractional.

## Step 4: Compute the Precise Decimal Average

```java
double preciseAverage = (double) totalTicks / sampleCount;
```

`(double)` sits directly in front of `totalTicks`, converting *that one value* to a `double` before anything else happens. Because one side of the `/` is now a `double`, the whole division is carried out with decimals: `241.66666...`. If the cast had been placed around the whole expression instead —

```java
double wrongAverage = (double) (totalTicks / sampleCount); // 241.0 — wrong
```

— `totalTicks / sampleCount` would finish first as plain `int` division (truncating to `241`), and only *that* whole number gets converted to a `double` afterward. Casting doesn't undo work that already happened; position is everything.

## Step 5: Compute a Rounded Whole-Number Version

`(int)` always cuts off the decimal — it never rounds on its own. `(int) 241.666...` would give `241`, not the nearest whole number. To actually round, add `0.5` first, then cast:

```java
int roundedAverage = (int) (preciseAverage + 0.5); // 242
```

`241.666... + 0.5` is `242.166...`, and cutting off the decimal from *that* lands on `242` — the correctly rounded result, not the truncated one.

## Step 6: Print Both

```java
System.out.println("Precise average: " + preciseAverage + " ticks/sample");
System.out.println("Rounded average: " + roundedAverage + " ticks/sample");
```

Output:

```
Precise average: 241.66666666666666 ticks/sample
Rounded average: 242 ticks/sample
```

## A Note on Limits

Neither value here comes close to it, but both types involved have a ceiling worth remembering: `totalTicks` is an `int`, which silently wraps around if it ever climbs past roughly ±2.1 billion (an encoder that's never reset over a long enough run could theoretically get there). `preciseAverage` is a `double`, which only keeps about 14-15 digits of precision — which is also exactly why comparing two `double`s with `==` is risky, even when the math "should" line up exactly.

## Recap

- `(int)` and `(double)` convert a value's type on the spot; `(int)` always cuts off decimals, never rounds.
- To fix truncating division, cast one of the numbers *before* dividing — position matters, as `wrongAverage` showed.
- To actually round instead of truncate, add `0.5` before casting to `int`.
- `int` values have a fixed range; going past it silently wraps to a wrong value.
- `double` values have a precision limit — tiny rounding differences can make `==` unreliable.
