# Assignment & Input — Worked Example

**Outline ref:** 2.3 — Assignment and Input (CSA 1.4)
**Pairs with:** [`lessons/ch02-variables-and-types/2.3-assignment-and-input.md`](../../lessons/ch02-variables-and-types/2.3-assignment-and-input.md)
**Status:** new — authored worked example (fully solved, walked step by step — not a problem to attempt)

## Problem

Take a flywheel's current RPM reading (standing in for a sensor input), save a snapshot of it for later comparison, then update the live RPM as a new reading comes in — and confirm the snapshot didn't move.

## Step 1: Plan It First

1. Store the current RPM reading (the "input" — it comes from a sensor, not typed text).
2. Copy it into a snapshot variable for later comparison.
3. Update the live RPM based on a new reading, using its own old value.
4. Print both the live value and the snapshot to confirm they're now different.

## Step 2: Set Up the Class and `main`

```java
public class FlywheelSnapshot
{
    public static void main(String[] args)
    {

    }
}
```

## Step 3: Assign the Initial Reading

```java
double currentRPM = 3000.0; // stands in for "whatever value the RPM sensor sends"
```

This is what "input" means here — some value arrives from outside the code (a sensor, in this case, not a keyboard). It gets stored in a variable exactly like any other value, and the rest of the code doesn't care where it came from.

## Step 4: Copy It Into a Snapshot

```java
double lastKnownRPM = currentRPM;
```

Read `currentRPM` here as "the value currently stored in `currentRPM`," which is `3000.0` — so `lastKnownRPM` is assigned a *copy* of `3000.0`. This does not link the two variables. `lastKnownRPM` has no idea `currentRPM` even exists after this line runs; it just has its own `3000.0`.

## Step 5: Update the Live Value Using Itself

A new sensor reading comes in, 150 RPM higher than before:

```java
currentRPM = currentRPM + 150;
```

The right-hand side runs first, using the *old* value of `currentRPM` (`3000.0`), computing `3150.0` — and only then is that result stored back into `currentRPM`. If the copy in Step 4 had happened *after* this line instead of before it, `lastKnownRPM` would have captured `3150.0`, not `3000.0` — order matters.

## Step 6: Confirm the Snapshot Didn't Move

```java
System.out.println("Current RPM: " + currentRPM);
System.out.println("Last known RPM: " + lastKnownRPM);
```

Output:

```
Current RPM: 3150.0
Last known RPM: 3000.0
```

`lastKnownRPM` is still `3000.0`, completely unaffected by Step 5 — exactly what a *copy* means. If `=` had somehow linked the two variables together, both numbers would match here, and they don't.

## What Would Break This

If Step 4 came *before* Step 3 — trying to write `double lastKnownRPM = currentRPM;` above the line that first assigns `currentRPM` a value — it wouldn't compile. A variable has to hold a value of the matching type before anything can read from it; Java refuses to guess.

## Recap

- Read `=` as "gets assigned," not "equals."
- Copying a variable's value into another does not link them — each is independent afterward, as `lastKnownRPM` staying put proved.
- A variable must have a value, of a matching type, before it's used in an expression.
- `currentRPM = currentRPM + 150` uses the old value first, then overwrites the variable.
- "Input" is any value that comes from outside your code — a sensor reading here, but a joystick or typed text just as easily.
