# Recursion — Worked Example

## Problem

For a pit display, the team stacks game pieces in a pyramid. The bottom row has `rows` pieces, the row above has one fewer, and so on up to a single piece at the top. Write a recursive method that returns the total number of pieces in a pyramid with a given number of rows, and trace how it works out the answer for a 4-row pyramid.

## Step 1: Plan It First

Look for the smaller version of the same problem inside it:

- A 4-row pyramid is its bottom row (4 pieces) sitting under a 3-row pyramid.
- A 3-row pyramid is 3 pieces sitting under a 2-row pyramid, and so on.

That gives both ingredients:

1. **Recursive call:** the pieces in `rows` rows = `rows` + the pieces in `rows - 1` rows. Passing `rows - 1` moves one step closer to the base case each time.
2. **Base case:** a pyramid with 0 rows has 0 pieces. This is the smallest input, and the method answers it directly with no self-call.

## Step 2: Write the Method

```java
public static int piecesInStack(int rows)
{
    if (rows == 0)      // base case — an empty pyramid has no pieces
    {
        return 0;
    }
    else
    {
        return rows + piecesInStack(rows - 1); // recursive call — one row smaller
    }
}
```

```java
System.out.println(piecesInStack(4)); // 10
```

## Step 3: Trace the Calls Down to the Base Case

Each call goes onto the call stack with its own copy of `rows`. None of them can finish until the call it made returns:

```
piecesInStack(4) returns 4 + piecesInStack(3)
piecesInStack(3) returns 3 + piecesInStack(2)
piecesInStack(2) returns 2 + piecesInStack(1)
piecesInStack(1) returns 1 + piecesInStack(0)
piecesInStack(0) returns 0
```

At this point five calls are in progress at the same time, one for each value of `rows` from 4 down to 0. `piecesInStack(0)` is the only call that returns right away, because it hit the base case.

## Step 4: Substitute Back Up

Now plug each returned value into the call that's waiting for it, working upward from the base case:

```
piecesInStack(1) returns 1 + piecesInStack(0) = 1 + 0 = 1
piecesInStack(2) returns 2 + piecesInStack(1) = 2 + 1 = 3
piecesInStack(3) returns 3 + piecesInStack(2) = 3 + 3 = 6
piecesInStack(4) returns 4 + piecesInStack(3) = 4 + 6 = 10
```

`piecesInStack(4)` returns `10`, which matches counting by hand: 4 + 3 + 2 + 1 = 10.

## Step 5: Check the Base Case Actually Gets Reached

`rows` goes down by exactly 1 on every call, so any starting value of 0 or more eventually hits `rows == 0` and stops. If the recursive call passed `rows` instead of `rows - 1`, the base case would never be reached. Every call would make an identical call, and the program would crash with `StackOverflowError`.

This pyramid is a straight chain of rows with no branching. A `for` loop adding `rows + (rows - 1) + ... + 1` would work just as well. Recursion is used here to practice tracing, because a small linear problem is the easiest place to do it.

## Recap

- Break the problem into "one piece of work + the same problem, one size smaller."
- The base case (`rows == 0`) is the smallest input and returns directly. The recursive call (`rows - 1`) has to move closer to it every time.
- To trace, first write out each call down to the base case, then substitute the returned values back up.
- Each call has its own `rows` on the call stack, so the four waiting calls don't interfere with each other.
