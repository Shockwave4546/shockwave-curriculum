# Searching Algorithms — Worked Example

## Problem

The scouting app keeps the team numbers at this weekend's event in an array, already sorted from lowest to highest. A scout wants to jump to team 6328's entry, and also wants to check whether team 5000 is at the event at all. Look up both teams with a linear search and then with a binary search, and compare how many elements each one checks.

## Step 1: Plan It First

1. Store the sorted team numbers.
2. Linear search: check each element in order, counting how many get checked.
3. Binary search: check the middle, throw away the half that can't hold the target, repeat.
4. Run both searches on a team that's present (6328) and one that isn't (5000), and compare.

```java
int[] eventTeams = {254, 604, 1114, 1622, 2056, 3310, 4414, 6328, 8033};
```

There are 9 teams, at indexes 0 through 8. The array is sorted, which is the one thing binary search needs.

## Step 2: Linear Search

Linear search doesn't care whether the data is sorted. It starts at index 0 and checks each element until it finds the target or runs out of elements:

```java
public static int findTeamLinear(int[] teams, int target)
{
    for (int j = 0; j < teams.length; j++)
    {
        if (teams[j] == target)
        {
            return j;
        }
    }
    return -1; // not found
}
```

```java
System.out.println(findTeamLinear(eventTeams, 6328)); // 7
System.out.println(findTeamLinear(eventTeams, 5000)); // -1
```

Team 6328 is at index 7, so finding it takes 8 checks (indexes 0 through 7). Team 5000 isn't in the array, so the loop has to check all 9 elements before it can return `-1`. That's linear search's worst case.

## Step 3: Binary Search for a Team That's Present

Binary search keeps `left`/`right` bounds and checks the middle element each time:

```java
public static int findTeamBinary(int[] sortedTeams, int target)
{
    int left = 0;
    int right = sortedTeams.length - 1;
    while (left <= right)
    {
        int middle = (left + right) / 2;
        if (target < sortedTeams[middle])
        {
            right = middle - 1; // target must be in the left half
        }
        else if (target > sortedTeams[middle])
        {
            left = middle + 1;  // target must be in the right half
        }
        else
        {
            return middle;      // found it
        }
    }
    return -1; // range exhausted — not found
}
```

Tracing `findTeamBinary(eventTeams, 6328)`:

| Check | `left` | `right` | `middle` | `sortedTeams[middle]` | Result |
|---|---|---|---|---|---|
| 1 | 0 | 8 | 4 | 2056 | 6328 > 2056, so `left = 5` |
| 2 | 5 | 8 | 6 | 4414 | 6328 > 4414, so `left = 7` |
| 3 | 7 | 8 | 7 | 6328 | match, return `7` |

`middle` is `(left + right) / 2` using integer division, so `(7 + 8) / 2` is `7`, not `7.5`. Binary search finds the same index as linear search, `7`, after checking 3 elements instead of 8.

## Step 4: Binary Search for a Team That's Missing

Tracing `findTeamBinary(eventTeams, 5000)`:

| Check | `left` | `right` | `middle` | `sortedTeams[middle]` | Result |
|---|---|---|---|---|---|
| 1 | 0 | 8 | 4 | 2056 | 5000 > 2056, so `left = 5` |
| 2 | 5 | 8 | 6 | 4414 | 5000 > 4414, so `left = 7` |
| 3 | 7 | 8 | 7 | 6328 | 5000 < 6328, so `right = 6` |

After check 3, `left` is `7` and `right` is `6`. Since `left > right`, the `while (left <= right)` condition is false, the loop ends, and the method returns `-1`. It needed 3 checks, where linear search needed 9.

```java
System.out.println(findTeamBinary(eventTeams, 6328)); // 7
System.out.println(findTeamBinary(eventTeams, 5000)); // -1
```

## Step 5: Compare

| Search | Linear search checks | Binary search checks |
|---|---|---|
| 6328 (present, index 7) | 8 | 3 |
| 5000 (not present) | 9 | 3 |

Both methods give the same answers. Binary search only gets them faster because `eventTeams` is sorted. Each check rules out half of the remaining range, so it can skip the teams on the wrong side of the middle without looking at them.

## Recap

- Linear search checks elements in order. A missing target is its worst case, because it has to check all `n` elements before it can return `-1`.
- Binary search needs sorted data. Each check compares the target to the middle element and throws away the half that can't contain it.
- `middle = (left + right) / 2` uses integer division, so the result is always a valid index.
- A missing target makes binary search's range run out (`left > right`), which ends the `while (left <= right)` loop and returns `-1` instead of looping forever.
