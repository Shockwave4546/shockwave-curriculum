# Sorting Algorithms — Worked Example

## Problem

During drive practice, the team timed five scoring cycles (in seconds). Sort the times from fastest to slowest so the drive coach can see the best cycles first. Sort one copy with selection sort and another copy with insertion sort, and track what the array looks like after every pass of each.

## Step 1: Plan It First

1. Store the five cycle times, and make a second copy so each sort starts from the same unsorted data.
2. Selection sort: on each pass, find the smallest remaining time and swap it into the next position.
3. Insertion sort: on each pass, take the next time and shift it left into its spot among the already-sorted times.
4. Compare the passes.

```java
int[] cycleTimes = {14, 9, 21, 6, 11};
int[] cycleTimesCopy = {14, 9, 21, 6, 11};
```

## Step 2: Selection Sort

```java
public static void selectionSort(int[] times)
{
    for (int j = 0; j < times.length - 1; j++)
    {
        int minIndex = j;
        for (int k = j + 1; k < times.length; k++)
        {
            if (times[k] < times[minIndex])
            {
                minIndex = k;
            }
        }
        int temp = times[j];
        times[j] = times[minIndex];
        times[minIndex] = temp;
    }
}
```

The array after each pass of the outer loop:

| Pass (`j`) | Smallest remaining | `minIndex` | Swap | Array after the pass |
|---|---|---|---|---|
| start | | | | `{14, 9, 21, 6, 11}` |
| 0 | 6 | 3 | index 0 and index 3 | `{6, 9, 21, 14, 11}` |
| 1 | 9 | 1 | index 1 with itself (no change) | `{6, 9, 21, 14, 11}` |
| 2 | 11 | 4 | index 2 and index 4 | `{6, 9, 11, 14, 21}` |
| 3 | 14 | 3 | index 3 with itself (no change) | `{6, 9, 11, 14, 21}` |

After pass `j`, everything from index 0 through `j` is in its final spot. In passes 1 and 3 the smallest value was already in place, so the swap didn't change anything. The inner loop still scanned the whole unsorted part to find that out. That's why selection sort does the same amount of scanning no matter how the data starts out.

There are only 4 passes for 5 elements, because the outer loop stops at `times.length - 1`. Once the first four positions are correct, the last element has to be the largest.

## Step 3: Insertion Sort

```java
public static void insertionSort(int[] times)
{
    for (int j = 1; j < times.length; j++)
    {
        int temp = times[j];
        int possibleIndex = j;
        while (possibleIndex > 0 && temp < times[possibleIndex - 1])
        {
            times[possibleIndex] = times[possibleIndex - 1]; // shift right
            possibleIndex--;
        }
        times[possibleIndex] = temp;
    }
}
```

The array after each pass of the outer loop, starting over from `cycleTimesCopy`:

| Pass (`j`) | `temp` | Shifts | Placed at | Array after the pass |
|---|---|---|---|---|
| start | | | | `{14, 9, 21, 6, 11}` |
| 1 | 9 | 1 (14) | index 0 | `{9, 14, 21, 6, 11}` |
| 2 | 21 | 0 | index 2 | `{9, 14, 21, 6, 11}` |
| 3 | 6 | 3 (21, 14, 9) | index 0 | `{6, 9, 14, 21, 11}` |
| 4 | 11 | 2 (21, 14) | index 2 | `{6, 9, 11, 14, 21}` |

After pass `j`, indexes 0 through `j` are sorted relative to each other, but they aren't necessarily in their final spots yet. In pass 3, `6` goes to the front and pushes `9` and `14` to new positions. The outer loop starts at `j = 1` and runs while `j < times.length`, so the last element (`11`, in pass 4) does get inserted.

## Step 4: Compare

```java
selectionSort(cycleTimes);
insertionSort(cycleTimesCopy);
for (int time : cycleTimes)
{
    System.out.print(time + " ");
}
System.out.println(); // 6 9 11 14 21
for (int time : cycleTimesCopy)
{
    System.out.print(time + " ");
}
System.out.println(); // 6 9 11 14 21
```

Both sorts give the same result by different routes:

- Selection sort puts one value in its final position on each pass, by searching for the minimum and swapping it in.
- Insertion sort keeps a sorted section on the left and grows it by one on each pass, shifting larger values right to make room.
- In insertion sort's pass 2, `21` was already larger than everything to its left, so the `while` loop stopped right away with 0 shifts. That early stop is what makes insertion sort adaptive. On data that's already nearly sorted, most passes look like that one.

## Recap

- Selection sort: the outer loop picks the position to fill, the inner loop finds the smallest remaining value, and a swap puts it there. It does the same scanning whatever the starting order is.
- Insertion sort: take `times[j]` as `temp`, shift larger values to the right, and drop `temp` into the gap. Values that are already in order cause little or no shifting.
- Selection sort's outer loop can stop at `length - 1`. Insertion sort's outer loop must run through `length - 1` inclusive (`j < length`), or the last element is never inserted.
- Tracing the array after each pass is the most reliable way to check a sort by hand.
