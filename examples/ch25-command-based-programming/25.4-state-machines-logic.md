# State Machines: Logic — Worked Example

## Problem

A climber subsystem is always in one of three situations: stowed inside the frame, extending its hook up to the bar, or actively climbing. A teammate tracks this with three booleans, and a bug report says the dashboard once showed the climber as "stowed" and "extending" at the same time. Replace the booleans with a state machine that makes that bug impossible.

## Step 1: Plan It First

1. Find out how the boolean version allows the bug.
2. List every state the climber can be in, and make each one an enum constant.
3. Replace the booleans with one field of that enum type, initialized to the real starting state.
4. Check that changing state is now a single assignment that can't leave two states "on."

## Step 2: See How the Booleans Allow the Bug

```java
private boolean isStowed = true;
private boolean isExtending = false;
private boolean isClimbing = false;
```

Starting to extend should mean turning one flag off and another on:

```java
isExtending = true;
// forgot: isStowed = false;
```

One missed line, and `isStowed` and `isExtending` are both `true`. The compiler can't catch it — as far as Java is concerned, any combination of three booleans is legal, even though only three of the eight combinations make sense.

## Step 3: One Enum Constant per State

```java
public enum ClimberState
{
    STOWED,
    EXTENDING,
    CLIMBING
}
```

Every situation the climber can really be in gets exactly one name, and nothing else is possible.

## Step 4: One Field, With a Real Starting Value

The three booleans become a single field:

```java
private ClimberState currentState = ClimberState.STOWED;
```

The climber really does start the match stowed, so that's its initial value. Leaving the field uninitialized would make it `null` — not any of the three states — until something assigned it.

## Step 5: Changing State

Starting to extend is now one assignment:

```java
currentState = ClimberState.EXTENDING;
```

There's no second line to forget. `currentState` held `STOWED`; now it holds `EXTENDING`; it can never hold both, because a variable only holds one value at a time.

## Step 6: Check It Runs

A quick standalone program confirms the state really is exactly one thing at a time:

```java
enum ClimberState
{
    STOWED,
    EXTENDING,
    CLIMBING
}

public class ClimberStateCheck
{
    public static void main(String[] args)
    {
        ClimberState currentState = ClimberState.STOWED;
        System.out.println(currentState); // STOWED
        currentState = ClimberState.EXTENDING;
        System.out.println(currentState); // EXTENDING
    }
}
```

Printing an enum value prints its name, so the output is `STOWED`, then `EXTENDING`.

## Recap

- Several independent booleans allow combinations that make no sense, and the compiler can't stop them.
- An enum lists every real state by name; a single field of that type can only ever hold one of them.
- Always initialize the state field to the subsystem's real starting state.
- A state change is just an assignment — deciding *when* to make it is Lesson 25.5's job.
