# Structuring a Command-Based Robot Project — Worked Example

## Problem

A practice robot has one mechanism: an `Arm`, driven by a motor on CAN ID 9. The team wants:

- Holding the operator's **left bumper** raises the arm at 40% speed; releasing it stops the arm.
- In autonomous, the arm raises for 1.5 seconds, then stops.

Lay out where every piece of this goes in a standard command-based project: `Constants`, the `Arm` subsystem, `RobotContainer`, and `Robot`.

## Step 1: Plan It First

1. Put the two tunable numbers (motor ID, raise speed) in `Constants`.
2. Give `Arm` an instance factory method for its "raise" command, since that command only involves the arm.
3. In `RobotContainer`, create the controller and the arm as `private` fields, bind the bumper, and build the autonomous command.
4. Keep `Robot` thin: run the scheduler, start autonomous, cancel it when teleop begins.

## Step 2: `Constants` — Every Tunable Number in One Place

```java
public class Constants
{
    public static final class ArmConstants
    {
        public static final int kMotorId = 9;
        public static final double kRaiseSpeed = 0.4;
    }
}
```

If the arm moves to a different CAN ID, or the drive team wants it faster, exactly one line changes. `final` means no code can accidentally reassign either value while the robot runs.

## Step 3: `Arm` — A Single-Subsystem Command Lives on the Subsystem

```java
public class Arm extends SubsystemBase
{
    public Command raiseCommand()
    {
        return this.startEnd(() -> this.set(ArmConstants.kRaiseSpeed), () -> this.set(0.0));
    }
}
```

(`set(double speed)` is the arm's own method for driving its motor; its hardware setup is left out here.)

`raiseCommand()` only involves the arm, so an instance factory method on `Arm` is the natural home. Because it's built with the subsystem's own `startEnd`, the command automatically requires `this` arm — no separate `addRequirements` needed.

## Step 4: `RobotContainer` — Where Setup Happens

```java
public class RobotContainer
{
    private final CommandXboxController operatorController = new CommandXboxController(1);
    private final Arm arm = new Arm();

    public RobotContainer()
    {
        configureBindings();
    }

    private void configureBindings()
    {
        operatorController.leftBumper().whileTrue(arm.raiseCommand());
    }

    public Command getAutonomousCommand()
    {
        return arm.raiseCommand().withTimeout(1.5);
    }
}
```

- `arm` is a `private` field. Nothing outside `RobotContainer` can reach it directly — anything that needs the arm has to be handed it explicitly, which keeps every use of the arm going through commands and the scheduler.
- `whileTrue` raises the arm while the bumper is held, and cancels the command (which stops the arm) on release.
- The autonomous command reuses the same factory, with `withTimeout(1.5)` giving it an end condition. Each call to `raiseCommand()` builds a brand-new command object, so the bumper binding and autonomous never share one instance.

## Step 5: `Robot` — Deliberately Thin

```java
public Robot()
{
    robotContainer = new RobotContainer();
}

@Override
public void robotPeriodic()
{
    CommandScheduler.getInstance().run();
}

@Override
public void autonomousInit()
{
    autonomousCommand = robotContainer.getAutonomousCommand();
    if (autonomousCommand != null)
    {
        CommandScheduler.getInstance().schedule(autonomousCommand);
    }
}

@Override
public void teleopInit()
{
    if (autonomousCommand != null)
    {
        autonomousCommand.cancel();
    }
}
```

Nothing arm-specific appears here at all. `Robot` doesn't know the arm exists — it just builds `RobotContainer`, runs the scheduler every loop, and starts or stops whatever autonomous command it's handed. Adding a second mechanism later changes `Constants`, a new subsystem file, and `RobotContainer`, but not `Robot`.

## Recap

- `Constants`: every tunable number, `public static final`, grouped by subsystem.
- Subsystem class: a command that only involves that subsystem is an instance factory method on it.
- `RobotContainer`: `private` subsystem fields, trigger bindings, and the autonomous command.
- `Robot`: builds `RobotContainer`, runs the scheduler in `robotPeriodic()`, schedules autonomous, and cancels it in `teleopInit()`.
