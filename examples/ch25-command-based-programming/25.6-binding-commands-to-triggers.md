# Binding Commands to Triggers — Worked Example

## Problem

The drive team hands you their wish list for the operator's controller, `operatorController` (a `CommandXboxController`):

1. Holding the **right bumper** runs the feeder; letting go stops it.
2. Pressing **A** once raises the amp bar.
3. Pressing **X** fires a note — but only if the shooter is already up to speed.
4. When the indexer's beam-break sensor sees a note, flash the LEDs — without flickering when a note wobbles right at the sensor's edge.

The subsystems already provide these commands and checks: `feeder.runCommand()` (runs until interrupted, stops the feeder when it ends), `ampBar.raiseCommand()`, `indexer.fireCommand()`, `leds.flashCommand()`, `shooter.isAtSpeed()`, and `indexer.hasNote()`. Write the bindings.

## Step 1: Plan It First

For each item, decide two things: what the trigger is, and which binding matches the behavior.

| Item | Trigger | Binding | Why |
|---|---|---|---|
| 1 | right bumper | `whileTrue` | Run while held, cancel when released |
| 2 | A button | `onTrue` | Fire once per press |
| 3 | X button **and** shooter at speed | `onTrue` | Fire once, only when both are true |
| 4 | beam break, debounced | `onTrue` | Fire once per note, ignoring flickers |

## Step 2: Hold to Run — `whileTrue`

```java
operatorController.rightBumper().whileTrue(feeder.runCommand());
```

`rightBumper()` returns a `Trigger` for that button. `whileTrue` schedules `runCommand()` the instant the bumper goes down and cancels it the instant it comes up — and canceling a command runs its `end(...)`, which stops the feeder. No release-handling code needed.

## Step 3: Press Once — `onTrue`

```java
operatorController.a().onTrue(ampBar.raiseCommand());
```

`onTrue` fires only on the change from not-pressed to pressed. Holding A down for five seconds still schedules `raiseCommand()` exactly once.

## Step 4: Two Conditions at Once — `and()`

```java
operatorController.x().and(shooter::isAtSpeed).onTrue(indexer.fireCommand());
```

`and(...)` builds a new trigger that's true only while *both* are true. It accepts any boolean condition, so a method reference like `shooter::isAtSpeed` works the same as another button would. If the operator presses X before the shooter is ready, nothing fires; the combined trigger becomes true — and `fireCommand()` is scheduled — the moment both conditions hold.

## Step 5: A Sensor Trigger, Debounced

```java
new Trigger(indexer::hasNote).debounce(0.1).onTrue(leds.flashCommand());
```

- `new Trigger(indexer::hasNote)` wraps a sensor check, not a button — any boolean condition can be a trigger.
- `debounce(0.1)` requires the sensor to read `true` steadily for 0.1 seconds before the trigger becomes true, so a note wobbling at the sensor's edge doesn't flash the LEDs five times.
- `onTrue` flashes once per note.

## Step 6: All Together

```java
operatorController.rightBumper().whileTrue(feeder.runCommand());
operatorController.a().onTrue(ampBar.raiseCommand());
operatorController.x().and(shooter::isAtSpeed).onTrue(indexer.fireCommand());
new Trigger(indexer::hasNote).debounce(0.1).onTrue(leds.flashCommand());
```

Four lines, written once during setup. From here on, the scheduler checks every one of these conditions each loop by itself.

## Recap

- A `Trigger` wraps any boolean condition — a controller button (`operatorController.a()`) or any `BooleanSupplier` (`new Trigger(indexer::hasNote)`).
- `whileTrue` is for "run while held"; `onTrue` is for "do it once per press."
- `and(...)` combines conditions, just like `&&`.
- `debounce(...)` filters out rapid flickering before a trigger reacts.
