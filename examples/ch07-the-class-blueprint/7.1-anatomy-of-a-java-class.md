# Anatomy of a Java Class — Worked Example

## Problem

Design and write a `Turret` class: it should track which way it's currently pointed and whether it's locked onto a target, and it should be able to start a search sweep (which gives up any lock it currently has).

## Step 1: Design — What Does This Class Need to Know About Itself?

Before writing any code, ask what the thing needs to know about itself:

- Which way is it pointed right now? → a heading, in degrees.
- Is it currently locked onto a target? → yes/no.

That's the data. The search sweep is behavior, not data — it belongs in a method, not an instance variable.

## Step 2: Lay Out the Three Parts

Every class has the same three main parts, in this order: instance variables, constructors, methods. Start from the empty skeleton:

```java
public class Turret
{
    // 1. instance variables — the data each object owns

    // 2. constructors — initialize the instance variables

    // 3. methods — the behaviors
}
```

## Step 3: Add the Instance Variables, `private`

Two `Turret` objects each need their own independent heading and lock state, so these are instance variables — one separate copy per object. They're `private`: only `Turret`'s own code should be able to set `isLockedOnTarget` directly, since "locked on" should only ever be the result of `Turret`'s own targeting logic, not something any other class can just declare `true` from the outside.

```java
public class Turret
{
    private double headingDegrees;
    private boolean isLockedOnTarget;
}
```

## Step 4: Add a Constructor

The constructor initializes the instance variables when a `Turret` is built with `new`. A freshly built turret starts pointed at 0 degrees and not locked onto anything:

```java
public class Turret
{
    private double headingDegrees;
    private boolean isLockedOnTarget;

    public Turret()
    {
        headingDegrees = 0.0;
        isLockedOnTarget = false;
    }
}
```

## Step 5: Add a Method

`startSearchSweep()` is a behavior: it gives up whatever lock the turret currently has so it can start scanning again.

```java
public class Turret
{
    private double headingDegrees;
    private boolean isLockedOnTarget;

    public Turret()
    {
        headingDegrees = 0.0;
        isLockedOnTarget = false;
    }

    public void startSearchSweep()
    {
        isLockedOnTarget = false;
    }
}
```

## Step 6: Check the Naming and the Order

- `Turret` is a class name → PascalCase.
- `startSearchSweep` is a method name → lowerCamelCase.
- `headingDegrees` and `isLockedOnTarget` are instance variables → lowerCamelCase, `private`.
- The three parts appear in the standard order: instance variables, then the constructor, then methods.

## Why `private` Matters Here

If `isLockedOnTarget` were `public`, any other class could write `myTurret.isLockedOnTarget = true;` directly — claiming a lock the turret never actually acquired. Because it's `private`, the only way it can become `true` is through code that lives inside `Turret` itself (targeting logic not shown here), and the only way it can become `false` again from the outside is by calling `startSearchSweep()`. That's encapsulation: outside code can only affect the turret's data through the behavior `Turret` chooses to expose.

## Recap

- Every class has the same three parts, in order: instance variables, constructors, methods — `Turret` follows that order exactly.
- Instance variables are per-object — a second `Turret` would get its own independent `headingDegrees` and `isLockedOnTarget`.
- Instance variables are `private`; methods meant for other classes to call are `public`. This is encapsulation, and it's why `isLockedOnTarget` can only change through `Turret`'s own methods.
- The class was designed by first asking what data it needs to represent (heading, lock state) before any code was written.
