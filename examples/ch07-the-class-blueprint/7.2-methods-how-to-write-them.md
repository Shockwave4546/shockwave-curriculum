# Methods: How to Write Them — Worked Example

## Problem

A `Shooter` class already has a `private` instance variable tracking its flywheel speed. Give other code a way to read that speed, a way to safely change it, and a useful printed representation — without just handing out a raw setter.

## Step 1: Start From the Existing Class

```java
public class Shooter
{
    private double flywheelRpm;

    public Shooter()
    {
        flywheelRpm = 0.0;
    }
}
```

Right now nothing outside `Shooter` can read or change `flywheelRpm` — it's `private` (Lesson 7.1).

## Step 2: Add a Getter

Other code needs to read the current speed, so add a getter — `public`, no parameters, returns the instance variable, named starting with `get`:

```java
public double getFlywheelRpm()
{
    return flywheelRpm;
}
```

## Step 3: Resist the Reflex to Add a Plain Setter

The obvious next move is a `setFlywheelRpm(double newRpm)` setter. But think about what that would let any other class do: set the flywheel to an arbitrary value, including something unsafe, with zero checks. Not every instance variable should be freely settable from outside.

Instead, write a method that changes the data *and* enforces a rule — a maximum safe speed of 6000 RPM:

```java
public void spinUpTo(double targetRpm)
{
    if (targetRpm > 6000.0)
    {
        flywheelRpm = 6000.0;
    }
    else
    {
        flywheelRpm = targetRpm;
    }
}
```

`targetRpm` is a primitive parameter, so it's copied in (call-by-value, Ch.4.1) — passing a variable from the caller in never lets `spinUpTo` change that caller's own variable, only `Shooter`'s own `flywheelRpm`.

## Step 4: Add `toString`

So printing a `Shooter` directly gives something useful instead of Java's default:

```java
public String toString()
{
    return "Shooter[flywheelRpm=" + flywheelRpm + "]";
}
```

## Step 5: Put It Together

```java
public class Shooter
{
    private double flywheelRpm;

    public Shooter()
    {
        flywheelRpm = 0.0;
    }

    public double getFlywheelRpm()
    {
        return flywheelRpm;
    }

    public void spinUpTo(double targetRpm)
    {
        if (targetRpm > 6000.0)
        {
            flywheelRpm = 6000.0;
        }
        else
        {
            flywheelRpm = targetRpm;
        }
    }

    public String toString()
    {
        return "Shooter[flywheelRpm=" + flywheelRpm + "]";
    }
}
```

## Step 6: Try It

```java
Shooter shooter = new Shooter();
shooter.spinUpTo(7500.0);              // over the cap
System.out.println(shooter);           // Java calls toString() automatically
System.out.println(shooter.getFlywheelRpm());
```

```
Shooter[flywheelRpm=6000.0]
6000.0
```

Requesting 7500 RPM didn't produce 7500 RPM — `spinUpTo` clamped it, which a bare setter never would have.

## Recap

- Getters return an instance variable's value and take no parameters — `getFlywheelRpm()` here.
- Not every instance variable needs a plain setter — `flywheelRpm` only changes through `spinUpTo`, which enforces the 6000 RPM cap a bare setter couldn't.
- `toString` is called automatically whenever Java needs to turn an object into text — `System.out.println(shooter)` used it without being asked explicitly.
- Method parameters follow the same call-by-value rule as before: `targetRpm` is a copy, so `spinUpTo` never reaches back and changes the caller's own variable.
