# Inheritance Hierarchies — Exercises

## Multiple Choice

**Question:** Given this small hierarchy:

```java
class Actuator { }
class Arm extends Actuator { }
class Wrist extends Actuator { }
```

Which of these does **not** compile?

**Options:**

- A. `Actuator m = new Arm();`
- B. `Wrist w = new Actuator();`
- C. `Actuator[] parts = { new Arm(), new Wrist() };`
- D. `ArrayList<Actuator> list = new ArrayList<Actuator>();` followed by `list.add(new Wrist());`

**Answer:** B

**Why:** A subclass-typed variable can't hold a plain superclass object. `Wrist w` promises that `w` refers to a `Wrist`, but an `Actuator` isn't necessarily a `Wrist` — so the compiler rejects it. Assignments only work the other direction: superclass variable, subclass object.

- A is wrong — this compiles. An `Arm` is an `Actuator`, so an `Actuator` variable can hold it.
- C is wrong — this compiles. An `Actuator[]` array can hold any mix of `Actuator` and its subclasses, because every `Arm` and every `Wrist` is an `Actuator`.
- D is wrong — this compiles too, for the same reason as C: an `ArrayList<Actuator>` accepts any object that is an `Actuator`, including a `Wrist`.

## Micro-Parsons

**Problem:** An intake has two rollers, and both are kinds of `Roller`. Given these classes, which are already written and go *below* the main class in the same file:

```java
class Roller
{
    private String name;

    public Roller(String name)
    {
        this.name = name;
    }

    public void spin()
    {
        System.out.println(name + " spinning");
    }
}

class FloorRoller extends Roller
{
    public FloorRoller()
    {
        super("Floor roller");
    }
}

class FeederRoller extends Roller
{
    public FeederRoller()
    {
        super("Feeder roller");
    }
}
```

Reorder the fragments below into the main class that goes above them. It should store both rollers in one `Roller[]` array, then loop over the array and call `spin()` on each one, printing `Floor roller spinning` and then `Feeder roller spinning`:

- a. `        for (Roller r : rollers)`
- b. `    }`
- c. `public class RollerCheck`
- d. `            r.spin();`
- e. `    {`
- f. `}`
- g. `        Roller[] rollers = { new FloorRoller(), new FeederRoller() };`
- h. `{`
- i. `        }`
- j. `    public static void main(String[] args)`
- k. `        {`

**Answer:** c, h, j, e, g, a, k, d, i, b, f

```java
public class RollerCheck
{
    public static void main(String[] args)
    {
        Roller[] rollers = { new FloorRoller(), new FeederRoller() };
        for (Roller r : rollers)
        {
            r.spin();
        }
    }
}

class Roller
{
    private String name;

    public Roller(String name)
    {
        this.name = name;
    }

    public void spin()
    {
        System.out.println(name + " spinning");
    }
}

class FloorRoller extends Roller
{
    public FloorRoller()
    {
        super("Floor roller");
    }
}

class FeederRoller extends Roller
{
    public FeederRoller()
    {
        super("Feeder roller");
    }
}
```

**Why this order:** The class line (`c`) and its brace (`h`), then `main` (`j`) and its brace (`e`). The array (`g`) has to exist before the loop (`a`) can walk through it. It's typed `Roller[]`, so it can hold a `FloorRoller` and a `FeederRoller` side by side. The loop's opening brace (`k`) comes next, then its body, `r.spin();` (`d`). `r` is typed `Roller`, and `spin()` is written in `Roller`, so the call works for both objects: each subclass inherits `spin()`. The braces then close in reverse order: the loop (`i`), `main` (`b`), then the class (`f`).


## Coding

**Mode:** full-program

**Problem:** `RobotPart` (below, already written, and not to be changed) is the superclass of
every mechanism. Build a small hierarchy and a registry that manages all of it from one place:

- Three subclasses of `RobotPart`: `Intake`, `Shooter`, and `Climber`. Each one only needs a
  constructor that takes the part's name and passes it up.
- `PartRegistry`, which keeps its parts in one `ArrayList` typed against the **superclass**, so
  it can hold all three kinds. It needs three methods:
  - `add(RobotPart part)` stores a part.
  - `stopAll()` calls `stop()` on every stored part, in the order they were added.
  - `find(String name)` returns the stored part whose `getName()` equals `name`, as a
    `RobotPart`, or `null` if there is none. (If two parts share a name, return the first.)

The fixed `main` reads a part count, then one `kind name` line per part, then a name to look up.
For the input `3 intake Front climber Left shooter Main Left`:

```text
[Front] stopped
[Left] stopped
[Main] stopped
found Left
```

**Starter:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        PartRegistry registry = new PartRegistry();
        int count = in.nextInt();
        for (int i = 0; i < count; i++)
        {
            String kind = in.next();
            String name = in.next();
            if (kind.equals("intake"))
            {
                registry.add(new Intake(name));
            }
            else if (kind.equals("shooter"))
            {
                registry.add(new Shooter(name));
            }
            else
            {
                registry.add(new Climber(name));
            }
        }
        registry.stopAll();
        String query = in.next();
        RobotPart found = registry.find(query);
        if (found == null)
        {
            System.out.println("no part named " + query);
        }
        else
        {
            System.out.println("found " + found.getName());
        }
    }
}
```

**Solution:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        PartRegistry registry = new PartRegistry();
        int count = in.nextInt();
        for (int i = 0; i < count; i++)
        {
            String kind = in.next();
            String name = in.next();
            if (kind.equals("intake"))
            {
                registry.add(new Intake(name));
            }
            else if (kind.equals("shooter"))
            {
                registry.add(new Shooter(name));
            }
            else
            {
                registry.add(new Climber(name));
            }
        }
        registry.stopAll();
        String query = in.next();
        RobotPart found = registry.find(query);
        if (found == null)
        {
            System.out.println("no part named " + query);
        }
        else
        {
            System.out.println("found " + found.getName());
        }
    }
}

// Don't change RobotPart
class RobotPart
{
    private String name;

    public RobotPart(String name) { this.name = name; }
    public String getName() { return name; }
    public void log(String msg) { System.out.println("[" + name + "] " + msg); }
    public void stop() { log("stopped"); }
}

class Intake extends RobotPart
{
    public Intake(String name) { super(name); }
}

class Shooter extends RobotPart
{
    public Shooter(String name) { super(name); }
}

class Climber extends RobotPart
{
    public Climber(String name) { super(name); }
}

class PartRegistry
{
    private ArrayList<RobotPart> parts = new ArrayList<RobotPart>();

    public void add(RobotPart part)
    {
        parts.add(part);
    }

    public void stopAll()
    {
        for (RobotPart p : parts)
        {
            p.stop();
        }
    }

    public RobotPart find(String name)
    {
        for (RobotPart p : parts)
        {
            if (p.getName().equals(name))
            {
                return p;
            }
        }
        return null;
    }
}
```

**Why:** Typing the list as `ArrayList<RobotPart>` is what lets one registry hold an `Intake`, a
`Shooter`, and a `Climber` side by side; an `ArrayList<Intake>` would reject the other two.
`add`'s parameter is also `RobotPart`, so any subclass object is accepted, and `find` returns a
`RobotPart` for the same reason. Comparing names uses `.equals`; `==` would compare references, and
the name read from the input is never the same `String` object as the one stored in a part, so
`find` would never succeed.
