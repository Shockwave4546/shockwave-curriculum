# Inheritance and Constructors — Exercises

## Multiple Choice

**Question:** Given these two classes:

```java
class Actuator
{
    private int channel;

    public Actuator(int channel)
    {
        this.channel = channel;
    }
}

class Clamp extends Actuator
{
    public Clamp()
    {
        System.out.println("Clamp ready");
    }
}
```

What happens when this code is compiled?

**Options:**

- A. It compiles, and `new Clamp()` prints `Clamp ready` with `channel` left at `0`
- B. It doesn't compile, because `Clamp()` needs a `super(...)` call matching `Actuator(int)`
- C. It compiles, but `new Clamp()` throws an exception when it runs
- D. It compiles, and Java automatically calls `Actuator(0)` for `Clamp`

**Answer:** B

**Why:** `Clamp()` doesn't call `super(...)` itself, so Java inserts a no-argument `super()` call at the start of it. That call needs an `Actuator()` constructor with no parameters — but `Actuator`'s only constructor takes an `int`. There's nothing for the inserted call to match, so the compiler rejects `Clamp` outright. The fix is an explicit call like `super(2);` as `Clamp()`'s first line.

- A is wrong — it assumes the superclass's constructor can simply be skipped. It can't: some `Actuator` constructor must run for every `Clamp`, and the only one available needs an argument.
- C is wrong — this is caught at compile time, before anything runs. There's no program to throw an exception.
- D is wrong — Java never invents arguments. The only call it inserts on its own is the no-argument `super()`.

## Micro-Parsons

**Problem:** A `DriverCamera` is a kind of `Camera`. Its constructor should pass its name up to `Camera`'s constructor, then print a ready message using the inherited `getName()` method. Given this main class and superclass, which are already written:

```java
public class CameraSetup
{
    public static void main(String[] args)
    {
        DriverCamera front = new DriverCamera("Front Cam");
    }
}

class Camera
{
    private String name;

    public Camera(String name)
    {
        this.name = name;
    }

    public String getName()
    {
        return name;
    }
}
```

Reorder the fragments below into the `DriverCamera` class that goes right after `Camera`, so the program prints `Front Cam ready for driver view`:

- a. `        System.out.println(getName() + " ready for driver view");`
- b. `    public DriverCamera(String name)`
- c. `}`
- d. `class DriverCamera extends Camera`
- e. `        super(name);`
- f. `{`
- g. `    }`
- h. `    {`

**Answer:** d, f, b, h, e, a, g, c

```java
public class CameraSetup
{
    public static void main(String[] args)
    {
        DriverCamera front = new DriverCamera("Front Cam");
    }
}

class Camera
{
    private String name;

    public Camera(String name)
    {
        this.name = name;
    }

    public String getName()
    {
        return name;
    }
}

class DriverCamera extends Camera
{
    public DriverCamera(String name)
    {
        super(name);
        System.out.println(getName() + " ready for driver view");
    }
}
```

**Why this order:** The class line with `extends Camera` (`d`) and its opening brace (`f`) come first. Then the constructor's signature (`b`) and opening brace (`h`). Inside the constructor, `super(name);` (`e`) comes first: it runs `Camera`'s constructor, which is the only code that can set `Camera`'s private `name` field. The `println` (`a`) has to come after it — it calls the inherited `getName()`, which can't be used until the `Camera` part of the object has been built. Put `a` before `e` and the code doesn't compile. Then the braces close in reverse: the constructor's body (`g`), then the class's body (`c`).


## Coding

**Mode:** full-program

**Problem:** `RobotPart` (below, already written, and not to be changed) has only one
constructor, `RobotPart(String name)`. Write two classes that depend on `super(...)`:

- `ArmLimitException`, a custom **unchecked** exception (extend `RuntimeException`). Its constructor
  takes a message and passes it up so `getMessage()` returns it.
- `Arm`, a subclass of `RobotPart`. Its constructor takes the arm's name, passes it to `RobotPart`,
  and starts the angle at `0`. `getAngle()` returns the current angle. `setAngle(int angle)` stores
  the new angle, **unless** `angle` is greater than `MAX_ANGLE = 90`: then it must leave the angle
  unchanged and throw `new ArmLimitException("past soft limit: " + angle)`. An angle of exactly `90`
  is allowed.

The fixed `main` reads the arm's name, then a list of target angles, and tries each one. For the
input `Shoulder 45 120 90`:

```text
[Shoulder] angle 45
[Shoulder] past soft limit: 120
[Shoulder] angle 90
```

**Starter:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        Arm arm = new Arm(in.next());
        while (in.hasNextInt())
        {
            int target = in.nextInt();
            try
            {
                arm.setAngle(target);
                arm.log("angle " + arm.getAngle());
            }
            catch (ArmLimitException e)
            {
                arm.log(e.getMessage());
            }
        }
    }
}

// Don't change RobotPart

{

    public RobotPart(String name) { this.name = name; }
    public String getName() { return name; }
    public void log(String msg) { System.out.println("[" + name + "] " + msg); }
    public void stop() { log("stopped"); }
}
```

**Solution:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        Arm arm = new Arm(in.next());
        while (in.hasNextInt())
        {
            int target = in.nextInt();
            try
            {
                arm.setAngle(target);
                arm.log("angle " + arm.getAngle());
            }
            catch (ArmLimitException e)
            {
                arm.log(e.getMessage());
            }
        }
    }
}

// Don't change RobotPart
class RobotPart
{
    private String name;

    public RobotPart(String name) { this.name = name; }
    public String getName() { return name; }
    public void log(String msg) { System.out.println("[" + name + "] " + msg); }
    public void stop() { log("stopped"); }
}

class ArmLimitException extends RuntimeException
{
    public ArmLimitException(String message)
    {
        super(message);
    }
}

class Arm extends RobotPart
{
    private static final int MAX_ANGLE = 90;
    private int angle;

    public Arm(String name)
    {
        super(name);
        angle = 0;
    }

    public int getAngle() { return angle; }

    public void setAngle(int angle)
    {
        if (angle > MAX_ANGLE)
        {
            throw new ArmLimitException("past soft limit: " + angle);
        }
        this.angle = angle;
    }
}
```

**Why:** `RobotPart` has no no-argument constructor, so `Arm`'s constructor must call
`super(name)` itself, and that call is also the only way to set `RobotPart`'s private `name`.
`ArmLimitException` does the same thing one level up: `super(message)` hands the text to
`RuntimeException`, which is what `getMessage()` returns. A constructor that forgets it compiles
(an exception has a no-argument constructor to fall back on) but `getMessage()` returns `null`, so
the log reads `[Shoulder] null`. The limit check uses `>`, not `>=`, because exactly `90` is allowed.
