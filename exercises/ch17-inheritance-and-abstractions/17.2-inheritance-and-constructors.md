# Inheritance and Constructors — Exercises

## Multiple Choice

**Question:** Given these two classes:

```java
class Actuator
{
    private int channel;

    public Actuator(int channel)
    {
        this.channel = channel;
    }
}

class Clamp extends Actuator
{
    public Clamp()
    {
        System.out.println("Clamp ready");
    }
}
```

What happens when this code is compiled?

**Options:**

- A. It compiles, and `new Clamp()` prints `Clamp ready` with `channel` left at `0`
- B. It doesn't compile, because `Clamp()` needs a `super(...)` call matching `Actuator(int)`
- C. It compiles, but `new Clamp()` throws an exception when it runs
- D. It compiles, and Java automatically calls `Actuator(0)` for `Clamp`

**Answer:** B

**Why:** `Clamp()` doesn't call `super(...)` itself, so Java inserts a no-argument `super()` call at the start of it. That call needs an `Actuator()` constructor with no parameters — but `Actuator`'s only constructor takes an `int`. There's nothing for the inserted call to match, so the compiler rejects `Clamp` outright. The fix is an explicit call like `super(2);` as `Clamp()`'s first line.

- A is wrong — it assumes the superclass's constructor can simply be skipped. It can't: some `Actuator` constructor must run for every `Clamp`, and the only one available needs an argument.
- C is wrong — this is caught at compile time, before anything runs. There's no program to throw an exception.
- D is wrong — Java never invents arguments. The only call it inserts on its own is the no-argument `super()`.

## Micro-Parsons

**Problem:** A `DriverCamera` is a kind of `Camera`. Its constructor should pass its name up to `Camera`'s constructor, then print a ready message using the inherited `getName()` method. Given this main class and superclass, which are already written:

```java
public class CameraSetup
{
    public static void main(String[] args)
    {
        DriverCamera front = new DriverCamera("Front Cam");
    }
}

class Camera
{
    private String name;

    public Camera(String name)
    {
        this.name = name;
    }

    public String getName()
    {
        return name;
    }
}
```

Reorder the fragments below into the `DriverCamera` class that goes right after `Camera`, so the program prints `Front Cam ready for driver view`:

- a. `        System.out.println(getName() + " ready for driver view");`
- b. `    public DriverCamera(String name)`
- c. `}`
- d. `class DriverCamera extends Camera`
- e. `        super(name);`
- f. `{`
- g. `    }`
- h. `    {`

**Answer:** d, f, b, h, e, a, g, c

```java
public class CameraSetup
{
    public static void main(String[] args)
    {
        DriverCamera front = new DriverCamera("Front Cam");
    }
}

class Camera
{
    private String name;

    public Camera(String name)
    {
        this.name = name;
    }

    public String getName()
    {
        return name;
    }
}

class DriverCamera extends Camera
{
    public DriverCamera(String name)
    {
        super(name);
        System.out.println(getName() + " ready for driver view");
    }
}
```

**Why this order:** The class line with `extends Camera` (`d`) and its opening brace (`f`) come first. Then the constructor's signature (`b`) and opening brace (`h`). Inside the constructor, `super(name);` (`e`) comes first: it runs `Camera`'s constructor, which is the only code that can set `Camera`'s private `name` field. The `println` (`a`) has to come after it — it calls the inherited `getName()`, which can't be used until the `Camera` part of the object has been built. Put `a` before `e` and the code doesn't compile. Then the braces close in reverse: the constructor's body (`g`), then the class's body (`c`).
