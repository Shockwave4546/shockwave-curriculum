# Abstract Classes and Methods — Exercises

## Multiple Choice

**Question:** Given this class:

```java
abstract class Gripper
{
    private String name;

    public Gripper(String name)
    {
        this.name = name;
    }

    public String getName()
    {
        return name;
    }

    public abstract void grab();
}
```

Which statement is true?

**Options:**

- A. `Gripper g = new Gripper("Claw");` compiles, as long as the code never calls `g.grab()`
- B. `class Claw extends Gripper` compiles without writing `grab()`, and inherits an empty `grab()` that does nothing
- C. `Gripper` isn't allowed to have a constructor, since it can never be instantiated
- D. A subclass that calls `super(name)` in its constructor and implements `public void grab()` can be instantiated, and a `Gripper` variable can hold it

**Answer:** D

**Why:** A concrete subclass has to do two things: run `Gripper`'s constructor through `super(...)`, and give every inherited abstract method a body. A subclass that does both can be built with `new`, and since every such object *is a* `Gripper`, a `Gripper`-typed variable can hold it.

- A is wrong — an abstract class can never be instantiated with `new`, whether or not its abstract methods are ever called. The compiler rejects the line itself: `Gripper is abstract; cannot be instantiated`.
- B is wrong — an abstract method isn't an empty method that gets inherited. A concrete subclass must implement it, or the class doesn't compile (the only alternative is declaring `Claw` abstract too).
- C is wrong — abstract classes can have constructors, and `Gripper` does. It runs for every subclass object, called through `super(name)`; it just can't be called with `new Gripper(...)`.

## Micro-Parsons

**Problem:** Every shot the robot takes is announced the same way, but each kind of shot fires differently. Given the program below, with the `Shot` class missing, reorder the fragments into the `Shot` class that goes where the comment is. `Shot` must be an abstract class with a concrete `announce()` method that prints `Shooting...`, followed by an abstract `fire()` method — write `announce()` first, then `fire()`. The program should print `Shooting...` and then `High shot: hood up, flywheel at full speed`.

```java
public class ShotTest
{
    public static void main(String[] args)
    {
        HighShot shot = new HighShot();
        shot.announce();
        shot.fire();
    }
}

// Shot class goes here

class HighShot extends Shot
{
    @Override
    public void fire()
    {
        System.out.println("High shot: hood up, flywheel at full speed");
    }
}
```

Reorder the fragments below to complete it:

- a. `    public abstract void fire();`
- b. `{`
- c. `        System.out.println("Shooting...");`
- d. `abstract class Shot`
- e. `    }`
- f. `    public void announce()`
- g. `}`
- h. `    {`

**Answer:** d, b, f, h, c, e, a, g

```java
public class ShotTest
{
    public static void main(String[] args)
    {
        HighShot shot = new HighShot();
        shot.announce();
        shot.fire();
    }
}

abstract class Shot
{
    public void announce()
    {
        System.out.println("Shooting...");
    }
    public abstract void fire();
}

class HighShot extends Shot
{
    @Override
    public void fire()
    {
        System.out.println("High shot: hood up, flywheel at full speed");
    }
}
```

**Why this order:** The class declaration (`d`) comes first — `abstract` goes right in it, because `Shot` declares an abstract method and can't be instantiated — followed by the class's opening brace (`b`). The concrete `announce()` method comes next, as the Problem asks: its signature (`f`), opening brace (`h`), `println` (`c`), and closing brace (`e`). Then the abstract `fire()` (`a`): a signature ending in a semicolon, with no braces and no body, because each subclass supplies its own. The class's closing brace (`g`) comes last. `HighShot` isn't abstract, so it must implement `fire()` — which it does — and it inherits `announce()` unchanged.


## Coding

**Mode:** full-program

**Problem:** On this robot there is no such thing as "just a part", so make `RobotPart` an
**abstract** class. Write all three classes:

- `RobotPart` is abstract. It keeps the private `name`, has a constructor taking the name, a
  `getName()` method, a `log(String msg)` method that prints `[name] msg`, and an **abstract**
  method `public abstract void stop()`.
- `Intake` extends `RobotPart`. Its `stop()` logs `rollers off`.
- `Climber` extends `RobotPart`. Its `stop()` logs `brake engaged`.

Both subclasses need a constructor that takes the name and passes it up. The fixed `main` builds
an array of `RobotPart`, stops every part, then prints a count. For the input
`3 intake Front climber Left intake Back`:

```text
[Front] rollers off
[Left] brake engaged
[Back] rollers off
3 parts stopped
```

**Starter:**

```java
import java.util.*;

public class Main

        for (int i = 0; i < count; i++)

            }
        }
        for (RobotPart p : parts)
        {
            p.stop();
        }
        System.out.println(parts.length + " parts stopped");
    }
}
```

**Solution:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        int count = in.nextInt();
        RobotPart[] parts = new RobotPart[count];
        for (int i = 0; i < count; i++)
        {
            String kind = in.next();
            String name = in.next();
            if (kind.equals("intake"))
            {
                parts[i] = new Intake(name);
            }
            else
            {
                parts[i] = new Climber(name);
            }
        }
        for (RobotPart p : parts)
        {
            p.stop();
        }
        System.out.println(parts.length + " parts stopped");
    }
}

abstract class RobotPart
{
    private String name;

    public RobotPart(String name) { this.name = name; }
    public String getName() { return name; }
    public void log(String msg) { System.out.println("[" + name + "] " + msg); }

    public abstract void stop();
}

class Intake extends RobotPart
{
    public Intake(String name) { super(name); }

    @Override
    public void stop() { log("rollers off"); }
}

class Climber extends RobotPart
{
    public Climber(String name) { super(name); }

    @Override
    public void stop() { log("brake engaged"); }
}
```

**Why:** `abstract` on the class means `new RobotPart(...)` no longer compiles, but `RobotPart`
still works as the array's element type, and still has a field, a constructor (run by each
subclass's `super(name)`), and concrete methods. `stop()` is only a signature ending in `;`, so each
concrete subclass has to write its own body, and the compiler rejects a subclass that forgets.
Because every element is really an `Intake` or a `Climber`, `p.stop()` in `main` is always safe, and
runs that class's own version.
