## Multiple Choice

**Question:** What does this code print?

```java
ArrayList<Integer> ids = new ArrayList<Integer>();
ids.add(200);
ids.add(200);

System.out.println(ids.get(0) == ids.get(1));
```

**Options:**

- A. `true`, guaranteed
- B. `false`, guaranteed
- C. Not guaranteed either way — `==` on boxed `Integer` objects compares identity, not value
- D. This won't compile, since `==` can't be used on `ArrayList` elements

**Answer:** C

**Why:** `ids.get(0)` and `ids.get(1)` are boxed `Integer` objects. `==` on objects checks whether they're the same object in memory, not whether their values match — it isn't reliable even for boxed numbers with equal values. The dependable way to compare values is `.equals()`.

- A is wrong — `==` comparing two separately created `Integer` objects isn't reliably `true` just because the underlying values match.
- B is wrong — it isn't reliably `false` either; treating `==` as dependable in either direction is the bug.
- D is wrong — `==` compiles fine on any two object references, including `ArrayList` elements; it just doesn't compare what a beginner might expect.

## Micro-Parsons

**Problem:** This method will live in a class alongside a `main` method that creates a list of shooter RPM setpoints and calls it. These lines, once correctly ordered, form the complete method that rotates that ArrayList right by one position — the last element moves to the front, and everything else shifts right by one.

Reorder the fragments below into a working method:

- a. `    }`
- b. `    for (int i = rpmSetpoints.size() - 1; i > 0; i--)`
- c. `}`
- d. `public static void rotateRight(ArrayList<Double> rpmSetpoints)`
- e. `        rpmSetpoints.set(i, rpmSetpoints.get(i - 1));`
- f. `    double last = rpmSetpoints.get(rpmSetpoints.size() - 1);`
- g. `{`
- h. `    rpmSetpoints.set(0, last);`
- i. `    {`

**Answer:** d, g, f, b, i, e, a, h, c

```java
import java.util.ArrayList;

public class ShooterConfig
{
    public static void rotateRight(ArrayList<Double> rpmSetpoints)
    {
        double last = rpmSetpoints.get(rpmSetpoints.size() - 1);
        for (int i = rpmSetpoints.size() - 1; i > 0; i--)
        {
            rpmSetpoints.set(i, rpmSetpoints.get(i - 1));
        }
        rpmSetpoints.set(0, last);
    }

    public static void main(String[] args)
    {
        ArrayList<Double> rpmSetpoints = new ArrayList<Double>();
        rpmSetpoints.add(2000.0);
        rpmSetpoints.add(3200.0);
        rpmSetpoints.add(4100.0);

        rotateRight(rpmSetpoints);
        System.out.println(rpmSetpoints);
    }
}
```

**Why this order:** `last` (`f`) must be saved before anything gets overwritten — otherwise the value being rotated to the front would already be destroyed by the time the code reaches it. The loop (`b`, `i`) then shifts every element up one index at a time, working backward from the end so each `set(i, ...)` (`e`) copies from a slot that hasn't been overwritten yet. The loop's closing brace (`a`) comes before the final `set(0, last)` (`h`), which must happen last, once the shifting is done. The method's closing brace (`c`) is always last. The surrounding class, import, and `main` (which creates `rpmSetpoints` and calls `rotateRight`) are the given scaffold.
