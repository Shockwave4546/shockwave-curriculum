# Array Traversals — Exercises

## Multiple Choice

**Question:** What does this method do to the array passed into it?

```java
public static void doubleAll(double[] values)
{
    for (double v : values)
    {
        v = v * 2;
    }
}
```

**Options:**

- A. Nothing — the caller's array is unchanged
- B. Every element in the caller's array is doubled
- C. Only the first element is doubled
- D. Doesn't compile, since `v` can't be reassigned inside a for-each loop

**Answer:** A

**Why:** `v` inside a for-each loop is a local copy of each element — reassigning `v` never touches the real array. To actually change elements, an indexed loop is needed instead (`values[i] = values[i] * 2;`).

- B is wrong — that's what an indexed loop would do; for-each can't reach back into the array like that.
- C is wrong — no element changes at all, not even the first; the reassignment is purely local on every iteration.
- D is wrong — reassigning the loop variable is perfectly legal; the loop compiles and runs fine, it just never touches the real array.

## Micro-Parsons

**Problem:** Given this class and main method, reorder the fragments below into the method body that creates an array of sensor readings and prints each reading together with its reading number, starting at 1.

Reorder the fragments below to complete it:

- a. `        {`
- b. `        double[] sensorReadings = {2.1, 2.4, 1.9};`
- c. `            System.out.println("Reading " + (i + 1) + ": " + sensorReadings[i]);`
- d. `        }`
- e. `        for (int i = 0; i < sensorReadings.length; i++)`

**Answer:** b, e, a, c, d

```java
public class SensorLogger
{
    public static void main(String[] args)
    {
        double[] sensorReadings = {2.1, 2.4, 1.9};
        for (int i = 0; i < sensorReadings.length; i++)
        {
            System.out.println("Reading " + (i + 1) + ": " + sensorReadings[i]);
        }
    }
}
```

**Why this order:** The array (`b`) must exist before the loop can reference its `length`. The loop header (`e`) comes before its own opening brace (`a`), and the print statement (`c`) — which labels each reading `i + 1` since match/reading numbers usually start at 1 while the index itself stays 0-based — lives inside those braces. The loop's closing brace (`d`) comes last, after everything it contains. The surrounding class and `main` method are the given scaffold; only the array declaration through the loop needed reordering.

## Coding

**Mode:** harness

**Problem:** Write `capSpeeds`, which changes every element of `speeds` that is **greater than `max`** so it
equals `max`, and then returns the same array. Elements that are `max` or lower stay as they are.

Examples:

- `capSpeeds(new int[] {40, 90, 60}, 70)` returns `{40, 70, 60}`
- `capSpeeds(new int[] {10, 20}, 50)` returns `{10, 20}`
- `capSpeeds(new int[] {100, 100}, 80)` returns `{80, 80}`

**Signature:** `public static int[] capSpeeds(int[] speeds, int max)`

**Starter:**

```java
public class Solution
{
    public static int[] capSpeeds(int[] speeds, int max)
    {
        // TODO: change any element above max to max, then return the array
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `new int[] {40, 90, 60}, 70` | `new int[] {40, 70, 60}` |
| yes | `new int[] {10, 20}, 50` | `new int[] {10, 20}` |
| yes | `new int[] {100, 100}, 80` | `new int[] {80, 80}` |
| no | `new int[] {99, 5, 5, 5}, 50` | `new int[] {50, 5, 5, 5}` |
| no | `new int[] {5, 5, 5, 99}, 50` | `new int[] {5, 5, 5, 50}` |
| no | `new int[] {70, 71}, 70` | `new int[] {70, 70}` |
| no | `new int[] {}, 10` | `new int[] {}` |

**Solution:**

```java
public class Solution
{
    public static int[] capSpeeds(int[] speeds, int max)
    {
        for (int i = 0; i < speeds.length; i++)
        {
            if (speeds[i] > max)
            {
                speeds[i] = max;
            }
        }
        return speeds;
    }
}
```

**Why:** Changing the array needs an indexed loop, so you can write `speeds[i] = max`. A for-each loop
(`for (int s : speeds) { s = max; }`) only changes its own local copy `s`, and the real array comes back
unchanged. The loop bound is `i < speeds.length`; using `<=` would throw `ArrayIndexOutOfBoundsException` on
the last pass.
