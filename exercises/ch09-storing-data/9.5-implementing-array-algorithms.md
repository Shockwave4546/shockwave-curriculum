# Implementing Array Algorithms — Exercises

## Multiple Choice

**Question:** A robot's climb times can legitimately include small negative corrections. What's the problem with this code, which is meant to find the fastest (minimum) climb time?

```java
double min = 0;
for (double time : climbTimes)
{
    if (time < min)
    {
        min = time;
    }
}
```

**Options:**

- A. If every real climb time happens to be positive, `min` stays `0` — a value that was never actually recorded
- B. `time < min` should be `time > min` to find a minimum
- C. This throws an `ArrayIndexOutOfBoundsException`
- D. Nothing is wrong — this correctly finds the minimum

**Answer:** A

**Why:** Seeding `min` with `0` instead of the array's first real element is the classic min/max pitfall — it only happens to give a correct answer when a value below `0` truly exists in the data. If every climb time is positive, the loop never finds anything smaller than the fake starting point of `0`, so it reports a minimum that was never actually recorded. The fix is to seed `min` with `climbTimes[0]` before the loop.

- B is wrong — `<` is the correct comparison for tracking a running minimum; flipping it would track a maximum instead.
- C is wrong — nothing here reads outside the array's bounds.
- D is wrong — this is exactly the "seeding with `0`" pitfall the lesson calls out; it only looks correct by coincidence.

## Micro-Parsons

**Problem:** Given a class with a `main` method where `int[] channels` already holds the radio channel numbers assigned to each subteam, and a `reportDuplicate()` helper method that is already defined, reorder these fragments into the nested loop (inside `main`) that checks every pair of channels (not just neighbors) and calls `reportDuplicate();` the instant two channels match.

Reorder the fragments below to complete it:

- a. `        for (int i = 0; i < channels.length; i++)`
- b. `        {`
- c. `            for (int j = i + 1; j < channels.length; j++)`
- d. `            {`
- e. `                if (channels[i] == channels[j])`
- f. `                {`
- g. `                    reportDuplicate();`
- h. `                }`
- i. `            }`
- j. `        }`

**Answer:** a, b, c, d, e, f, g, h, i, j

```java
public class RadioChannelCheck
{
    public static void reportDuplicate()
    {
        System.out.println("Duplicate channel assignment detected!");
    }

    public static void main(String[] args)
    {
        int[] channels = {10, 15, 22, 8, 15};

        for (int i = 0; i < channels.length; i++)
        {
            for (int j = i + 1; j < channels.length; j++)
            {
                if (channels[i] == channels[j])
                {
                    reportDuplicate();
                }
            }
        }
    }
}
```

**Why this order:** The outer loop (`a`, `b`) has to exist before the inner loop can be nested inside it. The inner loop starts its `j` index at `i + 1` (`c`, `d`) so each pair is only checked once, rather than checking every element against itself and against pairs already covered. The `if` (`e`) and its own braces (`f`, `h`) sit inside both loops so every pair gets examined. The braces close in reverse of how they opened — the `if`'s brace (`h`), then the inner loop's brace (`i`), then the outer loop's brace (`j`). The class, `reportDuplicate()`, the `channels` array, and `main`'s own braces are the given scaffold; only this nested loop needed reordering.

## Coding

**Mode:** harness

**Problem:** A sensor is "stuck" when it reports the same value twice in a row. Write `hasStuckReading`, which
returns `true` if **any two neighbouring** readings in the array are equal, and `false` otherwise. Equal
values that are *not* next to each other don't count. An array with 0 or 1 readings has no neighbours, so the
answer is `false`.

Examples:

- `hasStuckReading(new int[] {3, 5, 5, 8})` returns `true`
- `hasStuckReading(new int[] {3, 5, 3, 5})` returns `false`
- `hasStuckReading(new int[] {4})` returns `false`

**Signature:** `public static boolean hasStuckReading(int[] readings)`

**Starter:**

```java
public class Solution
{
    public static boolean hasStuckReading(int[] readings)
    {
        // TODO: compare each reading with the one after it
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `new int[] {3, 5, 5, 8}` | `true` |
| yes | `new int[] {3, 5, 3, 5}` | `false` |
| yes | `new int[] {4}` | `false` |
| no | `new int[] {1, 2, 3, 3}` | `true` |
| no | `new int[] {7, 7, 1, 2}` | `true` |
| no | `new int[] {1, 2, 3, 4}` | `false` |
| no | `new int[] {}` | `false` |
| no | `new int[] {9, 9}` | `true` |

**Solution:**

```java
public class Solution
{
    public static boolean hasStuckReading(int[] readings)
    {
        for (int i = 0; i < readings.length - 1; i++)
        {
            if (readings[i] == readings[i + 1])
            {
                return true;
            }
        }
        return false;
    }
}
```

**Why:** Each pass compares `readings[i]` with `readings[i + 1]`, so the loop has to stop at
`readings.length - 2`, which is what `i < readings.length - 1` does. Looping all the way to
`readings.length - 1` reads one past the end and throws `ArrayIndexOutOfBoundsException` whenever no pair
matches earlier. Only a match returns early (`true`); `false` waits until every neighbouring pair has been
checked.
