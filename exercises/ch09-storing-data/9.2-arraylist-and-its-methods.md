# ArrayList and its Methods — Exercises

## Multiple Choice

**Question:** Given:

```java
ArrayList<String> queue = new ArrayList<String>();
queue.add("Scout 254");
queue.add("Scout 118");
queue.add(1, "Scout 33");
```

What does `queue.get(1)` return afterward?

**Options:**

- A. `"Scout 33"`
- B. `"Scout 118"`
- C. `"Scout 254"`
- D. This throws an exception because index 1 already had an element

**Answer:** A

**Why:** `add(index, obj)` inserts at that index and shifts everything at or after it one position to the right. `"Scout 33"` is inserted at index 1, pushing `"Scout 118"` (previously at index 1) to index 2.

- B is wrong — that's what `get(1)` would have returned *before* the insert; the shift moved it to index 2.
- C is wrong — `"Scout 254"` stays at index 0, since the insert happened at index 1, not 0.
- D is wrong — inserting and shifting existing elements is exactly what `add(index, obj)` is designed to do, not something that throws.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that creates an ArrayList of pit inventory part names, adds one part to it, then prints how many parts are in the list.

Reorder the fragments below into a working program:

- a. `        parts.add("Backup Battery");`
- b. `public class PitInventory`
- c. `    }`
- d. `{`
- e. `    public static void main(String[] args)`
- f. `}`
- g. `    {`
- h. `        ArrayList<String> parts = new ArrayList<String>();`
- i. `        System.out.println(parts.size());`
- j. `import java.util.ArrayList;`

**Answer:** j, b, d, e, g, h, a, i, c, f

```java
import java.util.ArrayList;

public class PitInventory
{
    public static void main(String[] args)
    {
        ArrayList<String> parts = new ArrayList<String>();
        parts.add("Backup Battery");
        System.out.println(parts.size());
    }
}
```

**Why this order:** The `import` (`j`) has to appear before the class that uses `ArrayList`. Then the usual class/main scaffolding (`b`, `d`, `e`, `g`). The list must be created (`h`) before anything can be added to it (`a`), and it must be created and filled before `size()` (`i`) can report anything meaningful. The braces close in reverse: `main`'s body (`c`), then the class's body (`f`).

## Coding

**Mode:** harness

**Problem:** Write `dropId`, which removes the **first element whose value equals `id`** from the list and
returns the list. If no element equals `id`, return the list unchanged. Remove by **value**, not by position:
`id` is a CAN ID, not an index.

Examples:

- `dropId([5, 7, 1], 1)` returns `[5, 7]`
- `dropId([10, 20, 30], 30)` returns `[10, 20]`
- `dropId([4, 4, 9], 4)` returns `[4, 9]`

**Signature:** `public static ArrayList<Integer> dropId(ArrayList<Integer> ids, int id)`

**Starter:**

```java
import java.util.ArrayList;

public class Solution
{
    public static ArrayList<Integer> dropId(ArrayList<Integer> ids, int id)
    {
        // TODO: remove the first element equal to id, then return the list
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `new java.util.ArrayList<>(java.util.List.of(5, 7, 1)), 1` | `new java.util.ArrayList<>(java.util.List.of(5, 7))` |
| yes | `new java.util.ArrayList<>(java.util.List.of(10, 20, 30)), 30` | `new java.util.ArrayList<>(java.util.List.of(10, 20))` |
| yes | `new java.util.ArrayList<>(java.util.List.of(4, 4, 9)), 4` | `new java.util.ArrayList<>(java.util.List.of(4, 9))` |
| no | `new java.util.ArrayList<>(java.util.List.of(5, 7)), 9` | `new java.util.ArrayList<>(java.util.List.of(5, 7))` |
| no | `new java.util.ArrayList<>(java.util.List.of(3, 1, 8, 1)), 8` | `new java.util.ArrayList<>(java.util.List.of(3, 1, 1))` |
| no | `new java.util.ArrayList<>(java.util.List.of(2)), 2` | `new java.util.ArrayList<>()` |
| no | `new java.util.ArrayList<>(java.util.List.of(0, 6, 0)), 0` | `new java.util.ArrayList<>(java.util.List.of(6, 0))` |

**Solution:**

```java
import java.util.ArrayList;

public class Solution
{
    public static ArrayList<Integer> dropId(ArrayList<Integer> ids, int id)
    {
        ids.remove(Integer.valueOf(id));
        return ids;
    }
}
```

**Why:** `ids.remove(id)` with an `int` argument always picks `remove(int index)`, so it removes by
**position**: for `[5, 7, 1]` it would remove the element at index `1` (the `7`), and for `[10, 20, 30]` it
would throw `IndexOutOfBoundsException`. Wrapping the value with `Integer.valueOf(id)` selects
`remove(Object)`, which removes the first element that `.equals()` the value and does nothing when there is
no match.
