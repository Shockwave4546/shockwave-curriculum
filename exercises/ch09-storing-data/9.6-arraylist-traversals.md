# ArrayList Traversals — Exercises

## Multiple Choice

**Question:** Given `ArrayList<String> alerts` containing `"Low Battery"`, `"Motor Stall"`, and `"Radio Disconnect"`, what happens when this code runs?

```java
for (String alert : alerts)
{
    if (alert.equals("Low Battery"))
    {
        alerts.add("Escalated: Low Battery");
    }
}
```

**Options:**

- A. Throws `ConcurrentModificationException`
- B. Adds the new alert to the end of the list with no error
- C. Does nothing, since `add` inside a for-each loop is silently ignored
- D. Throws `ArrayIndexOutOfBoundsException`

**Answer:** A

**Why:** Adding (or removing) elements from an `ArrayList` while a for-each loop is traversing it throws `ConcurrentModificationException` — this restriction applies to `add` just as much as `remove`.

- B is wrong — that's what an indexed or `while` loop could safely do, but not a for-each loop.
- C is wrong — Java doesn't silently ignore this; it throws, loudly, the moment the mismatch is detected.
- D is wrong — that exception is for accessing an invalid index, not for modifying a collection while it's being traversed.

## Micro-Parsons

**Problem:** This method will live in a class alongside a `main` method that creates a list of defect reports and calls it. These lines, once correctly ordered, form the complete method that removes every entry starting with `"FLAGGED: "` from that list, using the careful pattern that avoids skipping elements after a removal.

Reorder the fragments below into a working method:

- a. `    public static void removeFlagged(ArrayList<String> defectReports)`
- b. `    {`
- c. `        int i = 0;`
- d. `        while (i < defectReports.size())`
- e. `        {`
- f. `            if (defectReports.get(i).startsWith("FLAGGED: "))` `            {`
- g. `                defectReports.remove(i);`
- h. `            }`
- i. `            else` `            {`
- j. `                i++;`
- k. `            }` `        }` `    }`

**Answer:** a, b, c, d, e, f, g, h, i, j, k

```java
import java.util.ArrayList;

public class DefectTracker
{
    public static void removeFlagged(ArrayList<String> defectReports)
    {
        int i = 0;
        while (i < defectReports.size())
        {
            if (defectReports.get(i).startsWith("FLAGGED: "))
            {
                defectReports.remove(i);
            }
            else
            {
                i++;
            }
        }
    }

    public static void main(String[] args)
    {
        ArrayList<String> defectReports = new ArrayList<String>();
        defectReports.add("FLAGGED: Loose wire");
        defectReports.add("Battery voltage low");
        defectReports.add("FLAGGED: Cracked bumper");

        removeFlagged(defectReports);
        System.out.println(defectReports);
    }
}
```

**Why this order:** The index variable (`c`) must be initialized before the `while` condition (`d`) can check it, and the method's and `while`'s own opening braces (`b`, `e`) each stay right after their header. Inside the loop, the `if`/`else` pair must appear in that order — Java requires `if` before its matching `else` — so `f` (the `if` condition plus its opening brace, merged since splitting them further wasn't the point being tested here) comes before `i` (`else` plus its own opening brace, same reasoning). The `if`-branch (`g`) removes the current element without advancing `i`, since the next element just shifted into that spot; the `else`-branch (`j`) is the only place `i++` happens, and only fires on iterations where nothing was removed. `h` closes the `if` block before `i`'s `else` can open. The very end is the one purely forced merge: once the `else` block's own closing brace is placed, the `while`'s closing brace and the method's closing brace have nowhere else to go, so all three are fused into `k`. The surrounding class, import, and `main` (which creates `defectReports` and calls `removeFlagged`) are the given scaffold.
