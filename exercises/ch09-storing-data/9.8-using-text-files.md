# Using Text Files — Exercises

## Multiple Choice

**Question:** A CSV file's first line is `teamNumber,winCount` (column headers), followed by real data rows like `1622,14`. What happens if this code runs without skipping the header row first?

```java
while (scan.hasNextLine())
{
    String[] fields = scan.nextLine().split(",");
    int wins = Integer.parseInt(fields[1]);
    // ...
}
```

**Options:**

- A. Throws a `NumberFormatException` when it tries to parse `"winCount"` as an integer
- B. Silently treats the header as a valid row with 0 wins
- C. Automatically skips the header row, since Java recognizes column names
- D. Compiles fine but the loop never runs

**Answer:** A

**Why:** On the very first iteration, `fields[1]` is the literal text `"winCount"`, and `Integer.parseInt("winCount")` can't convert non-numeric text into an `int` — it throws a `NumberFormatException` at run time. This is exactly why the lesson calls out skipping the header row as a required step, not optional cleanup.

- B is wrong — Java doesn't guess a fallback value; trying to parse non-numeric text as an `int` fails loudly instead of quietly substituting `0`.
- C is wrong — Java has no built-in awareness of "column headers" in a CSV; it reads whatever text is on the first line just like any other line.
- D is wrong — the loop does run: `hasNextLine()` is `true` and the first `nextLine()` succeeds; the crash happens partway through processing that first line, not before the loop starts.

## Micro-Parsons

**Problem:** This method will live in a class alongside a `main` method that calls it with a filename. These lines, once correctly ordered, form the complete method that opens a file by name, counts how many lines it contains, and returns that count.

Reorder the fragments below into a working method:

- a. `    public static int countLines(String filename) throws IOException`
- b. `    {`
- c. `        Scanner scan = new Scanner(new File(filename));`
- d. `        int count = 0;`
- e. `        while (scan.hasNextLine())`
- f. `        {`
- g. `            scan.nextLine();`
- h. `            count++;`
- i. `        }`
- j. `        scan.close();`
- k. `        return count;`
- l. `    }`

**Answer:** a, b, c, d, e, f, g, h, i, j, k, l

**Interchangeable:** (c, d)

```java
import java.io.File;
import java.io.IOException;
import java.util.Scanner;

public class MatchLogReader
{
    public static int countLines(String filename) throws IOException
    {
        Scanner scan = new Scanner(new File(filename));
        int count = 0;
        while (scan.hasNextLine())
        {
            scan.nextLine();
            count++;
        }
        scan.close();
        return count;
    }

    public static void main(String[] args) throws IOException
    {
        System.out.println(countLines("matchLog.txt"));
    }
}
```

**Why this order:** The method header (`a`) needs `throws IOException` since opening a file can fail, and its opening brace (`b`) follows immediately. The `Scanner` (`c`) and the `count` variable (`d`) neither one reads the other, so they can go in either order — declared `**Interchangeable:**`. `hasNextLine()` (`e`), not `hasNext()`, is what's being tested here: `hasNext()` looks for the next non-whitespace token and can silently miss a blank trailing line, undercounting; `hasNextLine()` counts every line, blank or not. Inside the loop (`f`/`i`), each pass reads one line (`g`) and bumps the counter (`h`) — two separate statements, kept as two separate fragments. Once the loop finishes, the scanner is closed (`j`) and the final count is returned (`k`) — closing and returning only make sense after every line has been read, and returning has to come after closing, not before. The method's closing brace (`l`) comes last. The surrounding class, imports, and `main` (which calls `countLines` and also declares `throws IOException`) are the given scaffold.

```java
import java.io.*;
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args) throws IOException
    {
        // Set-up: copy the input lines into a file, so the program has a file to read
        Scanner in = new Scanner(System.in);
        String alliance = in.nextLine();
        PrintWriter out = new PrintWriter("auto_config.csv");
        while (in.hasNextLine())
        {
            out.println(in.nextLine());
        }
        out.close();

        System.out.println(RouteLoader.fastestRoute("auto_config.csv", alliance));
    }
}

class RouteLoader
{
    public static String fastestRoute(String filename, String alliance) throws IOException
    {
        File configFile = new File(filename);
        Scanner scan = new Scanner(configFile);
        scan.nextLine();
        String bestName = "none";
        double bestTime = 0.0;
        while (scan.hasNextLine())
        {
            String[] fields = scan.nextLine().split(",");
            double time = Double.parseDouble(fields[1]);
            if (fields[2].equals(alliance) && (bestName.equals("none") || time < bestTime))
            {
                bestName = fields[0];
                bestTime = time;
            }
        }
        scan.close();
        return bestName;
    }
}
```

**Why:** Opening the file is the lesson's two-step: `new File(filename)` only holds a name, and
`new Scanner(configFile)` is what can fail, which is why the method header already says
`throws IOException`. One `scan.nextLine()` before the loop throws away the header; skipping that step
makes `Double.parseDouble("seconds")` crash with a `NumberFormatException` on the first line. Inside the
`while (scan.hasNextLine())` loop, `split(",")` gives `fields[0]` (name), `fields[1]` (time) and
`fields[2]` (alliance). Seeding the best route from the first *matching* route, rather than from a time
like `0.0`, is what keeps the answer right, and `<` rather than `<=` keeps the first of two equal times.
The alliance has to be compared with `.equals`, not `==`.
