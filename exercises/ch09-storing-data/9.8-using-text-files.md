# Using Text Files — Exercises

## Multiple Choice

**Question:** A CSV file's first line is `teamNumber,winCount` (column headers), followed by real data rows like `1622,14`. What happens if this code runs without skipping the header row first?

```java
while (scan.hasNext())
{
    String[] fields = scan.nextLine().split(",");
    int wins = Integer.parseInt(fields[1]);
    // ...
}
```

**Options:**

- A. Throws a `NumberFormatException` when it tries to parse `"winCount"` as an integer
- B. Silently treats the header as a valid row with 0 wins
- C. Automatically skips the header row, since Java recognizes column names
- D. Compiles fine but the loop never runs

**Answer:** A

**Why:** On the very first iteration, `fields[1]` is the literal text `"winCount"`, and `Integer.parseInt("winCount")` can't convert non-numeric text into an `int` — it throws a `NumberFormatException` at run time. This is exactly why the lesson calls out skipping the header row as a required step, not optional cleanup.

- B is wrong — Java doesn't guess a fallback value; trying to parse non-numeric text as an `int` fails loudly instead of quietly substituting `0`.
- C is wrong — Java has no built-in awareness of "column headers" in a CSV; it reads whatever text is on the first line just like any other line.
- D is wrong — the loop does run: `hasNext()` is `true` and the first `nextLine()` succeeds; the crash happens partway through processing that first line, not before the loop starts.

## Micro-Parsons

**Problem:** This method will live in a class alongside a `main` method that calls it with a filename. These lines, once correctly ordered, form the complete method that opens a file by name, counts how many lines it contains, and returns that count.

Reorder the fragments below into a working method:

- a. `    }`
- b. `    Scanner scan = new Scanner(new File(filename));`
- c. `public static int countLines(String filename) throws IOException`
- d. `        scan.nextLine(); count++;`
- e. `    int count = 0;`
- f. `}`
- g. `    while (scan.hasNext())`
- h. `    {`
- i. `    scan.close(); return count;`
- j. `{`

**Answer:** c, j, b, e, g, h, d, a, i, f

```java
import java.io.File;
import java.io.IOException;
import java.util.Scanner;

public class MatchLogReader
{
    public static int countLines(String filename) throws IOException
    {
        Scanner scan = new Scanner(new File(filename));
        int count = 0;
        while (scan.hasNext())
        {
            scan.nextLine(); count++;
        }
        scan.close(); return count;
    }

    public static void main(String[] args) throws IOException
    {
        System.out.println(countLines("matchLog.txt"));
    }
}
```

**Why this order:** The method header (`c`) needs `throws IOException` since opening a file can fail, and its opening brace (`j`) follows immediately. The `Scanner` (`b`) must exist before `hasNext()` (`g`) can be called on it, and `count` (`e`) must be declared before the loop can increment it. Inside the loop (`h`), each pass reads one line and bumps the counter (`d`) — both need to happen every iteration, so they're combined on one line. Once the loop finishes (its closing brace, `a`), the scanner is closed and the final count is returned (`i`) — closing and returning only make sense after every line has been read. The method's closing brace (`f`) comes last. The surrounding class, imports, and `main` (which calls `countLines` and also declares `throws IOException`) are the given scaffold.
