# Methods: How to Write Them — Exercises

## Multiple Choice

**Question:** A `Transmission` class has a private instance variable `private int currentGear;`. A teammate writes this method, intending it as a getter:

```java
public void getCurrentGear()
{
    System.out.println(currentGear);
}
```

Other code then tries `int gear = myTransmission.getCurrentGear();`, and it fails to compile. What's wrong with the method?

**Options:**

- A. It's `void`, so it doesn't return a value at all — a getter must be non-`void` and `return` the instance variable, not just print it
- B. It's missing the `private` keyword, so other classes can't call it
- C. `currentGear` needs to be `public` before any method can read it
- D. Getter methods must take one parameter — the value being returned

**Answer:** A

**Why:** A getter's whole job is to hand a value back to whoever called it, which requires a return type matching the field and a `return` statement. This method is `void` and only prints — it never hands anything back, so `int gear = myTransmission.getCurrentGear();` has nothing to assign to `gear`, and that's a compile error.

- B is wrong — the method is already declared `public`, exactly as a getter should be; that's not the problem here.
- C is wrong — getters exist precisely so an instance variable *can* stay `private` while still being readable from outside; making `currentGear` `public` would remove the need for this getter, not fix it.
- D is wrong — getters conventionally take zero parameters; adding one would make this a different kind of method entirely, not fix the missing return value.

## Micro-Parsons

**Problem:** This lesson emphasizes getters *and* setters as a pair, so scrambling only a getter would tell half the story — but a full getter+setter+`main` program runs well past a reasonable fragment count. Below is the outer scaffold of a complete program: the `Elevator` class declaration and braces, and a complete, already-written `main` that constructs an `Elevator`, raises it to a new height, and prints that height back out. Reorder the fragments below to fill in the class body: the field, then its getter, then its setter.

```java
public class Elevator
{
    // ⟵ reorder the fragments below into this spot: field, getter, setter

    public static void main(String[] args)
    {
        Elevator e = new Elevator();
        e.setHeightInches(24.0);
        System.out.println(e.getHeightInches());
    }
}
```

Reorder the fragments below:

- a. `    {`
- b. `    private double heightInches;`
- c. `        heightInches = newHeight;`
- d. `    public double getHeightInches()`
- e. `    }`
- f. `        return heightInches;`
- g. `    public void setHeightInches(double newHeight)`
- h. `    }`
- i. `    {`

**Answer:** b, d, a, f, h, g, i, c, e

**Interchangeable:** (a, i) (e, h)

```java
public class Elevator
{
    private double heightInches;

    public double getHeightInches()
    {
        return heightInches;
    }

    public void setHeightInches(double newHeight)
    {
        heightInches = newHeight;
    }

    public static void main(String[] args)
    {
        Elevator e = new Elevator();
        e.setHeightInches(24.0);
        System.out.println(e.getHeightInches());
    }
}
```

**Why this order:** With the class declaration, its braces, and the complete, already-written `main` held fixed as scaffold, only the field, getter, and setter are left to place. The field (`b`) is declared first, then the getter (`d`, `a`, `f`, `h` — signature, opening brace, `return` statement, closing brace), followed by the setter (`g`, `i`, `c`, `e`) in that same signature/brace/statement/brace shape, matching this lesson's getter-then-setter presentation — the getter and setter are exercised together in `main`, rather than just one in isolation. Note that `a` and `i` (both a bare four-space `{`) are textually identical, as are `e` and `h` (both a bare four-space `}`) — one pair belongs to the getter and the other to the setter, so it doesn't matter which physical copy lands in which slot as long as each method gets one opening and one closing brace.
