# Class (static) Variables & Methods — Exercises

## Multiple Choice

**Question:** A `Robot` class has `public static int totalRobots = 0;`, incremented inside its constructor. This code runs:

```java
Robot r1 = new Robot();
Robot r2 = new Robot();
```

What does `r1.totalRobots` equal afterward?

**Options:**

- A. `2` — there's only one shared copy of `totalRobots`, and every constructor call increments that same value, regardless of which object later reads it
- B. `1` — `r1` only counts the constructor call that built `r1` itself
- C. `0` — a `static` variable doesn't update until a getter reads it
- D. It depends on which of `r1` or `r2` was constructed more recently

**Answer:** A

**Why:** `static` means one shared copy belongs to the class itself, not a separate copy per object. Both constructor calls incremented that same `totalRobots`, so after both objects exist, any `Robot` — or the class itself — sees `2`.

- B is wrong — it treats `totalRobots` as if each object kept its own separate count, which is exactly what `static` means it does *not* do.
- C is wrong — a `static` variable updates the instant it's assigned or incremented, just like any other variable; there's no separate "activation" step tied to reading it later.
- D is wrong — since there's only one shared value, the order `r1` and `r2` were built in makes no difference to what either one reads.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program whose `Sensor` class has a `static` method that prints one specific sensor's reading, passed in as a parameter — since a `static` method has no object of its own to read `reading` from — then builds one `Sensor` and prints its reading.

Reorder the fragments below into a working program:

- a. `        System.out.println(s.reading);`
- b. `public class Sensor`
- c. `    }`
- d. `    private double reading;`
- e. `    public static void printReading(Sensor s)`
- f. `{`
- g. `    public static int sensorCount = 0;`
- h. `    {`
- i. `    public static void main(String[] args)`
- j. `    {`
- k. `        printReading(new Sensor());`
- l. *(two lines, merged into one fragment — nothing valid can ever come between the closing brace of `main` and the closing brace of the class)*
  ```java
      }
  }
  ```

**Answer:** b, f, g, d, e, h, a, c, i, j, k, l

```java
public class Sensor
{
    public static int sensorCount = 0;
    private double reading;

    public static void printReading(Sensor s)
    {
        System.out.println(s.reading);
    }

    public static void main(String[] args)
    {
        printReading(new Sensor());
    }
}
```

**Why this order:** The class declaration (`b`) and its opening brace (`f`) come first, followed by the two variable declarations (`g`, `d`). The static method's signature (`e`) and its own opening brace (`h`) come next. Inside, the print statement (`a`) reads `s.reading` — the specific `Sensor` object passed in as a parameter — because a `static` method has no object of its own to read an instance variable from directly. The method's body then closes (`c`), and `main` (`i`) is declared next with its own opening brace (`j`); inside it, the single statement (`k`) builds a new `Sensor` and passes it straight to `printReading`, calling the static method the same way any other code would — without ever making a `new Sensor()` to hold the method itself. Fragment `l` merges the program's last two closing braces into a single piece: `main`'s body closes and the class's body closes immediately after, with nothing else that could ever land between two closing braces at the end of a file. Note that `h` and `j` (both a bare four-space `{`) are textually identical — interchangeable copies at the same nesting depth, one opens `printReading` and one opens `main`, so it doesn't matter which physical copy lands in which slot.
