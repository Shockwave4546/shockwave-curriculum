# Class (static) Variables & Methods — Exercises

## Multiple Choice

**Question:** A `Robot` class has `public static int totalRobots = 0;`, incremented inside its constructor. This code runs:

```java
Robot r1 = new Robot();
Robot r2 = new Robot();
```

What does `r1.totalRobots` equal afterward?

**Options:**

- A. `2` — there's only one shared copy of `totalRobots`, and every constructor call increments that same value, regardless of which object later reads it
- B. `1` — `r1` only counts the constructor call that built `r1` itself
- C. `0` — a `static` variable doesn't update until a getter reads it
- D. It depends on which of `r1` or `r2` was constructed more recently

**Answer:** A

**Why:** `static` means one shared copy belongs to the class itself, not a separate copy per object. Both constructor calls incremented that same `totalRobots`, so after both objects exist, any `Robot` — or the class itself — sees `2`.

- B is wrong — it treats `totalRobots` as if each object kept its own separate count, which is exactly what `static` means it does *not* do. (`r1.totalRobots` is really just another way of reading `Robot.totalRobots` — the class name is the clearer, conventional way to write it, but the object-access syntax reads the exact same one shared value.)
- C is wrong — a `static` variable updates the instant it's assigned or incremented, just like any other variable; there's no separate "activation" step tied to reading it later.
- D is wrong — since there's only one shared value, the order `r1` and `r2` were built in makes no difference to what either one reads.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program whose `Sensor` class has a `static` method that prints one specific sensor's reading, passed in as a parameter — since a `static` method has no object of its own to read `reading` from — then builds one `Sensor` and prints its reading.

Reorder the fragments below into a working program:

- a. `        System.out.println(s.reading);`
- b. `public class Sensor`
- c. `    }`
- d. `    private double reading;`
- e. `    public static void printReading(Sensor s)`
- f. `{`
- g. `    {`
- h. `    public static void main(String[] args)`
- i. `    {`
- j. `        printReading(new Sensor());`
- k. *(two lines, merged into one fragment — nothing valid can ever come between the closing brace of `main` and the closing brace of the class)*
  ```java
      }
  }
  ```

**Answer:** b, f, d, e, g, a, c, h, i, j, k

**Interchangeable:** (g, i)

```java
public class Sensor
{
    private double reading;

    public static void printReading(Sensor s)
    {
        System.out.println(s.reading);
    }

    public static void main(String[] args)
    {
        printReading(new Sensor());
    }
}
```

**Why this order:** The class declaration (`b`) and its opening brace (`f`) come first, followed by the instance variable (`d`). The static method's signature (`e`) and its own opening brace (`g`) come next. Inside, the print statement (`a`) reads `s.reading` — the specific `Sensor` object passed in as a parameter — because a `static` method has no object of its own to read an instance variable from directly. The method's body then closes (`c`), and `main` (`h`) is declared next with its own opening brace (`i`); inside it, the single statement (`j`) builds a new `Sensor` and passes it straight to `printReading`, calling the static method exactly the way any other code outside `Sensor` would have to — through the class name or another object, never through a `Sensor` made just to hold the method, since `printReading` doesn't need one. Fragment `k` merges the program's last two closing braces into a single piece: `main`'s body closes and the class's body closes immediately after, with nothing else that could ever land between two closing braces at the end of a file. Note that `g` and `i` (both a bare four-space `{`) are textually identical — interchangeable copies at the same nesting depth, one opens `printReading` and one opens `main`, so it doesn't matter which physical copy lands in which slot.

## Coding

**Mode:** full-program

**Problem:** Every `Subsystem` is built with the current (in amps) it just drew. Write the class `Subsystem` so that
**the class itself** keeps track of two shared facts across every object ever created:

- how many `Subsystem` objects have been created, and
- the highest current any of them was built with (`0.0` if none was created).

Use two `private static` variables that start at `0` and `0.0`, update them in the constructor, and
expose them through the `public static` getters `getInstanceCount()` and `getMaxObservedCurrent()`. The fixed
`main` creates one subsystem per input value and then reads both numbers through the class name, never
through an object.

For example, the currents `12.5 30.0 8.0` print `subsystems: 3` and `max current: 30.0`. With no
subsystems at all, it prints `subsystems: 0` and `max current: 0.0`.

**Solution:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        int count = in.nextInt();
        for (int i = 0; i < count; i++)
        {
            double current = in.nextDouble();
            Subsystem subsystem = new Subsystem(current);
        }
        System.out.println("subsystems: " + Subsystem.getInstanceCount());
        System.out.println("max current: " + Subsystem.getMaxObservedCurrent());
    }
}

class Subsystem
{
    private static int instanceCount = 0;
    private static double maxObservedCurrent = 0.0;

    public Subsystem(double current)
    {
        instanceCount++;
        if (current > maxObservedCurrent)
        {
            maxObservedCurrent = current;
        }
    }

    public static int getInstanceCount()
    {
        return instanceCount;
    }

    public static double getMaxObservedCurrent()
    {
        return maxObservedCurrent;
    }
}
```

**Why:** A `static` variable has exactly one copy for the whole class, which is why the constructor of every new
object can add to the same count and compare against the same maximum. If the two variables were ordinary
instance variables, each object would have its own: the count would always print `1` and the maximum would
be whatever the last object was built with. The `>` comparison keeps the highest value even when it comes
first (`40.0 25.0 10.0 3.5` still ends at `40.0`) and a repeated value changes nothing. The getters are
`static` so `main` can call them as `Subsystem.getInstanceCount()` with zero objects in hand, which is why
the no-subsystem case works.
