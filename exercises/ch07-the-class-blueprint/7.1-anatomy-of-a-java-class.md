# Anatomy of a Java Class — Exercises

## Multiple Choice

**Question:** A `Climber` class stores its extension as `public double currentHeightInches;` — a public instance variable with no other methods. Another class in the program writes `myClimber.currentHeightInches = -12.0;` directly, and it compiles and runs fine. What is the most direct consequence of making `currentHeightInches` `public` instead of `private`?

**Options:**

- A. Any other class can set it to any value at all, including a physically impossible one like `-12.0`, since there's no method in `Climber` enforcing what counts as a valid height
- B. The program won't compile — instance variables are required to be `private` in Java
- C. Nothing changes in practice; `public` and `private` only affect how the code looks, not what other classes can do
- D. It can now only be changed from inside `Climber`'s own constructor, never afterward

**Answer:** A

**Why:** Encapsulation means the class's own methods are the only gatekeepers for how its data changes. Making `currentHeightInches` `public` removes that gate entirely — any other class can assign it anything, including a value like `-12.0` that no real climber height could be, because there's no `Climber` method standing between the outside code and the raw variable.

- B is wrong — Java doesn't require instance variables to be `private`; `public` compiles just fine, it's simply poor design that breaks encapsulation.
- C is wrong — `public` vs. `private` controls exactly what other classes can do. A `private` version of this same line would fail to compile from outside `Climber`; the `public` version let it through with no check at all.
- D is wrong — `public` makes a variable *more* freely changeable from anywhere, not restricted to the constructor.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program whose `Climber` class has a constructor that sets a starting height of `0.0` inches and marks it as not locked, then builds one `Climber` and prints its starting height.

Reorder the fragments below into a working program:

- a. `        currentHeightInches = 0.0;`
- b. `public class Climber`
- c. `    }`
- d. `{`
- e. `    private double currentHeightInches;`
- f. `    public Climber()`
- g. `    private boolean isLocked;`
- h. `        isLocked = false;`
- i. `    {`
- j. `    public static void main(String[] args)`
- k. `        System.out.println("Starting height: " + new Climber().currentHeightInches);`
- l. `    {`
- m. *(two lines, merged into one fragment — nothing valid can ever come between the closing brace of `main` and the closing brace of the class)*
  ```java
      }
  }
  ```

**Answer:** b, d, e, g, f, i, a, h, c, j, l, k, m

**Interchangeable:** (i, l) (e, g) (a, h)

```java
public class Climber
{
    private double currentHeightInches;
    private boolean isLocked;

    public Climber()
    {
        currentHeightInches = 0.0;
        isLocked = false;
    }

    public static void main(String[] args)
    {
        System.out.println("Starting height: " + new Climber().currentHeightInches);
    }
}
```

**Why this order:** The class declaration (`b`) and its opening brace (`d`) come first. The two instance variables (`e`, `g`) are declared before any constructor or method, conventionally matching the three-part order from this lesson — neither declaration reads the other, so they could swap too. The constructor's signature (`f`) and its own opening brace (`i`) come next, followed by the two assignment statements inside it (`a`, `h`) — conventionally in the same order the fields were declared, though neither assignment depends on the other, so they could swap as well. The constructor's body then closes (`c`), and `main` (`j`) is declared next with its own opening brace (`l`); inside it, the `println` (`k`) builds a new `Climber` and reads its starting height straight back — legal even though the field is `private`, since `main` lives inside `Climber` itself, and private access is scoped to the whole class, not just one object. Fragment `m` merges the program's last two closing braces into a single piece: `main`'s body closes and the class's body closes immediately after, with nothing else that could ever land between two closing braces at the end of a file. Note that `i` and `l` (both a bare four-space `{`) are textually identical — interchangeable copies at the same nesting depth, one opens the constructor and one opens `main`, so it doesn't matter which physical copy lands in which slot.

## Coding

**Mode:** full-program

**Problem:** The lesson's `Intake` class has three parts: instance variables, a constructor, and methods. Write the
class `Intake` so that each new intake starts **retracted and stopped** (not deployed, speed `0.0`).
It needs three methods: `deploy()` marks it as deployed, `spin(double speed)` sets its motor speed, and
`describe()` returns a `String` in the form `deployed=true speed=0.5` (the two values, separated by one
space). Keep the instance variables `private`.

The fixed `main` builds two separate intakes, `a` and `b`, prints both, deploys and spins them, and prints
both again. Each object keeps its **own** copy of the data, so spinning `b` must not change `a`.

For example, with the input `0.5 0.0 true` (speed for A, speed for B, whether to deploy A), the last two
lines print `A: deployed=true speed=0.5` and `B: deployed=false speed=0.0`.

**Starter:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        double speedA = in.nextDouble();
        double speedB = in.nextDouble();
        boolean deployA = in.nextBoolean();

        Intake a = new Intake();
        Intake b = new Intake();
        System.out.println("A: " + a.describe());
        System.out.println("B: " + b.describe());
        if (deployA)
        {
            a.deploy();
        }
        a.spin(speedA);
        b.spin(speedB);
        System.out.println("A: " + a.describe());
        System.out.println("B: " + b.describe());
    }
}

class Intake
{
    // TODO: instance variables (private), a constructor, and the methods below

    // deploy(): marks the intake as deployed
    // spin(double speed): sets the current motor speed
    // describe(): returns a String like "deployed=true speed=0.5"
}
```

**Solution:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        double speedA = in.nextDouble();
        double speedB = in.nextDouble();
        boolean deployA = in.nextBoolean();

        Intake a = new Intake();
        Intake b = new Intake();
        System.out.println("A: " + a.describe());
        System.out.println("B: " + b.describe());
        if (deployA)
        {
            a.deploy();
        }
        a.spin(speedA);
        b.spin(speedB);
        System.out.println("A: " + a.describe());
        System.out.println("B: " + b.describe());
    }
}

class Intake
{
    private boolean isDeployed;
    private double currentSpeed;

    public Intake()
    {
        isDeployed = false;
        currentSpeed = 0.0;
    }

    public void deploy()
    {
        isDeployed = true;
    }

    public void spin(double speed)
    {
        currentSpeed = speed;
    }

    public String describe()
    {
        return "deployed=" + isDeployed + " speed=" + currentSpeed;
    }
}
```

**Why:** The instance variables are what make each `Intake` object independent: `a` and `b` each own a
`currentSpeed`, so `b.spin(...)` never touches `a`. The constructor sets the starting state, which is
what the first two printed lines check. Making either variable `static` is the classic slip: there would
be one shared copy, so `A` and `B` would always print the same speed. `describe()` joins the two values
with `+`, and a `boolean` or `double` converts to text automatically. Keeping the variables `private` is
the lesson's encapsulation rule; the checker can't enforce it, but the only way `main` can read the
values is through `describe()`.
