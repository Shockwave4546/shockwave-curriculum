## Multiple Choice

**Question:** A teammate writes `System.out.println("Ready")` and forgets the semicolon at the end. When does this get caught?

**Options:**

- A. At compile time, before the program ever runs
- B. At run time, right after `"Ready"` is printed
- C. It isn't caught — Java assumes a semicolon was intended
- D. Only if the program is compiled a second time

**Answer:** A

**Why:** A missing `;` is a syntax error — the compiler checks the code's structure before any of it runs, and stops there if something's wrong. Nothing prints at all, because the program never starts running.

- B is wrong because it describes a run-time error — something that happens *while* the program runs, like the `main` example never reaching that far here.
- C is wrong — Java never guesses at missing syntax; it requires every statement to end in `;`.
- D is wrong — compiling doesn't get "another chance" the second time; the same error would be caught again immediately.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that prints a team's name on one line.

Reorder the fragments below into a working program:

- a. `        System.out.println("Shockwave 1622");`
- b. `public class TeamMotto`
- c. `    }`
- d. `{`
- e. `    public static void main(String[] args)`
- f. `}`
- g. `    {`

**Answer:** b, d, e, g, a, c, f

```java
public class TeamMotto
{
    public static void main(String[] args)
    {
        System.out.println("Shockwave 1622");
    }
}
```

**Why this order:** The class line (`b`) has to come first, and its opening brace (`d`) right after it — every class needs a name before its body. `main` (`e`) is the method that runs first, so it's declared next, followed by its own opening brace (`g`). The `println` statement (`a`) lives inside `main`'s braces. Then the braces close in the reverse order they opened: `main`'s body first (`c`), then the class's body (`f`).
