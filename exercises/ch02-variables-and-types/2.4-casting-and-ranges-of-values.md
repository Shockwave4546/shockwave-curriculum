## Problem: "Why Is My Average Always 0?"

A teammate is trying to compute the average vision-pipeline latency from 4 samples, but no matter what the 4 numbers are, this always prints `0`. Find the bug and fix it.

```java
public class LatencyAverage
{
    public static void main(String[] args)
    {
        int sample1 = 8;
        int sample2 = 12;
        int sample3 = 9;
        int sample4 = 3;

        int total = sample1 + sample2 + sample3 + sample4; // 32
        int count = 4;

        double average = total / count; // always prints 0 — why?
        System.out.println("Average latency: " + average + " ms");
    }
}
```

## Hints

- `average` is correctly declared as a `double` — so why is it still wrong? Look at the *right-hand side* of that assignment, not the variable itself.
- What are the types of `total` and `count`? What type does `total / count` evaluate to, before it's ever assigned to anything?
- Declaring the variable that *receives* a division as `double` does not change how the division itself is performed.

## Solution

```java
public class LatencyAverage
{
    public static void main(String[] args)
    {
        int sample1 = 8;
        int sample2 = 12;
        int sample3 = 9;
        int sample4 = 3;

        int total = sample1 + sample2 + sample3 + sample4; // 32
        int count = 4;

        double average = (double) total / count; // cast BEFORE dividing: 8.0
        System.out.println("Average latency: " + average + " ms");
    }
}
```

The bug: `total / count` is `int / int`, which truncates to `8` *before* that result is ever assigned into the `double average` — declaring `average` as a `double` doesn't retroactively change how the division happened. The fix casts `total` to `double` first, which — per lesson 2.4's "contagious double" rule — forces the whole division to be computed as a `double`, giving the real result `8.0` (which happens to be a whole number here, but try it with `total = 31` to see the difference: `31/4` truncates to `7`, while `(double) 31/4` correctly gives `7.75`).
