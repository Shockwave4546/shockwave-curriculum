## Multiple Choice

**Question:** A teammate declares `int armAngleDegrees = 47.5;` to store the arm's current angle. What happens when this code is compiled?

**Options:**

- A. It compiles and stores `47.5` in `armAngleDegrees`
- B. It compiles but stores `47` in `armAngleDegrees`, dropping the decimal
- C. It fails to compile, because `47.5` is a `double` literal and can't be stored in an `int` variable
- D. It compiles and stores `48`, rounding to the nearest whole number

**Answer:** C

**Why:** The type has to match the value being assigned. `47.5` has a decimal point, which makes it a `double` literal — and a `double` value doesn't fit in an `int` box, so the compiler rejects the line before the program ever runs.

- A is wrong because an `int` variable can never hold a decimal value; nothing gets stored, since the code doesn't compile.
- B is wrong because that's what happens if you deliberately cast a `double` down to an `int` (`(int) 47.5`) — not what happens from a plain mismatched declaration, which doesn't compile at all.
- D is wrong because Java never rounds automatically; nothing here rounds on a plain assignment.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that reports a winch's cable length and whether it's currently locked.

Reorder the fragments below into a working program:

- a. `        cableLengthInches = 18;`
- b. `public class WinchStatus`
- c. `    }`
- d. `}`
- e. `{`
- f. `    public static void main(String[] args)`
- g. `    {`
- h. `        int cableLengthInches;`
- i. `        boolean isLocked = true;`
- j. `        System.out.println("Cable length: " + cableLengthInches + ", locked: " + isLocked);`

**Answer:** b, e, f, g, h, a, i, j, c, d

**Interchangeable:** (a, i)

```java
public class WinchStatus
{
    public static void main(String[] args)
    {
        int cableLengthInches;
        cableLengthInches = 18;
        boolean isLocked = true;

        System.out.println("Cable length: " + cableLengthInches + ", locked: " + isLocked);
    }
}
```

**Why this order:** The class line (`b`) and its opening brace (`e`) come first, then `main` (`f`) and its own opening brace (`g`) — every program starts from this same skeleton. `cableLengthInches` is declared on its own (`h`) with no value yet, so it has to be assigned (`a`) on a separate, later line before anything can use it — declaring and assigning are two separate steps here, and the assignment can't come first. `isLocked` (`i`) is declared and assigned together, and since it doesn't depend on `cableLengthInches` at all, it could technically sit anywhere before the `println` — it's placed where it is simply to match the order the variables are described in the problem. The `println` (`j`) has to come after every variable it reads already has a value. Then the braces close in the reverse order they opened: `main`'s body first (`c`), then the class's body (`d`).
