# Compound Assignment Operators — Exercises

## Multiple Choice

**Question:** After this code runs, what is the final value of `intakeSpeed`?

```java
double intakeSpeed = 0.80;
intakeSpeed -= 0.15;
intakeSpeed /= 2;
```

**Options:**

- A. 0.325
- B. 0.65
- C. 0.40
- D. 1.30

**Answer:** A

**Why:** Each compound operator acts on whatever value `intakeSpeed` currently holds, in order. `intakeSpeed -= 0.15` updates it from `0.80` to `0.65`. `intakeSpeed /= 2` then divides the *current* value, `0.65`, by `2`, landing on `0.325`.

- B is wrong because that's the value after only the first line — it stops before `/= 2` runs.
- C is wrong because that's what you'd get from dividing the *original* `0.80` by `2`, skipping the `-= 0.15` step entirely. Compound operators always use the value as it stands at that moment, not the value from when the variable was first declared.
- D is wrong because that's what `intakeSpeed *= 2` would produce instead of `intakeSpeed /= 2` — multiplying instead of dividing.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a program that extends a climber by a fixed step, then clamps it so it never exceeds a maximum extension, then prints the result. Declare `climbExtension` first, then `maxExtension`, in that order.

Reorder the fragments below into a working program:

- a. `        climbExtension += 0.20;`
- b. `public class ClimbExtension`
- c.
  ```java
      }
  }
  ```
- d. `        double climbExtension = 0.65;`
- e. `{`
- f. `    public static void main(String[] args)`
- g. `        double maxExtension = 0.75;`
- h. `    {`
- i.
  ```java
          if (climbExtension > maxExtension) {
              climbExtension = maxExtension;
          }
  ```
- j. `        System.out.println("Climb extension: " + climbExtension);`

**Answer:** b, e, f, h, d, g, a, i, j, c

```java
public class ClimbExtension
{
    public static void main(String[] args)
    {
        double climbExtension = 0.65;
        double maxExtension = 0.75;

        climbExtension += 0.20;
        if (climbExtension > maxExtension) {
            climbExtension = maxExtension;
        }

        System.out.println("Climb extension: " + climbExtension);
    }
}
```

**Why this order:** `climbExtension` (`d`) and `maxExtension` (`g`) both have to be declared before anything uses them. Nothing in the code itself forces `d` before `g` — `a` only needs `d`, and `i` needs both — so the Problem text pins that order instead, matching how the two variables are introduced. `climbExtension += 0.20` (`a`) has to run before the clamp check (`i`), since the clamp is only meaningful *after* the step has been applied — `0.65 + 0.20` is `0.85`, which is past the `0.75` ceiling, so the clamp's body actually fires and pulls `climbExtension` back down to `0.75`. (If `i` ran before `a` instead, the clamp would check the *un-incremented* `0.65`, never fire, and the final answer would be `0.85`, not `0.75` — so `i` has to come after `a` too.) The `println` (`j`) comes last so it reports the clamped final value. The class/`main` skeleton opens (`b`, `e`, `f`, `h`) and closes (`c`, bundling both closing braces together since nothing can ever come between them).
