## Multiple Choice

**Question:** A drive team wants to swap which of two motor ports is called "primary." After this code runs, what are the final values of `portA` and `portB`?

```java
int portA = 3;
int portB = 7;
portA = portB;
portB = portA;
```

**Options:**

- A. portA = 7, portB = 3
- B. portA = 7, portB = 7
- C. portA = 3, portB = 3
- D. portA = 3, portB = 7

**Answer:** B

**Why:** `portA = portB` copies `portB`'s value (`7`) into `portA`, overwriting `portA`'s original `3` — which is now gone for good. `portB = portA` then copies `portA`'s *current* value, which is already `7`, back into `portB`. Nothing ever saved the original `3` anywhere, so both variables end up holding `7`.

- A is wrong because that's what a genuine swap would produce, but this code doesn't achieve one — the original `3` is lost the moment `portA = portB` runs, before it can ever reach `portB`.
- C is wrong because `portA` does change; it's assigned `portB`'s value on the very first line.
- D is wrong because that would only be true if neither line actually executed — both assignments run, and both change a variable's value.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a program that stores an autonomous start delay, saves a snapshot of it before changing it, and then prints both the updated delay and the untouched snapshot.

Reorder the fragments below into a working program:

- a. `        startDelay = startDelay + 3;`
- b. `public class DelayCheck`
- c. `    }`
- d. `}`
- e. `{`
- f. `    public static void main(String[] args)`
- g. `    {`
- h. `        int savedDelay = startDelay;`
- i. `        int startDelay = 2;`
- j. `        System.out.println("Start delay: " + startDelay + ", saved: " + savedDelay);`

**Answer:** b, e, f, g, i, h, a, j, c, d

```java
public class DelayCheck
{
    public static void main(String[] args)
    {
        int startDelay = 2;
        int savedDelay = startDelay;
        startDelay = startDelay + 3;

        System.out.println("Start delay: " + startDelay + ", saved: " + savedDelay);
    }
}
```

**Why this order:** `startDelay` (`i`) must be declared and given its starting value before anything can read it. `savedDelay = startDelay` (`h`) has to come right after, *while `startDelay` still holds its original value* — if this line ran after the update instead, `savedDelay` would capture the already-changed value, and there'd be no snapshot left of the original. Only once the copy is safely taken does `startDelay = startDelay + 3` (`a`) update `startDelay` using its own old value. The `println` (`j`) comes last so it reports the final state of both variables. The class/`main` skeleton opens (`b`, `e`, `f`, `g`) around all of it, and the braces close in the reverse order they opened: `main`'s body first (`c`), then the class's body (`d`).
