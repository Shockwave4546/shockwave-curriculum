# Strings — Exercises

## Multiple Choice

**Question:** What does this line print?

```java
System.out.println("Cycle count: " + 2 + 3);
```

**Options:**

- A. `Cycle count: 23`
- B. `Cycle count: 5`
- C. `Cycle count: 2 3`
- D. It doesn't compile — you can't add a `String` and an `int`

**Answer:** A

**Why:** `+` is evaluated left to right. `"Cycle count: " + 2` produces the `String` `"Cycle count: 2"` first, and *then* `+ 3` appends `"3"` to the end of that string — giving `"Cycle count: 23"`, not the sum of the numbers.

- B is wrong — that's what you'd get from `"Cycle count: " + (2 + 3)`, where parentheses force the addition to happen before either `+` touches the string.
- C is wrong — string concatenation never inserts a space on its own; only characters actually written into the string appear in the output.
- D is wrong — Java automatically converts a non-string operand to text whenever `+` is used with a `String`, so this compiles and runs fine.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that prints just the first letter of an alliance color.

Reorder the fragments below into a working program:

- a. `        System.out.println("Tag: " + tag);`
- b. `    public static void main(String[] args)`
- c. `        String tag = alliance.substring(0, 1);`
- d. `{`
- e. `public class AllianceTag`
- f. `}`
- g. `    {`
- h. `        String alliance = "Blue";`
- i. `    }`

**Answer:** e, d, b, g, h, c, a, i, f

```java
public class AllianceTag
{
    public static void main(String[] args)
    {
        String alliance = "Blue";
        String tag = alliance.substring(0, 1);
        System.out.println("Tag: " + tag);
    }
}
```

**Why this order:** The class header (`e`) and its opening brace (`d`) come first, then `main` (`b`) and its own opening brace (`g`). Inside `main`, `alliance` (`h`) has to be declared before `tag` (`c`) can call `.substring()` on it, and `tag` has to exist before the `println` (`a`) that reads it. The braces close in reverse order of how they opened: `main`'s body closes (`i`) first, then the class's body closes (`f`).

## Coding

**Mode:** harness

**Problem:** Autonomous routines are named like `"BlueAlliance-Left"`. Two names belong to the same **family** when their
first 4 characters match, ignoring upper/lowercase. Write `sameFamily`, which returns `true` if the two
names are in the same family and `false` otherwise. Every name has at least 4 characters.

Examples:

- `sameFamily("BlueAlliance-Left", "BlueAlliance-Right")` returns `true`
- `sameFamily("BlueAlliance-Left", "RedAlliance-Left")` returns `false`
- `sameFamily("BLUE-Safe", "blue-Fast")` returns `true`

**Signature:** `public static boolean sameFamily(String a, String b)`

**Starter:**

```java
public class Solution
{
    public static boolean sameFamily(String a, String b)
    {
        // TODO: compare the first 4 characters of each name, ignoring case
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `"BlueAlliance-Left", "BlueAlliance-Right"` | `true` |
| yes | `"BlueAlliance-Left", "RedAlliance-Left"` | `false` |
| yes | `"BLUE-Safe", "blue-Fast"` | `true` |
| no | `"Blue1", "Blue2"` | `true` |
| no | `"Redx-Left", "Redy-Left"` | `false` |
| no | `"Auto", "Auto"` | `true` |
| no | `"Left-Auto", "Lift-Auto"` | `false` |
| no | `new String("Blue-A"), new String("Blue-B")` | `true` |

**Solution:**

```java
public class Solution
{
    public static boolean sameFamily(String a, String b)
    {
        String firstA = a.substring(0, 4);
        String firstB = b.substring(0, 4);
        return firstA.equalsIgnoreCase(firstB);
    }
}
```

**Why:** `substring(0, 4)` gives the first 4 characters (indices 0-3), because the `to` index is exclusive. Using
`substring(0, 3)` is the classic off-by-one and wrongly makes `"Redx"` and `"Redy"` match. The two substrings are
new `String` objects, so `==` would compare the objects, not the text, and always say `false`. Use
`equalsIgnoreCase` (or `.equals()` after lowercasing) to compare the characters.
