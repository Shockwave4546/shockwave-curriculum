## Multiple Choice

**Question:** A find-and-replace loop is meant to replace every `"0"` in a sensor code with `"00"` (doubling each zero):

```java
while (code.indexOf("0") >= 0)
{
    int i = code.indexOf("0");
    String firstPart = code.substring(0, i);
    String lastPart = code.substring(i + 1);
    code = firstPart + "00" + lastPart;
}
```

What happens when this runs on a code that contains at least one `"0"`?

**Options:**

- A. It loops forever — the replacement text `"00"` still contains a `"0"`, so `indexOf("0")` keeps finding one
- B. It replaces every zero with `"00"` once each, then stops, because `indexOf` only searches the original text
- C. It throws an `IndexOutOfBoundsException` once all the zeros are gone
- D. It replaces only the first zero and leaves the rest of the string unchanged

**Answer:** A

**Why:** Each pass searches `code`'s *current* value, which was just reassigned at the end of the previous pass. Since the replacement text (`"00"`) still contains the character being searched for, `indexOf("0")` finds a match again on the very next pass — forever. A find-and-replace loop only terminates when each pass genuinely reduces the number of matches left to find.

- B is wrong — `indexOf` always searches whatever `code` currently holds, not the original string; it has no memory of what's already been replaced.
- C is wrong — nothing in this loop reads past the end of the string; it just never satisfies its exit condition, so it never gets the chance to throw.
- D is wrong — the loop keeps running (and keeps matching) instead of stopping after a single replacement.

## Micro-Parsons

**Problem:** A limit switch's status is packed into a string of `1`s and `0`s, e.g. `"10110"`, where `1` means the switch is triggered. The class and `main` method below are already set up — reorder only the fragments that go inside `main` so the program counts and prints how many switches are triggered.

```java
public class SwitchStatus
{
    public static void main(String[] args)
    {
        // fragments go here
    }
}
```

Reorder the fragments below:

- a. `            }`
- b. `        String status = "10110";`
- c. `                triggeredCount++;`
- d. `        for (int i = 0; i < status.length(); i++)`
- e. `        }`
- f. `            if (status.substring(i, i + 1).equals("1"))`
- g. `        {`
- h. `        System.out.println("Triggered: " + triggeredCount);`
- i. `            {`
- j. `        int triggeredCount = 0;`

**Answer:** b, j, d, g, f, i, c, a, e, h

```java
public class SwitchStatus
{
    public static void main(String[] args)
    {
        String status = "10110";
        int triggeredCount = 0;
        for (int i = 0; i < status.length(); i++)
        {
            if (status.substring(i, i + 1).equals("1"))
            {
                triggeredCount++;
            }
        }
        System.out.println("Triggered: " + triggeredCount);
    }
}
```

**Why this order:** `status` (`b`) and `triggeredCount` (`j`) are declared before the loop — `triggeredCount` needs to start at `0` before anything can be added to it, and `status` needs to exist before the loop calls `.length()` on it. The `for` header (`d`) and its opening brace (`g`) start the scan; inside it, the `if` header (`f`) and its opening brace (`i`) test one character at a time, with `triggeredCount++` (`c`) inside the `if`'s own braces. The `if` closes (`a`) before the `for` closes (`e`) — braces have to close from the inside out. Only after the loop finishes does `println` (`h`) run, since it needs the final count, not a partial one.
