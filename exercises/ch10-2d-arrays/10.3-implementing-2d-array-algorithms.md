# Implementing 2D Array Algorithms — Exercises

## Multiple Choice

**Question:** Game pieces scored are stored with one row per match and one column per alliance robot:

```java
int[][] piecesScored = { {3, 5, 2}, {4, 1, 6} };
```

What does `mystery(piecesScored, 1)` return?

```java
public static int mystery(int[][] a, int k)
{
    int total = 0;
    for (int row = 0; row < a.length; row++)
    {
        total = total + a[row][k];
    }
    return total;
}
```

**Options:**

- A. `6`
- B. `11`
- C. `7`
- D. It throws an `ArrayIndexOutOfBoundsException`

**Answer:** A

**Why:** `k` is used as the *column* index while `row` changes, so this sums column `1`: robot 2's pieces across both matches, `5 + 1 = 6`. Fixing the column and looping the rows sums a column, not a row.

- B is wrong — `11` is the sum of *row* `1` (`4 + 1 + 6`), the second match. That would need the row fixed and the column looping, which is the classic row-vs-column mix-up.
- C is wrong — `7` is the sum of column `0` (`3 + 4`). Column indices start at `0`, so `k = 1` is the second column, not the first.
- D is wrong — `row` stays below `a.length` (2), and column `1` exists in every row, so no index is ever out of bounds.

## Micro-Parsons

**Problem:** Given this class, the header and braces of a `getFastestOnDay` method, and a `main` method that calls it, reorder the fragments below into the method body. The 2D array holds battery-swap times in seconds, one row per pit crew member and one column per practice day. The method should return the fastest (smallest) time on the given day.

```java
public class BatterySwapTimes
{
    public static int getFastestOnDay(int[][] a, int day)
    {
        // fragments go here
    }

    public static void main(String[] args)
    {
        int[][] swapTimes = { {42, 38, 35}, {40, 41, 33}, {45, 36, 37} };
        System.out.println(getFastestOnDay(swapTimes, 1));
    }
}
```

Reorder the fragments below to complete it:

- a. `            {`
- b. `        return fastest;`
- c. `        for (int row = 0; row < a.length; row++)`
- d. `                fastest = a[row][day];`
- e. `        }`
- f. `        int fastest = a[0][day];`
- g. `            if (a[row][day] < fastest)`
- h. `        {`
- i. `            }`

**Answer:** f, c, h, g, a, d, i, e, b

```java
public class BatterySwapTimes
{
    public static int getFastestOnDay(int[][] a, int day)
    {
        int fastest = a[0][day];
        for (int row = 0; row < a.length; row++)
        {
            if (a[row][day] < fastest)
            {
                fastest = a[row][day];
            }
        }
        return fastest;
    }

    public static void main(String[] args)
    {
        int[][] swapTimes = { {42, 38, 35}, {40, 41, 33}, {45, 36, 37} };
        System.out.println(getFastestOnDay(swapTimes, 1));
    }
}
```

**Why this order:** `fastest` (`f`) is seeded first, with a real time from the chosen day's column (`a[0][day]`), not `0`. A seed of `0` would beat every real time. The loop (`c`, `h`) walks the rows, because the day (the column) stays fixed while each crew member (row) is checked. Inside it, the comparison (`g`, `a`) replaces `fastest` (`d`) only when a smaller time turns up. The braces close in reverse of how they opened: the `if`'s (`i`), then the loop's (`e`). The `return` (`b`) comes last, after every row has been checked. For day `1`, this prints `36`. The class, the method header and its braces, and `main` are the given scaffold. Only the method body needed reordering.

## Coding

**Mode:** harness

**Problem:** Swerve telemetry is stored in a `double[][]` with one row per module and one column per
current-draw sample (same layout as the lesson's `moduleCurrents`). Write
`getPeakSampleIndex`, which returns the index of the **sample column with the highest total current
across all modules** — the instant the robot came closest to a brownout. If two columns tie for the
highest total, return the **earlier** (smaller) column index. Every array has at least one row and
one column.

Examples:

- `getPeakSampleIndex(new double[][] { {12.1, 11.8, 40.2}, {12.0, 11.9, 12.1} })` returns `2`
- `getPeakSampleIndex(new double[][] { {5.0, 1.0}, {5.0, 1.0} })` returns `0`
- `getPeakSampleIndex(new double[][] { {3.0, 4.0}, {4.0, 3.0} })` returns `0` (both columns total `7.0`)

**Signature:** `public static int getPeakSampleIndex(double[][] currents)`

**Starter:**

```java
public class Solution
{
    public static int getPeakSampleIndex(double[][] currents)
    {
        // TODO: return the index of the column with the highest total
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `new double[][] { {12.1, 11.8, 40.2}, {12.0, 11.9, 12.1} }` | `2` |
| yes | `new double[][] { {5.0, 1.0}, {5.0, 1.0} }` | `0` |
| yes | `new double[][] { {3.0, 4.0}, {4.0, 3.0} }` | `0` |
| no | `new double[][] { {1.5}, {2.5} }` | `0` |
| no | `new double[][] { {1.0, 9.0, 2.0}, {1.0, 9.0, 2.0}, {1.0, 0.0, 2.0} }` | `1` |
| no | `new double[][] { {2.0, 1.0, 3.0}, {2.0, 1.0, 3.0}, {9.0, 0.0, 0.0} }` | `0` |
| no | `new double[][] { {1.0, 2.0, 2.0}, {1.0, 2.0, 2.0} }` | `1` |

**Solution:**

```java
public class Solution
{
    public static int getPeakSampleIndex(double[][] currents)
    {
        int peakCol = 0;
        double peakTotal = 0;
        for (int row = 0; row < currents.length; row++)
        {
            peakTotal = peakTotal + currents[row][0];
        }
        for (int col = 1; col < currents[0].length; col++)
        {
            double total = 0;
            for (int row = 0; row < currents.length; row++)
            {
                total = total + currents[row][col];
            }
            if (total > peakTotal)
            {
                peakTotal = total;
                peakCol = col;
            }
        }
        return peakCol;
    }
}
```

**Why:** This combines two Lesson 10.3 patterns. Summing a column fixes `col` and loops `row`
(`getTotalForSample`). Finding the biggest total seeds with a real value — column `0`'s total — not
`0` (`getPeakCurrent`'s rule). Using `>` rather than `>=` keeps the earlier column on a tie. A common
mistake is summing rows instead of columns, which answers "which module drew the most," a different
question.
