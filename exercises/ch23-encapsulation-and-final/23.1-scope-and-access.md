# Scope and Access — Exercises

## Multiple Choice

**Question:** A `FaultLog` class has this field:

```java
private final ArrayList<String> faults = new ArrayList<String>();
```

Which one of these lines, written inside one of `FaultLog`'s own methods, fails to compile?

**Options:**

- A. `faults.add("CAN timeout");`
- B. `faults.remove(0);`
- C. `faults = new ArrayList<String>();`
- D. `System.out.println(faults.size());`

**Answer:** C

**Why:** `final` allows a variable exactly one assignment, and `faults` already got it in its declaration. Assigning it again, pointing it at a different list, is a compile error. On an object reference, `final` locks *which object* the variable refers to, not what's inside that object.

- A is wrong. `add` changes the contents of the list `faults` refers to. It doesn't reassign `faults`, so `final` doesn't block it.
- B is wrong. Removing an element also only changes the list's contents. `faults` still refers to the same list afterward.
- D is wrong. This only reads from the list. Reading a `final` variable is always allowed, and `private` doesn't stop it either, since this line is inside the class's own method.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that adds up the current draw of three motors and prints `Total current: 75 A`. Pay attention to scope: the running total has to still exist after the loop finishes.

Reorder the fragments below into a working program:

- a. `            total = total + motorCurrents[i];`
- b. `    public static void main(String[] args)`
- c. `    }` `}`
- d. `        int[] motorCurrents = {12, 38, 25};`
- e. `public class CurrentTotal`
- f. `        System.out.println("Total current: " + total + " A");`
- g. `        for (int i = 0; i < motorCurrents.length; i++)`
- h. `{`
- i. `        int total = 0;`
- j. `        }`
- k. `    {`
- l. `        {`

**Answer:** e, h, b, k, d, i, g, l, a, j, f, c

**Interchangeable:** (d, i)

```java
public class CurrentTotal
{
    public static void main(String[] args)
    {
        int[] motorCurrents = {12, 38, 25};
        int total = 0;
        for (int i = 0; i < motorCurrents.length; i++)
        {
            total = total + motorCurrents[i];
        }
        System.out.println("Total current: " + total + " A");
    }
}
```

**Why this order:** The class line (`e`) and its opening brace (`h`) come first, then `main` (`b`) and its opening brace (`k`). The array (`d`) and the running total (`i`) both have to be declared before the loop uses them. Neither reads the other, so they can go in either order (hence **Interchangeable:** (d, i)). `total` has to be declared *here*, at method scope, outside the loop. If it were declared inside the loop's braces, it would have block scope: it would be reset to `0` every pass, and it would stop existing at the loop's closing brace, so the `println` couldn't use it and the program wouldn't compile. The loop header (`g`) and its opening brace (`l`) come next, then the line that adds each current (`a`), then the loop's closing brace (`j`). `i` is the loop's own block-scope variable and is gone after that brace. The `println` (`f`) comes after the loop, and `total` is still in scope there. The last fragment (`c`) closes `main` and then the class. It's merged into one fragment because once `main`'s closing brace is placed, the class's closing brace is the only thing left, and merging keeps the puzzle at 12 fragments.
