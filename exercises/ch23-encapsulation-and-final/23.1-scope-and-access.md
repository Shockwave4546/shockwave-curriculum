# Access, final, and Immutability — Exercises

## Multiple Choice

**Question:** A `FaultLog` class has this field:

```java
private final ArrayList<String> faults = new ArrayList<String>();
```

Which one of these lines, written inside one of `FaultLog`'s own methods, fails to compile?

**Options:**

- A. `faults.add("CAN timeout");`
- B. `faults.remove(0);`
- C. `faults = new ArrayList<String>();`
- D. `System.out.println(faults.size());`

**Answer:** C

**Why:** `final` allows a variable exactly one assignment, and `faults` already got it in its declaration. Assigning it again, pointing it at a different list, is a compile error. On an object reference, `final` locks *which object* the variable refers to, not what's inside that object.

- A is wrong. `add` changes the contents of the list `faults` refers to. It doesn't reassign `faults`, so `final` doesn't block it.
- B is wrong. Removing an element also only changes the list's contents. `faults` still refers to the same list afterward.
- D is wrong. This only reads from the list. Reading a `final` variable is always allowed, and `private` doesn't stop it either, since this line is inside the class's own method.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that builds an `AllianceInfo` with a blank `final` field, set once in the constructor, and prints `Alliance: Red`. Keep the field, constructor, and `main` in the usual order a class is written in: the field first, then the constructor, then `main`.

Reorder the fragments below into a working program:

- a. `    private final String color;`
- b. `public class AllianceInfo`
- c. `    public AllianceInfo(String color)`
- d. `{`
- e. `        this.color = color;`
- f. `    {`
- g. `    public static void main(String[] args)`
- h. `        AllianceInfo info = new AllianceInfo("Red");`
- i. `        System.out.println("Alliance: " + info.color);`
- j. `    }`
- k. `    {`
- l. `    }` `}`

**Answer:** b, d, a, c, f, e, j, g, k, h, i, l

**Interchangeable:** (f, k)

```java
public class AllianceInfo
{
    private final String color;
    public AllianceInfo(String color)
    {
        this.color = color;
    }
    public static void main(String[] args)
    {
        AllianceInfo info = new AllianceInfo("Red");
        System.out.println("Alliance: " + info.color);
    }
}
```

**Why this order:** The class line (`b`) and its opening brace (`d`) come first. `color` (`a`) is declared with no initializer — legal for a `final` field, as long as every constructor assigns it exactly once — so it's declared before the constructor that gives it its one assignment. The constructor's signature (`c`) and opening brace (`f`) come next, then the assignment (`e`) and its closing brace (`j`). `main`'s signature (`g`) and opening brace (`k`) follow the constructor — `f` and `k` are both the identical text `    {`, so which specific one lands on which brace makes no visible difference (hence **Interchangeable:** (f, k)). Inside `main`, `info` has to be created (`h`) before its field can be read (`i`) — `info.color` is legal here because `main` is inside `AllianceInfo` itself, the same class `color` is `private` to. The last fragment (`l`) closes `main` and then the class, merged into one fragment since nothing else can come between them.
