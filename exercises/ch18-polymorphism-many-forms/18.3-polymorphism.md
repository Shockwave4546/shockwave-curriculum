# Polymorphism — Exercises

## Multiple Choice

**Question:** `GamePiece` has a `score()` method. `Coral extends GamePiece`, overrides `score()`, and also adds a method of its own, `rotate()`, which `GamePiece` doesn't have. A teammate writes:

```java
GamePiece piece = new Coral();
piece.score();
piece.rotate();
```

What happens?

**Options:**

- A. It doesn't compile, because of `piece.rotate()`; if that line is removed, `piece.score()` runs `Coral`'s version
- B. It doesn't compile, because of `piece.rotate()`; if that line is removed, `piece.score()` runs `GamePiece`'s version
- C. It compiles and runs both lines, because the actual object is a `Coral`
- D. It compiles, but `piece.rotate()` crashes when the program runs

**Answer:** A

**Why:** The compiler checks each call against the variable's **declared** type, `GamePiece`. `GamePiece` has `score()`, so that call is fine — but it has no `rotate()`, so `piece.rotate()` is a compile error, even though the real object has one. Once the code compiles, the JVM picks which `score()` runs from the **actual** object type, `Coral`, so `Coral`'s override runs.

- B is wrong — the declared type only decides *whether* a call compiles, not *which version* runs. Runtime dispatch uses the actual type, so `Coral`'s `score()` runs, not `GamePiece`'s.
- C is wrong — it assumes the compiler looks at the actual object. It never does; it only consults the declared type, `GamePiece`.
- D is wrong — this problem is caught at compile time, before the program ever runs. The code never gets far enough to crash.

## Micro-Parsons

**Problem:** Given these alert classes and the class holding `main`, reorder the fragments below into the body of `main` (where the comment is). It should build an `Alert[]` array of size 2, put a `RumbleAlert` at index 0 and a `LightAlert` at index 1, then loop over the array calling `send()` on each element. The program should print:

```
Rumbling the driver controller
Flashing the LEDs orange
```

```java
public class AlertTest
{
    public static void main(String[] args)
    {
        // main body goes here
    }
}

class Alert
{
    public void send()
    {
        System.out.println("Generic alert");
    }
}

class RumbleAlert extends Alert
{
    @Override
    public void send()
    {
        System.out.println("Rumbling the driver controller");
    }
}

class LightAlert extends Alert
{
    @Override
    public void send()
    {
        System.out.println("Flashing the LEDs orange");
    }
}
```

Reorder the fragments below to complete it:

- a. `            a.send();`
- b. `        alerts[1] = new LightAlert();`
- c. `        Alert[] alerts = new Alert[2];`
- d. `        }`
- e. `        for (Alert a : alerts)`
- f. `        alerts[0] = new RumbleAlert();`
- g. `        {`

**Answer:** c, f, b, e, g, a, d

**Interchangeable:** (f, b)

```java
public class AlertTest
{
    public static void main(String[] args)
    {
        Alert[] alerts = new Alert[2];
        alerts[0] = new RumbleAlert();
        alerts[1] = new LightAlert();
        for (Alert a : alerts)
        {
            a.send();
        }
    }
}

class Alert
{
    public void send()
    {
        System.out.println("Generic alert");
    }
}

class RumbleAlert extends Alert
{
    @Override
    public void send()
    {
        System.out.println("Rumbling the driver controller");
    }
}

class LightAlert extends Alert
{
    @Override
    public void send()
    {
        System.out.println("Flashing the LEDs orange");
    }
}
```

**Why this order:** The array (`c`) has to exist before anything can be stored in it. The two assignments (`f` and `b`) fill index 0 and index 1 — they can go in either order, since each one writes its own separate slot, and the print order comes from the *indexes* (the loop always visits index 0 first), not from which line ran first. Both must come before the loop, though, or the loop would find empty slots. The loop header (`e`) and its opening brace (`g`) come next, then `a.send()` (`a`), then the loop's closing brace (`d`). Inside the loop, `a` is declared as a plain `Alert`, yet each call runs the actual object's own override — `RumbleAlert`'s `send()` for index 0, `LightAlert`'s for index 1. The three alert classes and the `AlertTest` class with `main`'s signature are the given scaffold.


## Coding

**Mode:** full-program

**Problem:** The robot-part classes below (`RobotPart`, `Intake`, `Climber`, `Shooter`) are
already written and are not to be changed. Only `Intake` has a `hasGamePiece()` method, and each
subclass overrides `stop()` with its own message. Write the class `PartManager` with two static
methods that take a `RobotPart[]`:

- `stopAll(RobotPart[] parts)` stops every part, in array order. It must not check which kind of part
  it is looking at: one loop calling `stop()` is enough, and each object runs its own version.
- `countHolding(RobotPart[] parts)` returns how many parts are an `Intake` that is currently holding
  a game piece. Parts that are not an `Intake` do not count, and must not crash the method.

The fixed `main` reads a part count, then one line per part (`intake name true/false`,
`climber name`, or `shooter name`), calls both methods, and prints the count. For the input
`3 intake Front true climber Left shooter Main`:

```text
[Front] rollers off
[Left] brake engaged
[Main] flywheel off
holding: 1
```

**Starter:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        int count = in.nextInt();
        RobotPart[] parts = new RobotPart[count];
        for (int i = 0; i < count; i++)
        {
            String kind = in.next();
            String name = in.next();
            if (kind.equals("intake"))
            {
                parts[i] = new Intake(name, in.nextBoolean());
            }
            else if (kind.equals("climber"))
            {
                parts[i] = new Climber(name);
            }
            else
            {
                parts[i] = new Shooter(name);
            }
        }
        PartManager.stopAll(parts);
        System.out.println("holding: " + PartManager.countHolding(parts));
    }
}
```

**Solution:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        int count = in.nextInt();
        RobotPart[] parts = new RobotPart[count];
        for (int i = 0; i < count; i++)
        {
            String kind = in.next();
            String name = in.next();
            if (kind.equals("intake"))
            {
                parts[i] = new Intake(name, in.nextBoolean());
            }
            else if (kind.equals("climber"))
            {
                parts[i] = new Climber(name);
            }
            else
            {
                parts[i] = new Shooter(name);
            }
        }
        PartManager.stopAll(parts);
        System.out.println("holding: " + PartManager.countHolding(parts));
    }
}

// Don't change the four classes below
class RobotPart
{
    private String name;

    public RobotPart(String name) { this.name = name; }
    public String getName() { return name; }
    public void log(String msg) { System.out.println("[" + name + "] " + msg); }
    public void stop() { log("stopped"); }
}

class Intake extends RobotPart
{
    private boolean hasGamePiece;

    public Intake(String name, boolean hasGamePiece)
    {
        super(name);
        this.hasGamePiece = hasGamePiece;
    }

    public boolean hasGamePiece() { return hasGamePiece; }

    @Override
    public void stop() { log("rollers off"); }
}

class Climber extends RobotPart
{
    public Climber(String name) { super(name); }

    @Override
    public void stop() { log("brake engaged"); }
}

class Shooter extends RobotPart
{
    public Shooter(String name) { super(name); }

    @Override
    public void stop() { log("flywheel off"); }
}

class PartManager
{
    public static void stopAll(RobotPart[] parts)
    {
        for (RobotPart p : parts)
        {
            p.stop();
        }
    }

    public static int countHolding(RobotPart[] parts)
    {
        int holding = 0;
        for (RobotPart p : parts)
        {
            if (p instanceof Intake i && i.hasGamePiece())
            {
                holding++;
            }
        }
        return holding;
    }
}
```

**Why:** `stopAll` needs no `if` chain: `p` is declared `RobotPart`, so the compiler accepts
`p.stop()`, and at runtime each object's own override runs. `hasGamePiece()` exists only on
`Intake`, so `countHolding` has to downcast, and the cast has to be guarded. Writing
`((Intake) p).hasGamePiece()` for every element compiles, but throws `ClassCastException` as soon as
it reaches a `Climber` or `Shooter`. `p instanceof Intake i` checks the real type first and gives
`i` already typed as `Intake`; the older form, an `instanceof` test followed by `(Intake) p`, works
the same way.
