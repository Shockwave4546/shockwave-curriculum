# Overriding Methods — Exercises

## Multiple Choice

**Question:** An `Actuator` class has this method:

```java
public void home()
{
    System.out.println("Actuator: homing");
}
```

`Elevator extends Actuator`. Which method declaration, placed inside `Elevator`, correctly **overrides** `home()`?

**Options:**

- A. `public void home(double speed) { ... }`
- B. `public int home() { ... }`
- C. `@Override public void home() { ... }`
- D. `@Override public void homee() { ... }`

**Answer:** C

**Why:** An override needs the same name and parameter list as the inherited method, and the same return type (or a subtype of it). C matches `home()` exactly — same name, no parameters, `void` — and `@Override` lets the compiler confirm it.

- A is wrong — adding a parameter makes it an **overload**, not an override. `Elevator` would end up with two methods: its new `home(double)` and the inherited `home()`, which still runs `Actuator`'s version unchanged.
- B is wrong — it differs from the inherited `home()` only by return type, and `int` isn't compatible with `void`, so it's neither a valid override nor a valid overload. It doesn't compile.
- D is wrong — `homee` is a typo, so there's no inherited method with that name to override. Because `@Override` is there, the compiler catches it and refuses to compile (without `@Override`, it would silently become a brand-new, unrelated method).

## Micro-Parsons

**Problem:** Given this `Actuator` class and `main` method, reorder the fragments below into the `Elevator` class that goes where the comment is. `Elevator` must extend `Actuator` and override `home()` so the program prints `Elevator: lowering to bottom limit`.

```java
public class HomingTest
{
    public static void main(String[] args)
    {
        Elevator lift = new Elevator();
        lift.home();
    }
}

class Actuator
{
    public void home()
    {
        System.out.println("Actuator: homing");
    }
}

// Elevator class goes here
```

Reorder the fragments below to complete it:

- a. `    public void home()`
- b. `}`
- c. `class Elevator extends Actuator`
- d. `        System.out.println("Elevator: lowering to bottom limit");`
- e. `    @Override`
- f. `{`
- g. `    }`
- h. `    {`

**Answer:** c, f, e, a, h, d, g, b

```java
public class HomingTest
{
    public static void main(String[] args)
    {
        Elevator lift = new Elevator();
        lift.home();
    }
}

class Actuator
{
    public void home()
    {
        System.out.println("Actuator: homing");
    }
}

class Elevator extends Actuator
{
    @Override
    public void home()
    {
        System.out.println("Elevator: lowering to bottom limit");
    }
}
```

**Why this order:** The class declaration (`c`) comes first — `extends Actuator` is what makes `Elevator` inherit `home()` in the first place, so there's something to override — followed by the class's opening brace (`f`). `@Override` (`e`) is an annotation on the method, so it sits directly above the method's signature (`a`), which must match `Actuator`'s `home()` exactly: same name, no parameters, `void`. The method's opening brace (`h`), its `println` statement (`d`), and its closing brace (`g`) follow, and the class's closing brace (`b`) comes last. The `Actuator` class and `HomingTest`'s `main` are the given scaffold; since `Elevator`'s override replaces the inherited version, `lift.home()` prints `Elevator: lowering to bottom limit`, not `Actuator: homing`.


## Coding

**Mode:** full-program

**Problem:** `RobotPart` (below, already written, and not to be changed) has a general `stop()`
that logs `stopped`. Write two subclasses that replace it:

- `Intake`, with the constructor `Intake(String name, boolean hasGamePiece)`. It **overrides**
  `stop()`: it logs `rollers off, game piece held` when `hasGamePiece` is `true`, and `rollers off`
  when it is `false`.
- `Shooter`, with the constructor `Shooter(String name)`. It **overrides** `stop()` to log
  `flywheel off`. It also gets an **overload**, `stop(int seconds)`, that logs
  `flywheel coasting for N s` (with the number in place of `N`) and leaves the plain `stop()`
  alone.

Use `@Override` on the overrides. The fixed `main` reads one part per run and stops it through a
`RobotPart` variable, which is the call that only an override can change. For the input
`shooter Main 3`:

```text
[Main] flywheel off
[Main] flywheel coasting for 3 s
```

**Starter:**

```java
import java.util.*;

public class Main

            part.stop();

}
```

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        String kind = in.next();
        String name = in.next();
        if (kind.equals("intake"))
        {
            RobotPart part = new Intake(name, in.nextBoolean());
            part.stop();
        }
        else
        {
            Shooter shooter = new Shooter(name);
            RobotPart part = shooter;
            part.stop();
            shooter.stop(in.nextInt());
        }
    }
}

// Don't change RobotPart
class RobotPart
{
    private String name;

    public RobotPart(String name) { this.name = name; }
    public String getName() { return name; }
    public void log(String msg) { System.out.println("[" + name + "] " + msg); }
    public void stop() { log("stopped"); }
}

class Intake extends RobotPart
{
    private boolean hasGamePiece;

    public Intake(String name, boolean hasGamePiece)
    {
        super(name);
        this.hasGamePiece = hasGamePiece;
    }

    @Override
    public void stop()
    {
        if (hasGamePiece)
        {
            log("rollers off, game piece held");
        }
        else
        {
            log("rollers off");
        }
    }
}

class Shooter extends RobotPart
{
    public Shooter(String name) { super(name); }

    @Override
    public void stop() { log("flywheel off"); }

    public void stop(int seconds)
    {
        log("flywheel coasting for " + seconds + " s");
    }
}
```

**Why:** Overriding means the **same signature**, `stop()` with no parameters, so
`part.stop()` on a `RobotPart` variable runs the subclass's version. `stop(int seconds)` has a
different parameter list, so it is an **overload**: it sits beside the inherited `stop()` instead of
replacing it, and it overrides nothing, so it gets no `@Override`. A student who writes only
`stop(int)` for `Shooter` has overridden nothing, and `part.stop()` still prints `stopped`. Here
`@Override` earns its keep on `Intake`: a typo like `stopp()` would be a compile error, not a
method that silently never runs.
