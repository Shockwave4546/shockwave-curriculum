# Packages & Imports — Exercises

## Multiple Choice

**Question:** A file declares `package frc.robot.climber;` and uses `String status = "locked";` without importing anything for `String`. Does this compile?

**Options:**

- A. Yes — `String` is part of `java.lang`, which never needs an import.
- B. No — every class used in a file, including `String`, must be imported.
- C. Yes, but only because `frc.robot.climber` happens to already contain a `String` class.
- D. No — `String` needs an import unless the file has no `package` line at all.

**Answer:** A

**Why:** `java.lang` classes — `String` and `System` among them — are always available in every Java file, with no `import` needed, regardless of what package the file itself belongs to.

- B is wrong — it overgeneralizes; `java.lang` is the one exception to "every class needs an import."
- C is wrong — `String` isn't a class this file defines or that happens to live in `frc.robot.climber`; it's a built-in `java.lang` class, available everywhere.
- D is wrong — whether a file has its own `package` line has nothing to do with whether `String` needs an import; `java.lang` classes never need one either way.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete file in the `frc.robot.climber` package that imports WPILib's `DigitalOutput` class, creates one on digital output pin 0 (the climber's "locked" signal light), and turns it on.

Reorder the fragments below into a working program:

- a. `        DigitalOutput lockedLight = new DigitalOutput(0);`
- b. `public class ClimberLock`
- c. `    }`
- d. `package frc.robot.climber;`
- e. `    public static void main(String[] args)`
- f. `}`
- g. `import org.wpilib.hardware.discrete.DigitalOutput;`
- h. `        lockedLight.set(true);`
- i. `{`
- j. `    {`

**Answer:** d, g, b, i, e, j, a, h, c, f

```java
package frc.robot.climber;

import org.wpilib.hardware.discrete.DigitalOutput;

public class ClimberLock
{
    public static void main(String[] args)
    {
        DigitalOutput lockedLight = new DigitalOutput(0);
        lockedLight.set(true);
    }
}
```

**Why this order:** The `package` line (`d`) has to be the very first line in the file, and the `import` (`g`) comes next — before the class that relies on the imported class shows up. The class declaration (`b`) and its opening brace (`i`) follow, then `main` (`e`) with its own opening brace (`j`). Inside `main`, the `DigitalOutput` object has to be created (`a`) before any behavior can be called on it — `set(true)` (`h`) only works once `lockedLight` exists. Then the braces close in the reverse order they opened: `main`'s body first (`c`), then the class's body (`f`).
