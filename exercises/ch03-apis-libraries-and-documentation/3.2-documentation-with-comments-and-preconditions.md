## Multiple Choice

**Question:** A method's documentation says `Precondition: batteryVoltage is greater than 0`. A teammate calls it with `batteryVoltage = -12.0`. What happens when the program runs?

**Options:**

- A. The method runs anyway and may return an incorrect result — Java does not check preconditions automatically.
- B. The compiler refuses to compile the program because the precondition is violated.
- C. The program throws a runtime exception naming the violated precondition.
- D. Java automatically substitutes `0` for the negative value before running the method.

**Answer:** A

**Why:** A precondition is a documented expectation, not something Java enforces on its own. Nothing about calling the method with `-12.0` stops the program — it just runs the method's code as written, which may now produce a result that breaks the postcondition it promised.

- B is wrong — the compiler doesn't read documentation comments for meaning at all; it ignores every comment completely, precondition or not.
- C is wrong — no exception is thrown unless the method's own code explicitly checks the value and throws one, which isn't described here.
- D is wrong — Java never substitutes or "fixes" a bad argument on its own; the value passed in is used exactly as given.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that documents and calls a method converting a raw sensor reading (0–1023) into a percentage (0–100), then prints the result.

Reorder the fragments below into a working program:

- a. `    /** Precondition: rawValue is between 0 and 1023. Postcondition: returns a percentage between 0 and 100. */`
- b. `    {`
- c. `        return rawValue / 1023.0 * 100;`
- d. `public class SensorScale`
- e. `        System.out.println(rawToPercent(512));`
- f. `    }`
- g. `    public static void main(String[] args)`
- h. `    public static double rawToPercent(int rawValue)`
- i. `    }`
- j. `    {`
- k. `{`
- l. `}`

**Answer:** d, k, g, b, e, f, a, h, j, c, i, l

```java
public class SensorScale
{
    public static void main(String[] args)
    {
        System.out.println(rawToPercent(512));
    }
    /** Precondition: rawValue is between 0 and 1023. Postcondition: returns a percentage between 0 and 100. */
    public static double rawToPercent(int rawValue)
    {
        return rawValue / 1023.0 * 100;
    }
}
```

**Why this order:** The class declaration (`d`) has to come first, with its opening brace (`k`) right after. `main` (`g`) is the entry point, declared next, followed by its own opening brace (`b`). Inside `main`, the only statement (`e`) calls `rawToPercent` and prints whatever it returns, then `main`'s body closes (`f`). The documentation comment (`a`) has to sit directly above the method it describes — not above `main` — because that's what ties a `/** */` comment to the code it documents. The method's signature (`h`) and its opening brace (`j`) follow the comment, its `return` statement (`c`) is the only line in its body, then the method's body closes (`i`) before the class's body closes last (`l`).
