# APIs and Libraries — Exercises

## Multiple Choice

**Question:** A teammate writes `DigitalInput limitSwitch = new DigitalInput(0); boolean pressed = limitSwitch.get();`. Which statement correctly identifies the class and the object?

**Options:**

- A. `DigitalInput` is the class; `limitSwitch` is the object built from it.
- B. `limitSwitch` is the class; `DigitalInput` is the object built from it.
- C. `get` is the class; `limitSwitch` is the object.
- D. `DigitalInput` and `limitSwitch` are both objects — there is no class here.

**Answer:** A

**Why:** `DigitalInput` is the blueprint — WPILib's class for reading a digital input pin — and `limitSwitch` is one specific instance built from it with `new`. Calling `limitSwitch.get()` reaches a behavior defined by the `DigitalInput` class and runs it on this one object.

- B is wrong — it swaps the roles: `DigitalInput` is the class (the blueprint), not something built from `limitSwitch`.
- C is wrong — `get` is a behavior (method) defined by the class, not the class itself.
- D is wrong — every object is built from some class; `DigitalInput` is that class here, not another object.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a program that creates WPILib's `Encoder` object for an arm (wired to digital channels 0 and 1), resets it, reads the distance it has measured, and prints that value. (A real file would also need an `import` line for `Encoder` — it's left out here; Lesson 3.3 covers imports.)

Reorder the fragments below into a working program:

- a. `        double armDistance = armEncoder.getDistance();`
- b. `    public static void main(String[] args)`
- c. `    }`
- d. `public class ArmCheck`
- e. `        Encoder armEncoder = new Encoder(0, 1);`
- f. `}`
- g. `{`
- h. `        System.out.println(armDistance);`
- i. `    {`
- j. `        armEncoder.reset();`

**Answer:** d, g, b, i, e, j, a, h, c, f

```java
public class ArmCheck
{
    public static void main(String[] args)
    {
        Encoder armEncoder = new Encoder(0, 1);
        armEncoder.reset();
        double armDistance = armEncoder.getDistance();
        System.out.println(armDistance);
    }
}
```

**Why this order:** The class line (`d`) has to come first, with its opening brace (`g`) right after. `main` (`b`) is the entry point, declared next, followed by its own opening brace (`i`). Inside `main`, the `Encoder` object must be created (`e`) before any behavior can be called on it. `reset()` (`j`) is a behavior that doesn't return anything, so it's just called on its own line — and the problem asks for the reset before the reading, so it goes first. `getDistance()` (`a`) is a behavior that *does* return a value, so it has to be stored in the `armDistance` variable before that variable can be printed (`h`). Then the braces close in the reverse order they opened: `main`'s body first (`c`), then the class's body (`f`).
