# Binding Commands to Triggers — Exercises

## Multiple Choice

**Question:** During setup, this binding is created:

```java
driverController.b().onTrue(Commands.runOnce(() -> gyro.reset()));
```

The driver presses **B** and holds it down for 3 seconds before letting go. How many times does `gyro.reset()` run?

**Options:**

- A. Once, the instant B is first pressed
- B. About 150 times — once every 20ms loop while B is held
- C. Twice — once when B is pressed and once when it's released
- D. Zero times until B is released, then once

**Answer:** A

**Why:** `onTrue` schedules its command only on the change from false to true — the instant B goes down. Holding B keeps the trigger true, but there's no new false-to-true change, so nothing is scheduled again until B is released and pressed a second time.

- B is wrong — scheduling every loop while held isn't what `onTrue` does; even `whileTrue` schedules its command once and keeps it running, rather than restarting it each loop.
- C is wrong — reacting to the release would need a separate `onFalse` binding; `onTrue` ignores the true-to-false change.
- D is wrong — that describes `onFalse`, which fires on the release; `onTrue` fires on the press.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete class, `OperatorControls`, that creates an operator controller on port 1 and a `ClimberSubsystem`. Its constructor builds one trigger, `climbButtons`, that is true only while **both** bumpers are held, debounced by 0.25 seconds so a brief accidental touch doesn't count. It then binds `climber.climbCommand()` so the climber runs only while that trigger stays true.

Reorder the fragments below into a working class:

- a. `        climbButtons.whileTrue(climber.climbCommand());`
- b. `    public OperatorControls()`
- c. `}`
- d. `    private final CommandXboxController operator = new CommandXboxController(1);`
- e. `    {`
- f. `public class OperatorControls`
- g. `        Trigger climbButtons = operator.leftBumper().and(operator.rightBumper()).debounce(0.25);`
- h. `    }`
- i. `{`
- j. `    private final ClimberSubsystem climber = new ClimberSubsystem();`

**Answer:** f, i, d, j, b, e, g, a, h, c

**Interchangeable:** (d, j)

```java
public class OperatorControls
{
    private final CommandXboxController operator = new CommandXboxController(1);
    private final ClimberSubsystem climber = new ClimberSubsystem();

    public OperatorControls()
    {
        Trigger climbButtons = operator.leftBumper().and(operator.rightBumper()).debounce(0.25);
        climbButtons.whileTrue(climber.climbCommand());
    }
}
```

**Why this order:** The class header (`f`) and brace (`i`) come first, then the two fields (`d`, `j`) — the controller and the subsystem have to exist before the constructor can use them. The constructor (`b`, `e`) first builds the combined, debounced trigger (`g`) and stores it in `climbButtons`, and only then binds a command to it (`a`) — the variable can't be used before it's declared. `whileTrue` is the right binding here: it keeps `climbCommand()` running while both bumpers stay held and cancels it the instant either is released. The constructor's brace closes (`h`), then the class's (`c`).

`d` and `j` can go in either order: neither field's initializer uses the other, and both are created before the constructor body runs, whichever comes first.
