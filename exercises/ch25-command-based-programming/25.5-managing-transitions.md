# Managing Transitions — Exercises

## Multiple Choice

**Question:** An indexer's state machine runs this `switch` in `periodic()`. What does one call print when `currentState` is `IndexerState.FEEDING`?

```java
switch (currentState)
{
    case FEEDING:
        System.out.println("Belt forward");
    case JAMMED:
        System.out.println("Belt reverse");
        break;
    case STOPPED:
        System.out.println("Belt off");
        break;
}
```

**Options:**

- A. `Belt forward` only
- B. `Belt forward`, then `Belt reverse`
- C. `Belt forward`, then `Belt reverse`, then `Belt off`
- D. Nothing — the code doesn't compile, because the `FEEDING` case has no `break;`

**Answer:** B

**Why:** The `FEEDING` case is missing its `break;`, so after printing `Belt forward`, execution falls through into the `JAMMED` case's code and prints `Belt reverse` too. The `break;` at the end of `JAMMED` stops it there. This is exactly the bug a missing `break;` causes: the wrong state's behavior runs on top of the intended one.

- A is wrong — that's what would happen *with* a `break;` after `Belt forward`; without one, execution doesn't stop at the next `case` label.
- C is wrong — fall-through continues only until the next `break;`, which comes right after `Belt reverse`, so `STOPPED`'s code never runs.
- D is wrong — a missing `break;` compiles just fine; that's what makes it such an easy bug to miss.

## Micro-Parsons

**Problem:** This program is a plain-Java stand-in for a shooter subsystem's state machine: `main` calls `periodic()` three times, standing in for three scheduler loops, and raises `flywheelRpm` to 3200 before the second call. While `SPINNING_UP`, the shooter should print `Spinning up` and move to `READY` once `flywheelRpm` is at least 3000; while `READY`, it should print `Ready to fire`.

Given this enum, class, fields, `periodic()` method, and `main` method:

```java
enum ShooterState
{
    SPINNING_UP, READY
}

public class ShooterStateMachine
{
    private ShooterState currentState = ShooterState.SPINNING_UP;
    private double flywheelRpm = 0.0;

    public void periodic()
    {
        // your fragments go here
    }

    public static void main(String[] args)
    {
        ShooterStateMachine shooter = new ShooterStateMachine();
        shooter.periodic();
        shooter.flywheelRpm = 3200.0;
        shooter.periodic();
        shooter.periodic();
    }
}
```

Reorder the fragments below into the body of `periodic()`:

- a. `        System.out.println("Ready to fire");`
- b. `switch (currentState)`
- c. `        {`
- d. `    case SPINNING_UP:`
- e. `        break;`
- f. `            currentState = ShooterState.READY;`
- g. `{`
- h. `        if (flywheelRpm >= 3000)`
- i. `        System.out.println("Spinning up");`
- j. `    case READY:`
- k. `        }`
- l. `        break;`
- m. `}`

**Answer:** b, g, d, i, h, c, f, k, e, j, a, l, m

**Interchangeable:** (e, l)

```java
enum ShooterState
{
    SPINNING_UP, READY
}

public class ShooterStateMachine
{
    private ShooterState currentState = ShooterState.SPINNING_UP;
    private double flywheelRpm = 0.0;

    public void periodic()
    {
        switch (currentState)
        {
            case SPINNING_UP:
                System.out.println("Spinning up");
                if (flywheelRpm >= 3000)
                {
                    currentState = ShooterState.READY;
                }
                break;
            case READY:
                System.out.println("Ready to fire");
                break;
        }
    }

    public static void main(String[] args)
    {
        ShooterStateMachine shooter = new ShooterStateMachine();
        shooter.periodic();
        shooter.flywheelRpm = 3200.0;
        shooter.periodic();
        shooter.periodic();
    }
}
```

**Why this order:** The `switch` header (`b`) and its brace (`g`) wrap everything. The `SPINNING_UP` case label (`d`) comes first, followed by that state's behavior (`i`). The transition check (`h`, `c`, `f`, `k`) belongs inside `SPINNING_UP` — the only state it applies to — and the case ends with `break;` (`e`) so it doesn't fall through into `READY`. Then the `READY` case (`j`), its behavior (`a`), and its own `break;` (`l`). The `switch`'s brace closes last (`m`).

The program prints `Spinning up`, `Spinning up`, `Ready to fire`: on the second call the RPM check passes, but `Spinning up` was already printed before the check ran, so the new `READY` state only shows up on the third call.

`e` and `l` are the same text (`        break;`), so either one works in either spot.
