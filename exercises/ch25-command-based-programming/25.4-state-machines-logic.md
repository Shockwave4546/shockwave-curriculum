# State Machines: Logic — Exercises

## Multiple Choice

**Question:** A shooter mechanism tracks what it's doing with three fields: `boolean isIdle`, `boolean isSpinningUp`, and `boolean isReady`. A teammate replaces them with a single field, `ShooterState currentState`, where `ShooterState` is an enum with the constants `IDLE`, `SPINNING_UP`, and `READY`. What problem does this change solve?

**Options:**

- A. The shooter can no longer be recorded as being in two states at once, like idle and ready at the same time.
- B. The shooter code runs faster, because an enum is checked more quickly than a `boolean`.
- C. The shooter can now be in two states at once when it needs to be, like spinning up and ready together.
- D. The state field no longer needs an initial value, because an enum field always starts at its first constant.

**Answer:** A

**Why:** With three independent booleans, nothing stops two of them from being `true` together — a contradiction that compiles just fine. A single enum-typed field holds exactly one value at a time, so the shooter's state is structurally guaranteed to be exactly one of `IDLE`, `SPINNING_UP`, or `READY`.

- B is wrong — the point of the change is correctness and readability, not speed.
- C is wrong — it's the opposite: being in exactly one state at a time is the whole guarantee a state machine gives you.
- D is wrong — an enum field left uninitialized is `null`, not its first constant; it still needs a real starting value like `ShooterState.IDLE`.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that declares a `GearState` enum with the constants `LOW` and `HIGH`, then creates a single state variable for a two-speed gearbox that starts in `LOW` gear, and prints it. Declare the enum first in the file, above the class that uses it.

*Note on file order:* putting the enum before the class with `main` is fine on Java 25's single-file launcher (this course's target), but Java 17's single-file launcher requires the class that contains `main` to come first in the file — see the note in Lesson 25.4's worked example.

Reorder the fragments below into a working program:

- a. `        GearState currentGear = GearState.LOW;`
- b. `public class GearboxStatus`
- c. `    }`
- d. `enum GearState`
- e. `    public static void main(String[] args)`
- f. `}`
- g. `    LOW, HIGH`
- h. `{`
- i. `        System.out.println(currentGear);`
- j. `    {`
- k. `{`
- l. `}`

**Answer:** d, h, g, f, b, k, e, j, a, i, c, l

**Interchangeable:** (h, k) (f, l)

```java
enum GearState
{
    LOW, HIGH
}

public class GearboxStatus
{
    public static void main(String[] args)
    {
        GearState currentGear = GearState.LOW;
        System.out.println(currentGear);
    }
}
```

**Why this order:** The enum's header (`d`), brace (`h`), constant list (`g`), and closing brace (`f`) come first, defining every state the gearbox can be in. Then the class (`b`, `k`) and `main` (`e`, `j`). Inside `main`, the state variable must be declared and given its real starting value (`a`) before it can be printed (`i`) — the program prints `LOW`. Then `main`'s brace closes (`c`), then the class's (`l`).

`h` and `k` are the same text (`{`), as are `f` and `l` (`}`), so either one of each pair works in either spot.
