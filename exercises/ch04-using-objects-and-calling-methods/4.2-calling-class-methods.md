## Multiple Choice

**Question:**

```java
public static double computeAverage(int a, int b)
{
    return (a + b) / 2.0;
}
```

```java
int result = computeAverage(4, 6);
```

What happens when this code is compiled?

**Options:**

- A. Compile error — a `double` return value can't be assigned directly to an `int` variable
- B. Compiles and runs fine — `result` becomes `5`
- C. Compiles and runs fine — `result` becomes `5.0`
- D. Compile error — `computeAverage` must be called without storing its result

**Answer:** A

**Why:** `computeAverage` returns a `double`. Assigning a `double` into an `int` variable without an explicit cast is a type mismatch, and the compiler rejects it before the program ever runs.

- B is wrong — the code never runs at all; it fails to compile, so there's no `5` (or anything else) to observe.
- C is wrong for the same reason — `result` is declared as `int`, so it couldn't hold `5.0` even if the assignment were allowed.
- D is wrong — storing a method's return value in a variable is exactly what non-void methods are for; the problem here is the *type* of the variable, not the act of storing at all.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that calls a non-void method and prints its returned value directly, without storing it in a variable first.

Reorder the fragments below into a working program:

- a. `    public static int toPercent(double raw)`
- b. `        return (int)(raw * 100);`
- c. `{`
- d. `    }`
- e. `public class JoystickCheck`
- f. `    public static void main(String[] args)`
- g. `        System.out.println("Joystick at " + toPercent(0.42) + "%");`
- h. `    {`
- i. `    {`
- j.
  ```java
      }
  }
  ```

**Answer:** e, c, f, h, g, d, a, i, b, j

```java
public class JoystickCheck
{
    public static void main(String[] args)
    {
        System.out.println("Joystick at " + toPercent(0.42) + "%");
    }

    public static int toPercent(double raw)
    {
        return (int)(raw * 100);
    }
}
```

**Why this order:** As before, the class line (`e`) and its opening brace (`c`) open the program, followed by `main` (`f`) and its own opening brace (`h`). Rather than storing `toPercent(0.42)` in a variable first, the `println` call (`g`) uses the method's return value directly inside the expression — same rule as `System.out.println(square(4))` from the lesson. `main`'s body then closes (`d`). `toPercent`'s signature (`a`) and opening brace (`i`) come next, and its `return` statement (`b`) is the only line in its body — `return` both produces the value and ends the method immediately, so nothing else needs to go inside those braces. Finally, `j` — the method's closing brace immediately followed by the class's closing brace, merged into a single fragment since nothing could ever validly go between them — finishes the program.
