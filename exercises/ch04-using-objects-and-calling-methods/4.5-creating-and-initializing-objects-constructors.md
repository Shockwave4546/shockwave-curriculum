# Creating & Initializing Objects: Constructors — Exercises

## Multiple Choice

**Question:** A `Waypoint` class has this constructor: `public Waypoint(double x, double y) { ... }`. A teammate means to create a waypoint at x=7.0, y=3.0, but writes:

```java
Waypoint corner = new Waypoint(3.0, 7.0);
```

What happens?

**Options:**

- A. The code compiles and runs, but `corner` silently ends up at the wrong position (x=3.0, y=7.0)
- B. The code won't compile, since the argument order doesn't match the intended position
- C. The code compiles, but throws a `NullPointerException` at runtime
- D. Java automatically detects the mismatch and swaps the arguments back into the correct order

**Answer:** A

**Why:** Both arguments are `double` values, so the compiler has no way to tell that they were meant to go in the other order — it just matches them positionally to the constructor's parameters. `3.0` becomes `x` and `7.0` becomes `y`, exactly backwards from what was intended, and the program runs without ever signaling a problem.

- B is wrong — the compiler only checks argument *count* and *type* against the signature, not intended meaning; two `double` arguments in either order compile equally well.
- C is wrong — `corner` is a real, fully constructed `Waypoint` object; nothing here is `null`, so there's nothing to throw a `NullPointerException`.
- D is wrong — Java has no way to know which order was "intended"; there is no such auto-correction, which is exactly why this bug is dangerous — it's silent.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that declares a `Timer` reference as `null`, then constructs it later once an event actually begins.

Reorder the fragments below into a working program:

- a. `        Timer enduranceTimer = null;`
- b. `    {`
- c. `        // ... later, once the endurance challenge begins ...`
- d. `}`
- e. `    public static void main(String[] args)`
- f. `        System.out.println("Endurance timer started");`
- g. `public class MatchClock`
- h. `        enduranceTimer = new Timer(30.0);`
- i. `    }`
- j. `{`

**Answer:** g, j, e, b, a, c, h, f, i, d

```java
public class MatchClock
{
    public static void main(String[] args)
    {
        Timer enduranceTimer = null;

        // ... later, once the endurance challenge begins ...
        enduranceTimer = new Timer(30.0);

        System.out.println("Endurance timer started");
    }
}
```

**Why this order:** The class line (`g`) and its opening brace (`j`) come first, then `main` (`e`) and its own opening brace (`b`). `enduranceTimer` is declared as `null` (`a`) before anything else — it exists as a variable, but doesn't refer to an object yet. The comment (`c`) marks that time passes before the challenge starts, and only then is `enduranceTimer` actually assigned a real object with `new` (`h`) — notice `new` isn't needed again on the left side, since `enduranceTimer` already exists as a variable. The confirmation message (`f`) only makes sense once the timer is real, so it comes after the assignment, followed by `main`'s closing brace (`i`) and the class's closing brace (`d`).
