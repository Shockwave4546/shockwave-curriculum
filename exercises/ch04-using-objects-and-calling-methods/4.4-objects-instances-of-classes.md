## Multiple Choice

**Question:**

```java
Joystick driverStick = new Joystick(0);
Joystick operatorStick = new Joystick(1);
```

Later, code changes some internal state of `driverStick` (for example, calling a method that updates its stored deadband value). What happens to `operatorStick`?

**Options:**

- A. `operatorStick` is unaffected — each object has its own independent attribute values
- B. `operatorStick` changes too, since both were built from the same class
- C. They only share state if they were declared on the same line
- D. It depends on which one was constructed first

**Answer:** A

**Why:** `driverStick` and `operatorStick` are two separate `Joystick` objects. The class defines what attributes *exist* (like a deadband value), but each object holds its own values for them — changing one object's state has zero effect on any other object of the same class.

- B is wrong — sharing a class only means sharing what attributes and behaviors are *possible*, not sharing the actual values. That's exactly the mistake this pitfall warns about.
- C is wrong — how variables are declared (same line, separate lines) has no bearing on whether the objects they refer to share state; only assigning one reference variable to another would do that, and neither line does so here.
- D is wrong — construction order has no effect on independence; even the first-constructed object's state never leaks into objects constructed after it.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that constructs three independent `Solenoid` objects for a pneumatics subsystem.

Reorder the fragments below into a working program:

- a. `        Solenoid armSolenoid = new Solenoid(1);`
- b. `    {`
- c. `public class PneumaticsSetup`
- d. `        Solenoid hookSolenoid = new Solenoid(2);`
- e. `        Solenoid clawSolenoid = new Solenoid(0);`
- f. `    public static void main(String[] args)`
- g. `}`
- h. `        System.out.println("Three solenoids created");`
- i. `    }`
- j. `{`

**Answer:** c, j, f, b, e, a, d, h, i, g

```java
public class PneumaticsSetup
{
    public static void main(String[] args)
    {
        Solenoid clawSolenoid = new Solenoid(0);
        Solenoid armSolenoid = new Solenoid(1);
        Solenoid hookSolenoid = new Solenoid(2);

        System.out.println("Three solenoids created");
    }
}
```

**Why this order:** The class line (`c`) and its opening brace (`j`) come first, then `main` (`f`) and its own opening brace (`b`). Each `Solenoid` is a separate object built from the same class, so its own reference variable must exist before the program can be said to have "created" it — `clawSolenoid` (`e`), `armSolenoid` (`a`), and `hookSolenoid` (`d`) follow the order they're introduced in the problem, each with its own CAN-style channel number as the constructor's argument. The confirmation message (`h`) only makes sense once all three exist, so it comes last inside `main`, followed by `main`'s closing brace (`i`) and the class's closing brace (`g`).
