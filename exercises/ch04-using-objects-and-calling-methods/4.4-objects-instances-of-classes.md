# Objects — Instances of Classes — Exercises

## Multiple Choice

**Question:**

```java
Joystick driverStick = new Joystick(0);
Joystick operatorStick = new Joystick(1);
```

Later, code changes some internal state of `driverStick` — for example, `driverStick.setXChannel(3);`, which changes which axis that joystick reports as its X axis. What happens to `operatorStick`?

**Options:**

- A. `operatorStick` is unaffected — each object has its own independent attribute values
- B. `operatorStick` changes too, since both were built from the same class
- C. They only share state if they were declared on the same line
- D. It depends on which one was constructed first

**Answer:** A

**Why:** `driverStick` and `operatorStick` are two separate `Joystick` objects. The class defines what attributes *exist* (like which axis counts as X), but each object holds its own values for them — changing one object's state has zero effect on any other object of the same class.

- B is wrong — sharing a class only means sharing what attributes and behaviors are *possible*, not sharing the actual values. That's exactly the mistake this pitfall warns about.
- C is wrong — how variables are declared (same line, separate lines) has no bearing on whether the objects they refer to share state; only assigning one reference variable to another would do that, and neither line does so here.
- D is wrong — construction order has no effect on independence; even the first-constructed object's state never leaks into objects constructed after it.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that imports WPILib's `DigitalOutput` class and constructs three independent `DigitalOutput` objects — signal lights for the intake, shooter, and climber, on digital output pins 0, 1, and 2.

Reorder the fragments below into a working program:

- a. `        DigitalOutput shooterLight = new DigitalOutput(1);`
- b. `    {`
- c. `public class SignalLights`
- d. `        DigitalOutput climberLight = new DigitalOutput(2);`
- e. `        DigitalOutput intakeLight = new DigitalOutput(0);`
- f. `    public static void main(String[] args)`
- g. `}`
- h. `        System.out.println("Three signal lights created");`
- i. `    }`
- j. `{`
- k. `import org.wpilib.hardware.discrete.DigitalOutput;`

**Answer:** k, c, j, f, b, e, a, d, h, i, g

**Interchangeable:** (e, a, d)

```java
import org.wpilib.hardware.discrete.DigitalOutput;

public class SignalLights
{
    public static void main(String[] args)
    {
        DigitalOutput intakeLight = new DigitalOutput(0);
        DigitalOutput shooterLight = new DigitalOutput(1);
        DigitalOutput climberLight = new DigitalOutput(2);

        System.out.println("Three signal lights created");
    }
}
```

**Why this order:** The `import` (`k`) comes first, before the class that uses `DigitalOutput`. The class line (`c`) and its opening brace (`j`) come next, then `main` (`f`) and its own opening brace (`b`). Each `DigitalOutput` is a separate object built from the same class, with its own pin number as the constructor's argument — `intakeLight` (`e`), `shooterLight` (`a`), and `climberLight` (`d`). None of the three reads another, so they can be created in any order. The confirmation message (`h`) only makes sense once all three exist, so it comes last inside `main`, followed by `main`'s closing brace (`i`) and the class's closing brace (`g`).
