# Calling Instance Methods — Exercises

## Multiple Choice

**Question:**

```java
DigitalInput beamBreak = new DigitalInput(2);
beamBreak.get();
```

`get()` reports whether WPILib's `DigitalInput` sees its pin as on (`true`) or off (`false`) — here, whether a beam-break sensor in the intake is tripped. What's the issue with this code?

**Options:**

- A. It compiles and runs, but does nothing useful — the returned reading is computed and then thrown away
- B. It won't compile — getters must always be assigned to a variable
- C. It throws a `NullPointerException`, since `beamBreak` was never given a value
- D. `get()` requires an argument, so this won't compile

**Answer:** A

**Why:** `get()` is a getter — it reports a value and returns it, with no other side effect. Calling it and doing nothing with the result still compiles fine; the returned reading is simply discarded, which is a real, easy-to-miss bug.

- B is wrong — Java doesn't force a non-void method's return value to be used; the compiler allows this line exactly as written.
- C is wrong — `beamBreak` was constructed with `new DigitalInput(2)`, so it refers to a real object; there's no `null` reference here to throw an exception.
- D is wrong — `DigitalInput`'s `get()` takes no arguments, and a getter reporting an object's own reading typically takes none; the actual issue is the ignored return value, not a missing argument.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that constructs an `Elevator` object, commands it to a position, then reads back and prints its current height using a getter. `Elevator` is the team's own class — assume it already exists in the same package, with an `Elevator()` constructor, `moveToPosition(double)`, and `getPosition()`.

Reorder the fragments below into a working program:

- a. `        Elevator lift = new Elevator();`
- b. `}`
- c. `    {`
- d. `        double currentHeight = lift.getPosition();`
- e. `public class ElevatorCheck`
- f. `        lift.moveToPosition(24.0);`
- g. `    public static void main(String[] args)`
- h. `    }`
- i. `{`
- j. `        System.out.println("Elevator height: " + currentHeight);`

**Answer:** e, i, g, c, a, f, d, j, h, b

```java
public class ElevatorCheck
{
    public static void main(String[] args)
    {
        Elevator lift = new Elevator();

        lift.moveToPosition(24.0);

        double currentHeight = lift.getPosition();
        System.out.println("Elevator height: " + currentHeight);
    }
}
```

**Why this order:** The class line (`e`) and its opening brace (`i`) come first, then `main` (`g`) and its own opening brace (`c`). `lift` must be constructed (`a`) before any instance method can be called on it — calling a method on a reference that isn't built yet is exactly the `NullPointerException` risk from this lesson. Once `lift` is real, `moveToPosition(24.0)` (`f`) commands it, an instance method call that only makes sense applied to this specific object. `getPosition()` (`d`) is a getter, so its return value must actually be used — here it's stored in `currentHeight` — before that value is printed (`j`). Finally, `main`'s closing brace (`h`) and the class's closing brace (`b`) end the program.
