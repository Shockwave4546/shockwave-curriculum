## Multiple Choice

**Question:** A `Robot` class defines two methods:

```java
public static void logEvent(String message) { ... }
public static void logEvent(String message, int priority) { ... }
```

Which statement is correct?

**Options:**

- A. This is valid overloading — Java picks the matching version based on the number of arguments passed at the call site
- B. This won't compile — two methods in the same class can never share a name
- C. This compiles, but calling `logEvent("Auto started")` is ambiguous and won't run
- D. This won't compile — overloaded methods must differ in return type, not parameter list

**Answer:** A

**Why:** Both methods are named `logEvent`, but their parameter lists differ in number — one takes a single `String`, the other a `String` and an `int`. That's a valid overload, and Java resolves which one to run by matching the call site's arguments against each signature.

- B is wrong — overloading exists precisely so methods *can* share a name, as long as their parameter lists differ.
- C is wrong — there's no ambiguity. `logEvent("Auto started")` has exactly one argument, which only matches the one-parameter signature.
- D is wrong — overloaded methods are told apart by their parameter lists (number or type), not by return type. Two methods with identical parameter lists but different return types wouldn't compile, but that isn't the case here.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that calls an overloaded method with two arguments to report a match score.

Reorder the fragments below into a working program:

- a. `        System.out.println(teamName + " scored " + score + " points");`
- b. `public class MatchReport`
- c. `    }`
- d. `{`
- e. `    public static void reportMatchScore(String teamName, int score)`
- f. `        reportMatchScore("Shockwave", 145);`
- g. `    public static void main(String[] args)`
- h.
  ```java
      }
  }
  ```
- i. `    {`
- j. `    {`

**Answer:** b, d, g, i, f, c, e, j, a, h

```java
public class MatchReport
{
    public static void main(String[] args)
    {
        reportMatchScore("Shockwave", 145);
    }

    public static void reportMatchScore(String teamName, int score)
    {
        System.out.println(teamName + " scored " + score + " points");
    }
}
```

**Why this order:** The class line (`b`) and its opening brace (`d`) come first. `main` (`g`) is declared next with its own opening brace (`i`); the call to `reportMatchScore` (`f`) sits inside `main`'s body, matching the method's parameter order exactly — `String` first, then `int`. `main`'s body closes (`c`) before `reportMatchScore`'s own signature (`e`) and opening brace (`j`) begin. Inside that method, `teamName` is used as the parameter name — a variable in the method's own header — while `"Shockwave"` and `145` were the arguments supplied at the call site. The `println` (`a`) lives inside that method's body, and then `h` — the method's closing brace immediately followed by the class's closing brace, merged into a single fragment since nothing could ever validly go between them — ends the program.
