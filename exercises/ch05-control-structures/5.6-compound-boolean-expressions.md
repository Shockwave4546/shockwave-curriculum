## Multiple Choice

**Question:** Given:

```java
boolean armExtended = true;
boolean hookEngaged = true;
boolean manualOverride = true;

boolean readyToClimb = !armExtended && hookEngaged || manualOverride;
```

What is the value of `readyToClimb`?

**Options:**

- A. `true`
- B. `false`
- C. It won't compile — the expression needs parentheses to be legal
- D. It depends on the order the variables were declared in

**Answer:** A

**Why:** `!` binds tightest, then `&&`, then `||` — so this parses as `(!armExtended && hookEngaged) || manualOverride`. `!armExtended` is `false`, so `false && hookEngaged` is `false` no matter what `hookEngaged` is. But then `false || manualOverride` is `false || true`, which is `true`. Overall: `true`.

- B is wrong because that's the result if `||` were mistakenly evaluated before `&&` (grouping it as `!armExtended && (hookEngaged || manualOverride)`) — but Java's actual precedence always applies `&&` before `||`.
- C is wrong because the expression is completely legal without parentheses; Java always applies a fixed precedence order on its own, it doesn't require parentheses to compile.
- D is wrong because the order variables are declared in never changes how an expression's operators are grouped — only precedence rules and parentheses control that.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program where a vision camera object might not be connected (represented as a possibly-`null` variable). Print `"TARGET FOUND"` if the camera exists and reports a target; otherwise print `"NO TARGET"`. Checking for `null` first is what keeps a missing camera from crashing the program.

Reorder the fragments below into a working program:

- a. `        if (visionCamera != null && visionCamera.hasTarget())`
- b. `    {`
- c. *(three lines, merged — this branch's only statement and its own braces, since nothing else could ever validly go between them)*
  ```java
          {
              System.out.println("NO TARGET");
          }
  ```
- d. `}`
- e. `public class TargetCheck`
- f. `        else`
- g. *(three lines, merged — this branch's only statement and its own braces)*
  ```java
          {
              System.out.println("TARGET FOUND");
          }
  ```
- h. `    public static void main(String[] args)`
- i. `        Camera visionCamera = null;`
- j. `    }`
- k. `{`

**Answer:** e, k, h, b, i, a, g, f, c, j, d

```java
public class TargetCheck
{
    public static void main(String[] args)
    {
        Camera visionCamera = null;

        if (visionCamera != null && visionCamera.hasTarget())
        {
            System.out.println("TARGET FOUND");
        }
        else
        {
            System.out.println("NO TARGET");
        }
    }
}
```

**Why this order:** The class (`e`) and its opening brace (`k`) come first, followed by `main` (`h`) and its own opening brace (`b`). `visionCamera` (`i`) has to exist before it can be checked. Inside the `if`'s condition (`a`), `visionCamera != null` is checked first specifically because `&&` short-circuits — if it's `false`, `visionCamera.hasTarget()` is never called, which is exactly what avoids a crash on a missing camera. Its single-statement body and braces are merged into one fragment (`g`), since nothing else could ever validly go inside them. `else` (`f`) directly follows, with its own merged body (`c`). `main`'s body then closes (`j`), followed by the class's own closing brace (`d`).
