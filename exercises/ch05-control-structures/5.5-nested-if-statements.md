# Nested if Statements — Exercises

## Multiple Choice

**Question:** (The indentation below is shown exactly as a teammate typed it — on purpose.)

```java
if (batteryVoltage > 11.0)
    if (allSensorsOk)
        System.out.println("READY");
else
    System.out.println("NOT READY");
```

If `batteryVoltage` is `10.5`, what prints?

**Options:**

- A. `NOT READY`, because the `else` attaches to the outer `if`
- B. Nothing prints, because the `else` attaches to the inner `if`, and the outer condition is false
- C. `READY`, because `allSensorsOk` is never checked when voltage is low
- D. It doesn't compile, because an `if` inside an `if` needs braces

**Answer:** B

**Why:** Without braces, an `else` always attaches to the closest unmatched `if`, regardless of indentation — here, that's the inner `if (allSensorsOk)`, not the outer one. Since `batteryVoltage > 11.0` is false, the entire outer `if`'s body — including that inner `if`/`else` pair — never runs at all. Nothing prints.

- A is wrong because that's what the indentation visually suggests, but Java ignores indentation entirely; the `else` binds to the nearest unmatched `if`, which is the inner one.
- C is wrong because it's true that `allSensorsOk` is never checked, but that also means the inner `if`/`else` block — including its `else` — never runs, so nothing prints, not `READY`.
- D is wrong because nested `if` statements without braces compile just fine in Java; it's a readability and correctness hazard (the dangling-else problem), not a compiler error.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a program that prints `"FAST"` if a climb took under 10 seconds, `"OK"` if it took under 20 seconds, or `"SLOW"` otherwise — the trailing `else` makes sure every possible climb time lands somewhere, instead of silently doing nothing.

Reorder the fragments below into a working program:

- a. `        if (climbTime < 10.0)`
- b. *(three lines, merged — this branch's only statement and its own braces, since nothing else could ever validly go between them)*
  ```java
          {
              System.out.println("FAST");
          }
  ```
- c. `public class ClimbSpeed`
- d. `        else if (climbTime < 20.0)`
- e. `    public static void main(String[] args)`
- f. *(three lines, merged — this branch's only statement and its own braces)*
  ```java
          {
              System.out.println("OK");
          }
  ```
- g. `        else`
- h. `{`
- i. *(three lines, merged — this branch's only statement and its own braces)*
  ```java
          {
              System.out.println("SLOW");
          }
  ```
- j. `    {`
- k. `        double climbTime = 14.5;`
- l. *(two lines, merged into one fragment — nothing valid can ever come between the closing brace of `main` and the closing brace of the class)*
  ```java
      }
  }
  ```

**Answer:** c, h, e, j, k, a, b, d, f, g, i, l

```java
public class ClimbSpeed
{
    public static void main(String[] args)
    {
        double climbTime = 14.5;

        if (climbTime < 10.0)
        {
            System.out.println("FAST");
        }
        else if (climbTime < 20.0)
        {
            System.out.println("OK");
        }
        else
        {
            System.out.println("SLOW");
        }
    }
}
```

**Why this order:** The class (`c`) and its opening brace (`h`) open the program, followed by `main` (`e`) and its own opening brace (`j`). `climbTime` (`k`) has to be declared before anything checks it. The `if` (`a`) comes first in the chain; its single-statement body and own braces are merged into one fragment (`b`) since nothing else could ever validly sit inside them. `else if` (`d`) has to directly follow that closing brace — it's part of the same chain, not a separate statement — with its own merged body (`f`). The final `else` (`g`) has no condition of its own: it catches every climb time that didn't match either range above, so `"SLOW"` is a real reachable outcome instead of the chain silently doing nothing; its body is merged the same way (`i`). Only one of the three branches ever runs. Finally, `l` — the method's closing brace immediately followed by the class's closing brace, merged into a single fragment since nothing could ever validly go between them — ends the program.
