# While Loops — Exercises

## Multiple Choice

**Question:**

```java
int shotsRemaining = 0;
while (shotsRemaining > 0)
{
    System.out.println("Firing shot " + shotsRemaining);
    shotsRemaining--;
}
System.out.println("Done");
```

What prints?

**Options:**

- A. `Firing shot 0` then `Done`
- B. Just `Done`
- C. An infinite loop of `Firing shot` lines
- D. Nothing prints at all — not even `Done`

**Answer:** B

**Why:** A `while` loop checks its condition *before* every pass, including the first. Here `shotsRemaining` starts at `0`, so `shotsRemaining > 0` is false immediately — the loop body never runs, not even once. Execution just falls through to the `println("Done")` line that follows the loop.

- A is wrong because the loop body never executes at all when the starting condition is already false, so `Firing shot 0` is never printed.
- C is wrong because a loop that never starts can't run infinitely — there's no infinite loop here at all.
- D is wrong because the `Done` line isn't inside the loop — it always runs after the loop, regardless of whether the loop body ever executed.

## Micro-Parsons

**Problem:** Given this class and main method, reorder the fragments below into the method body that simulates retrying a camera connection. Each attempt increments a counter, then marks the connection as established once at least 2 attempts have been made. Print each attempt's number and current connection status. Stop once connected, or after 5 attempts.

```java
public class ConnectionRetry
{
    public static void main(String[] args)
    {
        // your reordered fragments go here
    }
}
```

Reorder the fragments below to complete it:

- a. `        while (!connected && attempts < 5)`
- b. `            connected = (attempts >= 2);`
- c. `        boolean connected = false;`
- d. `        }`
- e. `        int attempts = 0;`
- f. `            System.out.println("Attempt " + attempts + " connected=" + connected);`
- g. `            attempts++;`
- h. `        {`

**Answer:** e, c, a, h, g, b, f, d

**Interchangeable:** (e, c)

```java
public class ConnectionRetry
{
    public static void main(String[] args)
    {
        int attempts = 0;
        boolean connected = false;

        while (!connected && attempts < 5)
        {
            attempts++;
            connected = (attempts >= 2);
            System.out.println("Attempt " + attempts + " connected=" + connected);
        }
    }
}
```

**Why this order:** Both `attempts` (`e`) and `connected` (`c`) — the loop's initialize step — have to exist before the `while` header (`a`) can test them (in either order, so `e` and `c` are marked interchangeable), and its opening brace (`h`) follows right after. Inside the loop, `attempts` has to be incremented (`g`) *before* `connected` is recomputed (`b`), since the connection check depends on the updated count. The `println` (`f`) comes last in the body because it reports both values *after* they've been updated for this pass, and the closing brace (`d`) ends the loop. The surrounding class and `main` method are the given scaffold; only the declarations and the loop needed reordering.

## Coding

**Mode:** harness

**Problem:** A shop has `remaining` batteries to charge and its chargers handle `perDay` batteries each
day. Write `daysToFinish`, which returns how many days it takes to charge them all. Use a `while` loop: each
pass is one day, and each day charges `perDay` batteries (the last day may charge fewer than `perDay`, which
is fine). `perDay` is always at least `1`. If there is nothing left to charge (`remaining` is `0` or less),
the answer is `0`.

Examples:

- `daysToFinish(10, 3)` returns `4` (3, then 3, then 3, then the last 1)
- `daysToFinish(9, 3)` returns `3`
- `daysToFinish(1, 5)` returns `1`

**Signature:** `public static int daysToFinish(int remaining, int perDay)`

**Starter:**

```java
public class Solution
{
    public static int daysToFinish(int remaining, int perDay)
    {
        // TODO: count the days in a while loop
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `10, 3` | `4` |
| yes | `9, 3` | `3` |
| yes | `1, 5` | `1` |
| no | `0, 4` | `0` |
| no | `-2, 3` | `0` |
| no | `12, 4` | `3` |
| no | `13, 4` | `4` |

**Solution:**

```java
public class Solution
{
    public static int daysToFinish(int remaining, int perDay)
    {
        int days = 0;
        while (remaining > 0)
        {
            remaining = remaining - perDay;
            days++;
        }
        return days;
    }
}
```

**Why:** The loop's three steps are all there: `days` and `remaining` start before the loop, the test
`remaining > 0` is checked before every pass, and `remaining` shrinks inside the body so the loop
eventually ends (forget that update line and the method never returns). Because a `while` checks first, a
starting `remaining` of `0` or less runs the body zero times and returns `0`. A `do-while` would run the body
once before checking, wrongly giving `1` for `0, 4` and `-2, 3`.
