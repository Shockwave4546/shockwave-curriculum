# Nested Iteration — Exercises

## Multiple Choice

**Question:** A teammate writes this nested loop, intending to print `0` and `1` for each of two outer passes:

```java
for (int i = 0; i < 2; i++)
{
    for (int i = 0; i < 2; i++)
    {
        System.out.println(i);
    }
}
```

What happens?

**Options:**

- A. It compiles and prints `0 1 0 1` (each pass correctly)
- B. It compiles but the inner loop never runs
- C. It fails to compile — the inner `i` conflicts with the outer `i` in the same scope
- D. It compiles and runs forever, since both loops share the same variable

**Answer:** C

**Why:** A loop variable declared in a `for` header is a real variable declaration. Declaring a second `int i` inside the outer loop's body — while the outer `i` is still in scope — is a duplicate declaration in the same scope, which Java rejects at compile time. Nested loops need distinct variable names (like `row`/`col` or `i`/`j`) specifically to avoid this.

- A is wrong because that's what would happen if the two loops used two different variable names; as actually written, the program never compiles, so nothing prints.
- B is wrong because it's not that the inner loop specifically fails to run — the entire program fails to compile, so neither loop ever runs.
- D is wrong because reusing the same variable name isn't a runtime infinite-loop problem — it's a compile-time naming conflict, so the program never even gets the chance to run.

## Micro-Parsons

**Problem:** Given this class and main method, reorder the fragments below into the method body that uses nested `for` loops to print every combination of a path number (1 to 2) and a waypoint number (1 to 3), in the format `Path P Waypoint W`, with the path loop on the outside.

```java
public class PathPlanner
{
    public static void main(String[] args)
    {
        // your reordered fragments go here
    }
}
```

Reorder the fragments below to complete it:

- a. `            }`
- b. `            for (int waypoint = 1; waypoint <= 3; waypoint++)`
- c. `        }`
- d. `                System.out.println("Path " + path + " Waypoint " + waypoint);`
- e. `        for (int path = 1; path <= 2; path++)`
- f. `        {`
- g. `            {`

**Answer:** e, f, b, g, d, a, c

```java
public class PathPlanner
{
    public static void main(String[] args)
    {
        for (int path = 1; path <= 2; path++)
        {
            for (int waypoint = 1; waypoint <= 3; waypoint++)
            {
                System.out.println("Path " + path + " Waypoint " + waypoint);
            }
        }
    }
}
```

**Why this order:** The outer loop (`e`) and its opening brace (`f`) come first. For every single value of `path`, the inner loop (`b`) — using a distinct variable name, since a second `int path` in the same scope wouldn't compile — restarts completely, opening its own brace (`g`) fresh each time. The print statement (`d`) is the inner loop's only body line. The braces then close in reverse order: the inner loop's body first (`a`), then the outer loop's body last (`c`). The surrounding class and `main` method are the given scaffold; only the two loops needed reordering.

## Coding

**Mode:** harness

**Problem:** The vision system scans a square grid with `size` rows and `size` columns, both numbered
`1` through `size`. A cell is a "hit" when its row number plus its column number equals `target`. Write
`countHits`, which uses nested loops to return how many cells in the grid are hits. If no cell matches, the
answer is `0`.

Examples:

- `countHits(3, 4)` returns `3` (cells row 1/col 3, row 2/col 2, row 3/col 1)
- `countHits(3, 2)` returns `1` (only row 1/col 1)
- `countHits(4, 100)` returns `0`

**Signature:** `public static int countHits(int size, int target)`

**Starter:**

```java
public class Solution
{
    public static int countHits(int size, int target)
    {
        // TODO: visit every row and column, and count the hits
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `3, 4` | `3` |
| yes | `3, 2` | `1` |
| yes | `4, 100` | `0` |
| no | `3, 6` | `1` |
| no | `4, 5` | `4` |
| no | `5, 3` | `2` |
| no | `1, 2` | `1` |

**Solution:**

```java
public class Solution
{
    public static int countHits(int size, int target)
    {
        int hits = 0;
        for (int row = 1; row <= size; row++)
        {
            for (int col = 1; col <= size; col++)
            {
                if (row + col == target)
                {
                    hits++;
                }
            }
        }
        return hits;
    }
}
```

**Why:** The outer loop picks a row; for each row the inner loop runs through every column from the start,
so every `(row, col)` pair is checked exactly once. The two loops need distinct variable names (`row` and
`col`). Both start at `1` and use `<=`, so the last row and last column are included: stopping with `<`
misses the corner cell `(size, size)`, which is the only hit for `3, 6`, and the hits at the edges for `4, 5`.
