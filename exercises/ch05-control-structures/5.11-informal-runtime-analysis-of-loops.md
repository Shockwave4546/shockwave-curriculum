# Informal Runtime Analysis of Loops — Exercises

## Multiple Choice

**Question:** How many times does this loop run?

```java
for (int i = 4; i < 9; i++)
{
    ...
}
```

**Options:**

- A. 5
- B. 4
- C. 9
- D. 6

**Answer:** A

**Why:** For a `<` bound, the largest value the loop variable actually reaches is one less than the limit — here, `8`, not `9`. Using the formula (largest − smallest + 1): `8 - 4 + 1 = 5`. The loop visits `i = 4, 5, 6, 7, 8` — five values.

- B is wrong because it comes from computing `9 - 4 - 1`, which undercounts by one instead of correctly adding one.
- C is wrong because it just uses the upper bound directly — but `i` never actually reaches `9` for a `<` bound, and this also ignores the starting value entirely.
- D is wrong because it comes from computing `9 - 4 + 1` without first accounting for the `<` bound — that's treating `< 9` as if it were `<= 9`, which is off by one in the other direction.

## Micro-Parsons

**Problem:** Given this class and main method, reorder the fragments below into the method body that uses a nested loop to scan 3 radio channels, each checked with 5 retries, and counts the total number of checks performed with a counter — then prints that total.

```java
public class ChannelScanner
{
    public static void main(String[] args)
    {
        // your reordered fragments go here
    }
}
```

Reorder the fragments below to complete it:

- a. `            for (int retry = 0; retry < 5; retry++)`
- b. `            }`
- c. `        int checkCount = 0;`
- d. `                checkCount++;`
- e. `        System.out.println(checkCount);`
- f. `        for (int channel = 0; channel < 3; channel++)`
- g. `        }`
- h. `        {`
- i. `            {`

**Answer:** c, f, h, a, i, d, b, g, e

```java
public class ChannelScanner
{
    public static void main(String[] args)
    {
        int checkCount = 0;

        for (int channel = 0; channel < 3; channel++)
        {
            for (int retry = 0; retry < 5; retry++)
            {
                checkCount++;
            }
        }

        System.out.println(checkCount);
    }
}
```

**Why this order:** `checkCount` (`c`) starts at `0` before either loop begins. The outer loop (`f`) and its brace (`h`) come next, followed by the inner loop (`a`) and its own brace (`i`) — nested completely inside, restarting for every single outer pass. The increment (`d`) is the innermost statement, running once per inner-loop pass. The braces close in reverse order — inner body (`b`), then outer body (`g`) — and the total only prints (`e`) once both loops have completely finished: `3 × 5 = 15` total checks. The surrounding class and `main` method are the given scaffold; only the two loops needed reordering.

## Coding

**Mode:** harness

**Problem:** Predict a loop's work without running it. Here are two nested loops:

```java
for (int a = outerStart; a < outerLimit; a++)
{
    for (int b = innerStart; b < innerLimit; b++)
    {
        // body
    }
}
```

Write `bodyRuns`, which returns how many times the body runs, **without using any loops**: count each
loop's passes from its header, then multiply. A loop whose start is already at or past its limit runs
`0` times (never a negative number), which makes the total `0`.

Examples:

- `bodyRuns(3, 7, 0, 5)` returns `20` (the outer loop runs 4 times, the inner loop 5)
- `bodyRuns(0, 5, 0, 10)` returns `50`
- `bodyRuns(2, 3, 4, 5)` returns `1`

**Signature:** `public static int bodyRuns(int outerStart, int outerLimit, int innerStart, int innerLimit)`

**Starter:**

```java
public class Solution
{
    public static int bodyRuns(int outerStart, int outerLimit, int innerStart, int innerLimit)
    {
        // TODO: count each loop's passes, then multiply them
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `3, 7, 0, 5` | `20` |
| yes | `0, 5, 0, 10` | `50` |
| yes | `2, 3, 4, 5` | `1` |
| no | `4, 4, 0, 5` | `0` |
| no | `5, 2, 0, 3` | `0` |
| no | `3, 7, 1, 4` | `12` |
| no | `0, 3, 2, 2` | `0` |

**Solution:**

```java
public class Solution
{
    public static int bodyRuns(int outerStart, int outerLimit, int innerStart, int innerLimit)
    {
        int outerPasses = outerLimit - outerStart;
        if (outerPasses < 0)
        {
            outerPasses = 0;
        }
        int innerPasses = innerLimit - innerStart;
        if (innerPasses < 0)
        {
            innerPasses = 0;
        }
        return outerPasses * innerPasses;
    }
}
```

**Why:** For a `<` bound, the loop variable reaches `limit - 1`, so the passes are
`(limit - 1) - start + 1 = limit - start`. Adding `1` (treating the limit as reached) is the lesson's
first pitfall and is what `3, 7, 0, 5` catches. Nested loops multiply, they do not add. When the start is
already at or past the limit, `limit - start` is zero or negative, but a loop can never run a negative
number of times, so the count is clamped to `0`; without that, `5, 2, 0, 3` gives `-9` instead of `0`.
