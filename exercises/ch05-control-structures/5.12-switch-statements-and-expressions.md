# switch Statements and Expressions — Exercises

## Multiple Choice

**Question:** A teammate writes this code to announce the climb level the robot reached:

```java
int climbLevel = 2;

switch (climbLevel)
{
    case 1:
        System.out.println("Low");
    case 2:
        System.out.println("Mid");
    case 3:
        System.out.println("High");
        break;
    default:
        System.out.println("None");
}
```

What prints?

**Options:**

- A. Only `Mid`
- B. `Mid`, then `High`
- C. `Mid`, then `High`, then `None`
- D. `Low`, then `Mid`, then `High`

**Answer:** B

**Why:** Java jumps straight to `case 2:` and prints `Mid`. There's no `break` after it, so execution falls through into `case 3:` and prints `High` too — a case label is only a jump target, and it doesn't stop code that's already running. The `break` after `High` then ends the `switch`, so nothing after it runs.

- A is wrong because it assumes each case stops by itself. In the colon form, only a `break` (or the end of the `switch`) stops execution; without one, the next case's statements run as well.
- C is wrong because the `break` after `High` ends the whole `switch` before `default` is reached. `default` only runs when no label matches, or when execution falls into it.
- D is wrong because the `switch` starts at the label that matches `climbLevel`, which is `case 2:`. Fall-through only moves *forward* from there, so `case 1:` never runs.

## Micro-Parsons

**Problem:** Given this class and main method, reorder the fragments below into the method body that sets the shooter's speed from the field zone the robot is in, using a `switch` expression: zone `1` is `2000` RPM, zones `2` and `3` are `3500` RPM, and any other zone is `0`. Then print the result as `RPM: ` followed by the speed. The robot is in zone `2`.

```java
public class ShotSelector
{
    public static void main(String[] args)
    {
        // your reordered fragments go here
    }
}
```

Reorder the fragments below to complete it:

- a. `            case 2, 3 -> 3500;`
- b. `        System.out.println("RPM: " + rpm);`
- c. `        int rpm = switch (zone)`
- d. `            default -> 0;`
- e. `        {`
- f. `        int zone = 2;`
- g. `            case 1 -> 2000;`
- h. `        };`

**Answer:** f, c, e, g, a, d, h, b

**Interchangeable:** (g, a, d)

```java
public class ShotSelector
{
    public static void main(String[] args)
    {
        int zone = 2;
        int rpm = switch (zone)
        {
            case 1 -> 2000;
            case 2, 3 -> 3500;
            default -> 0;
        };
        System.out.println("RPM: " + rpm);
    }
}
```

**Why this order:** `zone` (`f`) has to exist before the `switch` can look at it. The `switch` expression starts with `int rpm = switch (zone)` (`c`) and its opening brace (`e`). The three cases (`g`, `a`, `d`) go inside the braces. They can be in any order: arrow cases never fall through, and `default` only applies when no other label matches, wherever it sits — that's why `g`, `a` and `d` are marked interchangeable. Listing `default` last is the usual style. The closing `};` (`h`) ends the `switch` and, with its semicolon, the whole `int rpm = ...` assignment. Only then does `rpm` hold a value, so the `println` (`b`) comes last. It prints `RPM: 3500`. The surrounding class and `main` method are the given scaffold; only the method body needed reordering.

## Coding

**Mode:** harness

**Problem:** The drive team picks an autonomous mode with a number. Write `autoPlan`, which uses a
`switch` to return the plan for that mode: mode `1` is `"Drive forward"`, mode `2` is `"Score one piece"`,
modes `3` and `4` are both `"Score two pieces"`, and any other number is `"Do nothing"`.

Examples:

- `autoPlan(1)` returns `"Drive forward"`
- `autoPlan(3)` returns `"Score two pieces"`
- `autoPlan(9)` returns `"Do nothing"`

**Signature:** `public static String autoPlan(int mode)`

**Starter:**

```java
public class Solution
{
    public static String autoPlan(int mode)
    {
        // TODO: use a switch to pick the plan
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `1` | `"Drive forward"` |
| yes | `3` | `"Score two pieces"` |
| yes | `9` | `"Do nothing"` |
| no | `2` | `"Score one piece"` |
| no | `4` | `"Score two pieces"` |
| no | `0` | `"Do nothing"` |
| no | `-1` | `"Do nothing"` |

**Solution:**

```java
public class Solution
{
    public static String autoPlan(int mode)
    {
        String plan = switch (mode)
        {
            case 1 -> "Drive forward";
            case 2 -> "Score one piece";
            case 3, 4 -> "Score two pieces";
            default -> "Do nothing";
        };
        return plan;
    }
}
```

**Why:** A `switch` expression looks at `mode` once and produces the matching case's value, with no
`break` to forget. `case 3, 4` lists two labels for one result, so mode `4` is covered. The `default`
is required, because a `switch` expression on an `int` must handle every value, and it also supplies
`"Do nothing"` for `0`, `-1` and `9`. The semicolon after the closing brace is needed, since the whole
`switch` is the right-hand side of an assignment. In the colon form (`case 1:`), a missing `break` lets
mode `1` fall through and return a later case's text.
