# Implementing Selection and Iteration Algorithms — Exercises

## Multiple Choice

**Question:** A teammate wants a warning to print roughly 25% of the time a sensor is read, and writes:

```java
if (Math.random() < 0.25)
{
    System.out.println("Sensor glitch simulated");
}
```

They run this exact code 4 times in a row and are confused that `"Sensor glitch simulated"` printed 0 times, not exactly once. What's the best explanation?

**Options:**

- A. The code has a bug — `< 0.25` should be `== 0.25`
- B. `Math.random()` only returns values above `0.5`, so this condition can never trigger
- C. `0.25` is a probability, not a guaranteed count — over just 4 tries, it's entirely normal for the event to not happen even once
- D. `Math.random()` must be seeded first, or it always returns the same value

**Answer:** C

**Why:** `Math.random() < 0.25` is true with probability 25% on any single call — it doesn't guarantee "1 out of every 4 tries." Over only 4 tries, getting zero matches (or two, or more) is completely normal; the 25% figure only describes the average over many, many tries, not a fixed count in a small sample.

- A is wrong because `== 0.25` would almost never be true — `Math.random()` returns values across an essentially continuous range, so `< 0.25` is exactly the right way to express a 25% chance.
- B is wrong because `Math.random()` returns a value from `0.0` up to (not including) `1.0`, spread evenly across that entire range — not restricted to values above `0.5`.
- D is wrong because `Math.random()` works correctly for this kind of simulation without any manual seeding step; it doesn't return the same fixed value on repeated calls.

## Micro-Parsons

**Problem:** Given this class and main method, reorder the fragments below into the method body that uses a `for` loop counting from 1 to 6 to count how many of those numbers are divisible by 3, then prints the count.

```java
public class MultipleCounter
{
    public static void main(String[] args)
    {
        // your reordered fragments go here
    }
}
```

Reorder the fragments below to complete it:

- a. `            if (n % 3 == 0)`
- b. `        System.out.println(multipleCount);`
- c. `        int multipleCount = 0;`
- d. `            }`
- e. `                multipleCount++;`
- f. `        for (int n = 1; n <= 6; n++)`
- g. `        }`
- h. `            {`
- i. `        {`

**Answer:** c, f, i, a, h, e, d, g, b

```java
public class MultipleCounter
{
    public static void main(String[] args)
    {
        int multipleCount = 0;

        for (int n = 1; n <= 6; n++)
        {
            if (n % 3 == 0)
            {
                multipleCount++;
            }
        }

        System.out.println(multipleCount);
    }
}
```

**Why this order:** `multipleCount` (`c`) — the accumulator — has to start at `0` before the loop begins. The `for` header (`f`) and its opening brace (`i`) come next. Inside, the `if` (`a`) and its brace (`h`) check each number; the increment (`e`) is what makes this a frequency count, and it has to live *inside* the `if`, not directly in the loop body, or it would count every number instead of just the matching ones. The braces close in reverse order — the `if`'s body (`d`), then the loop's body (`g`) — and the final count prints (`b`) only after the loop has finished. The surrounding class and `main` method are the given scaffold; only the loop and its `if` needed reordering.

## Coding

**Mode:** harness

**Problem:** A gyro test model says the drift error at second `t` is `t * t - 6 * t`, measured for every
second from `1` up to and including `seconds`. Drift can be negative. Write `highestDrift`, which returns
the **largest** drift reading over those seconds. `seconds` is at least `1`.

Examples:

- `highestDrift(8)` returns `16` (the readings are `-5, -8, -9, -8, -5, 0, 7, 16`)
- `highestDrift(6)` returns `0`
- `highestDrift(7)` returns `7`

**Signature:** `public static int highestDrift(int seconds)`

**Starter:**

```java
public class Solution
{
    public static int highestDrift(int seconds)
    {
        // TODO: track the largest reading seen so far while looping
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `8` | `16` |
| yes | `6` | `0` |
| yes | `7` | `7` |
| no | `1` | `-5` |
| no | `3` | `-5` |
| no | `4` | `-5` |
| no | `5` | `-5` |

**Solution:**

```java
public class Solution
{
    public static int highestDrift(int seconds)
    {
        int highest = Integer.MIN_VALUE;
        for (int t = 1; t <= seconds; t++)
        {
            int drift = t * t - 6 * t;
            if (drift > highest)
            {
                highest = drift;
            }
        }
        return highest;
    }
}
```

**Why:** This is the lesson's min/max pattern: an accumulator (`highest`) plus an `if` inside the loop
that replaces it whenever a bigger reading turns up. The seed matters. Starting `highest` at `0` is the
lesson's wrong-starting-value pitfall: when every reading is negative (`seconds` from `1` to `5`), `0`
beats all of them and the method wrongly returns `0`. `Integer.MIN_VALUE`, the most negative `int`, loses to
every real reading, so the first one always replaces it. Seeding with the first reading (`-5`) would also
work.
