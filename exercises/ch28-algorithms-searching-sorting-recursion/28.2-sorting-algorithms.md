# Sorting Algorithms — Exercises

## Multiple Choice

**Question:** The lesson's selection sort is run on an array of shooter spin-up times (in hundredths of a second). What does the array look like after the first **two** passes of the outer loop (`j = 0` and `j = 1`)?

```java
int[] spinUpTimes = {31, 19, 42, 8, 3};
```

**Options:**

- A. `{3, 8, 42, 19, 31}`
- B. `{3, 8, 19, 31, 42}`
- C. `{19, 31, 42, 8, 3}`
- D. `{3, 8, 31, 19, 42}`

**Answer:** A

**Why:** In pass `j = 0`, the smallest value in the whole array is `3`, at index 4. It swaps with index 0, giving `{3, 19, 42, 8, 31}`. In pass `j = 1`, the smallest value from index 1 onward is `8`, at index 3. It swaps with index 1, giving `{3, 8, 42, 19, 31}`. Each pass puts exactly one value into its final position and swaps whatever was there into the old spot of the minimum. The rest of the array doesn't get tidied up along the way.

- B is wrong. That's the fully sorted array, which selection sort only reaches after all four passes. Two passes fix only the first two positions.
- C is wrong. That's what the first two passes of *insertion* sort produce: `19` is inserted in front of `31`, and then `42` stays where it is.
- D is wrong. That's what you'd get by *shifting* each minimum into place and moving the other values right, like insertion sort does. Selection sort *swaps* instead, so after pass 0 the `31` from index 0 ends up at index 4.

## Micro-Parsons

**Problem:** Given a `BatteryLog` class with a `main` method that creates `double[] batteryVoltages = {12.4, 11.9, 12.8, 12.1};`, calls `sortVoltages(batteryVoltages);`, and prints the result, plus the signature and braces of the `sortVoltages(double[] voltages)` method, reorder the fragments below into the method body. The body should insertion-sort `voltages` from lowest to highest.

Reorder the fragments below to complete it:

- a. `    while (possibleIndex > 0 && temp < voltages[possibleIndex - 1])`
- b. `}`
- c. `        possibleIndex--;`
- d. `    double temp = voltages[j];`
- e. `for (int j = 1; j < voltages.length; j++)`
- f. `    {`
- g. `    voltages[possibleIndex] = temp;`
- h. `        voltages[possibleIndex] = voltages[possibleIndex - 1];`
- i. `{`
- j. `    int possibleIndex = j;`
- k. `    }`

**Answer:** e, i, d, j, a, f, h, c, k, g, b

**Interchangeable:** (d, j)

```java
public class BatteryLog
{
    public static void sortVoltages(double[] voltages)
    {
        for (int j = 1; j < voltages.length; j++)
        {
            double temp = voltages[j];
            int possibleIndex = j;
            while (possibleIndex > 0 && temp < voltages[possibleIndex - 1])
            {
                voltages[possibleIndex] = voltages[possibleIndex - 1];
                possibleIndex--;
            }
            voltages[possibleIndex] = temp;
        }
    }

    public static void main(String[] args)
    {
        double[] batteryVoltages = {12.4, 11.9, 12.8, 12.1};
        sortVoltages(batteryVoltages);
        for (double voltage : batteryVoltages)
        {
            System.out.print(voltage + " ");
        }
        System.out.println();
    }
}
```

**Why this order:** The outer loop (`e`, `i`) starts at `j = 1`, because a single element at index 0 already counts as sorted. It runs through the last index so every element gets inserted. Inside it, the value being inserted is saved in `temp` (`d`) and its starting position in `possibleIndex` (`j`). Those two lines don't depend on each other, so they can go in either order. Both have to come before the `while` loop (`a`, `f`), because its condition reads both of them. Inside the `while`, the shift (`h`) must come before `possibleIndex--;` (`c`), since the shift copies from `possibleIndex - 1` into `possibleIndex` and needs the current position. After the `while` closes (`k`), `temp` is written into the gap (`g`). That step runs once per pass, after the shifting is done, and not once per shift. The outer loop's brace (`b`) closes last. The class, `main`, and the method's signature and braces are the given scaffold. The finished program prints `11.9 12.1 12.4 12.8 ` (with a trailing space).

## Coding

**Mode:** harness

**Problem:** A leaderboard needs scores from highest to lowest. Write `sortDescending` using
**selection sort**: for each position from the front, find the **largest** value in the part of the
array not yet sorted and swap it into that position. Sort `scores` in place and also return it.
Duplicates are allowed, and the array may be empty.

Examples:

- `sortDescending(new int[] {3, 9, 1})` returns `{9, 3, 1}`
- `sortDescending(new int[] {5})` returns `{5}`
- `sortDescending(new int[] {1, 2, 3})` returns `{3, 2, 1}`

**Signature:** `public static int[] sortDescending(int[] scores)`

**Starter:**

```java
public class Solution
{
    public static int[] sortDescending(int[] scores)
    {
        // TODO: selection sort, largest first, then return scores
    }
}
```

**Tests:**

| Visible | Arguments | Expected |
|---|---|---|
| yes | `new int[] {3, 9, 1}` | `new int[] {9, 3, 1}` |
| yes | `new int[] {5}` | `new int[] {5}` |
| yes | `new int[] {1, 2, 3}` | `new int[] {3, 2, 1}` |
| no | `new int[] {3, 1, 2}` | `new int[] {3, 2, 1}` |
| no | `new int[] {4, 4, 2, 4}` | `new int[] {4, 4, 4, 2}` |
| no | `new int[] {2, 8, 5, 8, 1}` | `new int[] {8, 8, 5, 2, 1}` |
| no | `new int[] {}` | `new int[] {}` |

**Solution:**

```java
public class Solution
{
    public static int[] sortDescending(int[] scores)
    {
        for (int j = 0; j < scores.length - 1; j++)
        {
            int maxIndex = j;
            for (int k = j + 1; k < scores.length; k++)
            {
                if (scores[k] > scores[maxIndex])
                {
                    maxIndex = k;
                }
            }
            int temp = scores[j];
            scores[j] = scores[maxIndex];
            scores[maxIndex] = temp;
        }
        return scores;
    }
}
```

**Why:** This is the lesson's selection sort with the comparison flipped from "smallest" to
"largest". The outer loop picks the position `j` to fill next; the inner loop starts at `j + 1`
(everything before `j` is already placed) and remembers the index of the largest value seen; then
one swap puts it in position `j`. The outer loop stops at `length - 1` because the last element is
already in place after the others are. Stopping one pass earlier (`length - 2`) can leave the last
two values swapped, as in `{3, 1, 2}`, which is why a hidden test uses it. `length - 1` also makes
the empty array safe: the loop body never runs.
