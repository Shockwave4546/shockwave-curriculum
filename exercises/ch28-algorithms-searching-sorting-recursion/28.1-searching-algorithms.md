# Searching Algorithms — Exercises

## Multiple Choice

**Question:** A teammate runs the lesson's `binarySearch` method on an array of motor controller IDs that was never sorted. What does this call return?

```java
int[] controllerIds = {14, 3, 22, 9, 30};
System.out.println(binarySearch(controllerIds, 3));
```

**Options:**

- A. `1`, the index where `3` is stored
- B. `-1`, even though `3` is in the array
- C. Nothing, because the `while` loop never ends
- D. It throws an `ArrayIndexOutOfBoundsException`

**Answer:** B

**Why:** The first check looks at the middle, `controllerIds[2]`, which is `22`. Because `3 < 22`, the method sets `right = 1`, keeping only indexes 0 and 1. The next middle is `(0 + 1) / 2 = 0`, and `controllerIds[0]` is `14`. Because `3 < 14`, the method sets `right = -1`. Now `left > right`, so the loop ends and the method returns `-1`. The `3` at index 1 is never checked. Binary search assumes everything left of the middle is smaller and everything right of it is larger. That's only true for sorted data, so on unsorted data it can throw away the half that holds the target.

- A is wrong. `3` really is at index 1, but binary search never looks there. Linear search would return `1`, because it checks every element.
- C is wrong. Every check either lowers `right` or raises `left`, so the range always shrinks. Once `left > right`, `while (left <= right)` is false and the loop stops. Unsorted data gives a wrong answer, but the loop still ends.
- D is wrong. `middle` is always between `left` and `right`, and the loop only runs while `left <= right`, so the method never reads outside the array.

## Micro-Parsons

**Problem:** Given a `SubsystemLookup` class whose `main` method already creates `String[] subsystems = {"Drivetrain", "Intake", "Shooter", "Climber"};` and prints `indexOfSubsystem(subsystems, "Shooter")`, reorder the fragments below into the `indexOfSubsystem` method. It should do a linear search of `subsystems` for `name` and return the index of the match, or `-1` if there is no match. The array holds `String`s, so compare them with `.equals()`.

Reorder the fragments below into the complete method:

- a. `        {`
- b. `    return -1;`
- c. `public static int indexOfSubsystem(String[] subsystems, String name)`
- d. `        }`
- e. `    for (int i = 0; i < subsystems.length; i++)`
- f. `}`
- g. `            return i;`
- h. `    {`
- i. `        if (subsystems[i].equals(name))`
- j. `{`
- k. `    }`

**Answer:** c, j, e, h, i, a, g, d, k, b, f

```java
public class SubsystemLookup
{
    public static int indexOfSubsystem(String[] subsystems, String name)
    {
        for (int i = 0; i < subsystems.length; i++)
        {
            if (subsystems[i].equals(name))
            {
                return i;
            }
        }
        return -1;
    }

    public static void main(String[] args)
    {
        String[] subsystems = {"Drivetrain", "Intake", "Shooter", "Climber"};
        System.out.println(indexOfSubsystem(subsystems, "Shooter"));
    }
}
```

**Why this order:** The method signature (`c`) and its opening brace (`j`) come first. The `for` loop (`e`, `h`) visits each index in order, which is what makes this a linear search. The check (`i`) goes inside the loop and uses `.equals()`, because `==` on `String`s compares identity, not content. When it matches, `return i;` (`g`) goes inside the `if`'s braces (`a`, `d`), since returning as soon as a match is found is fine. `return -1;` (`b`) has to come after the loop's closing brace (`k`), because the method can only decide the name is missing after it has checked every element. Putting `return -1;` inside the loop is wrong for two reasons. Java won't compile it, because the method would have no `return` for the case where the loop never runs. And the logic would be wrong anyway: the method would give up after checking only index 0. The method's closing brace (`f`) comes last. The class and `main` are the given scaffold. The finished program prints `2`, since `"Shooter"` is at index 2.
