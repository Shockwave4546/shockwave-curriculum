# Recursion — Exercises

## Multiple Choice

**Question:** A teammate writes a recursive method that counts how many 2-foot drive steps it takes to cover a distance. What happens when `main` calls `stepsToCover(5)`?

```java
public static int stepsToCover(int feet)
{
    if (feet == 0)
    {
        return 0;
    }
    else
    {
        return 1 + stepsToCover(feet - 2);
    }
}
```

**Options:**

- A. It returns `2`
- B. It returns `3`
- C. It crashes with a `StackOverflowError`
- D. It doesn't compile, because a recursive method has to use a loop to stop

**Answer:** C

**Why:** The calls go `stepsToCover(5)`, `stepsToCover(3)`, `stepsToCover(1)`, `stepsToCover(-1)`, `stepsToCover(-3)`, and so on. Starting from an odd number and subtracting 2 each time, `feet` jumps from `1` to `-1` and is never exactly `0`. The method has a base case, and every call changes the argument, but the argument skips right past the base case and keeps getting further away. The recursion never stops, and the program eventually runs out of call-stack space and crashes with `StackOverflowError`. This is the lesson's "recursive call that doesn't actually shrink the problem" pitfall: the change has to lead *to* the base case, not just change the value.

- A is wrong. That would mean treating `5` as two whole steps and dropping the leftover foot. The method never does that, because no call ever reaches `feet == 0`.
- B is wrong. Rounding up to 3 steps is what a correct version might return (for example, one with a base case of `feet <= 0`). This version has no way to stop once `feet` goes below `0`.
- D is wrong. The method compiles fine. Recursion stops through a base case, not a loop, and Java doesn't check whether that base case will actually be reached.

## Micro-Parsons

**Problem:** A gearbox has several identical stages, and each stage reduces speed by the same ratio. The total reduction is the per-stage ratio multiplied together once per stage (for example, 3 stages at 4:1 is 4 × 4 × 4 = 64:1). Given a `GearboxMath` class whose `main` method prints `totalReduction(3, 4)`, reorder the fragments below into the complete recursive `totalReduction` method. It needs a base case of 0 stages, which is a reduction of `1` (no change), and a recursive call that uses one fewer stage.

Reorder the fragments below into a working method:

- a. `    return ratioPerStage * totalReduction(ratioPerStage, stages - 1);`
- b. `{`
- c. `        return 1;`
- d. `    }`
- e. `public static int totalReduction(int ratioPerStage, int stages)`
- f. `    if (stages == 0)`
- g. `}`
- h. `    {`

**Answer:** e, b, f, h, c, d, a, g

```java
public class GearboxMath
{
    public static int totalReduction(int ratioPerStage, int stages)
    {
        if (stages == 0)
        {
            return 1;
        }
        return ratioPerStage * totalReduction(ratioPerStage, stages - 1);
    }

    public static void main(String[] args)
    {
        System.out.println(totalReduction(3, 4));
    }
}
```

**Why this order:** The signature (`e`) and opening brace (`b`) come first. The base-case check (`f`, `h`, `c`, `d`) has to come before the recursive call. If `a` came first, every call would recurse again right away, and the `stages == 0` check could never run. That's infinite recursion, and Java won't even compile it: the `if` after the `return` is an "unreachable statement" error. Once `stages` reaches `0`, `return 1;` (`c`) ends that call. Any other value skips the `if`, reaches the recursive call (`a`), and passes `stages - 1`, one step closer to the base case. No `else` is needed, because `return 1;` already leaves the method whenever the base case is true. So `a` only runs when `stages` isn't `0`. The method's brace (`g`) closes last. The class and `main` are the given scaffold. The finished program prints `81` (3 × 3 × 3 × 3).
