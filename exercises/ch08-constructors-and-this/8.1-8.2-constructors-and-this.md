# Constructors & "this" — Exercises

## Multiple Choice

**Question:** A teammate writes this constructor for an `Intake` class:

```java
public Intake(int rollerPort)
{
    rollerPort = rollerPort;
}
```

After `Intake front = new Intake(3);`, what is `front.rollerPort`?

**Options:**

- A. `3`
- B. `0`
- C. It won't compile
- D. It depends on where `rollerPort` is declared in the class

**Answer:** B

**Why:** Without `this`, `rollerPort = rollerPort;` assigns the parameter to itself — the closest name in scope on both sides is the parameter, not the instance variable. The instance variable `rollerPort` is never touched, so it stays at its default value for an `int`, which is `0`.

- A is wrong — it assumes the assignment reached the instance variable, but it never does; that's exactly the bug.
- C is wrong — both sides of `rollerPort = rollerPort;` are valid names (the parameter), so this compiles cleanly. The bug is silent, not a compiler error.
- D is wrong — a field's default value doesn't depend on where it's declared in the class; an unset `int` field is always `0` regardless of position.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that builds one `Shooter` and prints the wheel port it was given, using `this` to correctly set the field from the constructor's parameter of the same name.

Reorder the fragments below into a working program:

- a. `    public static void main(String[] args)`
- b. `    private int wheelPort;`
- c. `public class Shooter`
- d. `        System.out.println("Wheel port: " + new Shooter(4).wheelPort);`
- e. `{`
- f. `    public Shooter(int wheelPort)`
- g. `    {`
- h. `    {`
- i. `        this.wheelPort = wheelPort;`
- j. `    }`
- k. `    }` `}`

**Answer:** c, e, b, f, g, i, j, a, h, d, k

```java
public class Shooter
{
    private int wheelPort;

    public Shooter(int wheelPort)
    {
        this.wheelPort = wheelPort;
    }

    public static void main(String[] args)
    {
        System.out.println("Wheel port: " + new Shooter(4).wheelPort);
    }
}
```

**Why this order:** The class line (`c`) comes first with its opening brace (`e`) right after. The field (`b`) is declared before any constructor uses it. The constructor's signature (`f`) and its opening brace (`g`) stay as separate one-line fragments, and its single statement (`i`) and closing brace (`j`) stay separate too — `this.wheelPort = wheelPort;` is the only line that can actually reach the instance variable, since the parameter `wheelPort` shadows the field and the left-hand side needs `this` to mean something different from the right-hand side; that's the exact placement this lesson is testing, so it's kept fully granular rather than fused away. `main` (`a`) is declared next, with its own opening brace (`h`) kept as a separate fragment — `g` and `h` are textually identical (`    {`), so only the surrounding context tells them apart. Note that `j` (the constructor's closing brace) is *not* fused with `a` (main's signature): Java doesn't require `main` to come after the constructor, so that adjacency is a genuine ordering choice, not a forced one. Inside `main`, the `println` (`d`) builds a new `Shooter` and reads its field back. Only at the very end is there a truly forced pair: once `main`'s closing brace is placed, the class's closing brace is the only fragment left with nowhere else it could go, so those two are fused into one fragment (`k`).
