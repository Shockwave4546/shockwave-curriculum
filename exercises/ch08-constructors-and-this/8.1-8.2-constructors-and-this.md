# Constructors & "this" — Exercises

## Multiple Choice

**Question:** A teammate writes this `Intake` class:

```java
public class Intake
{
    private int rollerPort;

    public Intake(int rollerPort)
    {
        rollerPort = rollerPort;
    }

    public static void main(String[] args)
    {
        Intake front = new Intake(3);
        System.out.println(front.rollerPort);
    }
}
```

What does `main` print?

**Options:**

- A. `3`
- B. `0`
- C. It won't compile
- D. It depends on where `rollerPort` is declared in the class

**Answer:** B

**Why:** Without `this`, `rollerPort = rollerPort;` assigns the parameter to itself — the closest name in scope on both sides is the parameter, not the instance variable. The instance variable `rollerPort` is never touched, so it stays at its default value for an `int`, which is `0`. `main` can read the `private` field directly because it lives inside `Intake` itself — `private` only blocks *other* classes.

- A is wrong — it assumes the assignment reached the instance variable, but it never does; that's exactly the bug.
- C is wrong — both sides of `rollerPort = rollerPort;` are valid names (the parameter), so this compiles cleanly. The bug is silent, not a compiler error.
- D is wrong — a field's default value doesn't depend on where it's declared in the class; an unset `int` field is always `0` regardless of position.

## Micro-Parsons

**Problem:** These lines, once correctly ordered, form a complete program that builds one `Shooter` and prints the wheel port it was given, using `this` to correctly set the field from the constructor's parameter of the same name. Order the class body as: the field first, then the constructor, then `main`.

Reorder the fragments below into a working program:

- a. `    public static void main(String[] args)`
- b. `    private int wheelPort;`
- c. `public class Shooter`
- d. `        System.out.println("Wheel port: " + new Shooter(4).wheelPort);`
- e. `{`
- f. `    public Shooter(int wheelPort)`
- g. `    {`
- h. `    {`
- i. `        this.wheelPort = wheelPort;`
- j. `    }`
- k. `    }` `}`

**Answer:** c, e, b, f, g, i, j, a, h, d, k

**Interchangeable:** (g, h)

```java
public class Shooter
{
    private int wheelPort;

    public Shooter(int wheelPort)
    {
        this.wheelPort = wheelPort;
    }

    public static void main(String[] args)
    {
        System.out.println("Wheel port: " + new Shooter(4).wheelPort);
    }
}
```

**Why this order:** The Problem text pins the required order — field, then constructor, then `main` — so follow that rather than guessing from what Java itself would accept (Java doesn't actually require `main` to come after the constructor, but this puzzle does). The class line (`c`) comes first with its opening brace (`e`) right after. The field (`b`) is declared before the constructor that uses it. The constructor's signature (`f`) and its opening brace (`g`) stay as separate one-line fragments, and its single statement (`i`) and closing brace (`j`) stay separate too — `this.wheelPort = wheelPort;` is the only line that can actually reach the instance variable, since the parameter `wheelPort` shadows the field and the left-hand side needs `this` to mean something different from the right-hand side; that's the exact placement this lesson is testing, so it's kept fully granular rather than fused away. `main` (`a`) is declared next, with its own opening brace (`h`) kept as a separate fragment — `g` and `h` are textually identical (`    {`), which is why they're declared Interchangeable: whichever physical fragment lands in which slot, the reassembled program reads the same either way. Only at the very end is there a truly forced pair: once `main`'s closing brace is placed, the class's closing brace is the only fragment left with nowhere else it could go, so those two are fused into one fragment (`k`).

## Coding

**Mode:** full-program

**Problem:** Write the class `Climber` with two `private` instance variables, a motor port (`int`) and a climb
speed (`double`), and two **overloaded constructors**:

- `Climber(int motorPort, double climbSpeed)` sets both values.
- `Climber(int motorPort)` uses a default climb speed of `0.5`. It must **delegate** to the two-argument
  constructor with `this(...)` instead of repeating its code.

Both parameters use the same names as the instance variables, so use `this.` to tell them apart. Add the
two getters `getMotorPort()` and `getClimbSpeed()`.

The fixed `main` reads a number of climbers; each is either `default <port>` or `custom <port> <speed>`.
It builds each one and prints its two values.

For example, `default 4` prints `port 4, speed 0.5`, and `custom 7 0.8` prints `port 7, speed 0.8`.

**Solution:**

```java
import java.util.*;

public class Main
{
    // Don't change main
    public static void main(String[] args)
    {
        Scanner in = new Scanner(System.in);
        int count = in.nextInt();
        for (int i = 0; i < count; i++)
        {
            String kind = in.next();
            int port = in.nextInt();
            Climber climber;
            if (kind.equals("default"))
            {
                climber = new Climber(port);
            }
            else
            {
                double speed = in.nextDouble();
                climber = new Climber(port, speed);
            }
            System.out.println("port " + climber.getMotorPort() + ", speed " + climber.getClimbSpeed());
        }
    }
}

class Climber
{
    private int motorPort;
    private double climbSpeed;

    public Climber(int motorPort)
    {
        this(motorPort, 0.5);
    }

    public Climber(int motorPort, double climbSpeed)
    {
        this.motorPort = motorPort;
        this.climbSpeed = climbSpeed;
    }

    public int getMotorPort()
    {
        return motorPort;
    }

    public double getClimbSpeed()
    {
        return climbSpeed;
    }
}
```

**Why:** In the two-argument constructor, `this.motorPort = motorPort;` copies the parameter into the instance
variable. Without `this.`, `motorPort = motorPort;` assigns the parameter to itself and the field stays at
its default `0` / `0.0`, so every line would print `port 0, speed 0.0`. The one-argument constructor is a
single line, `this(motorPort, 0.5);`, which must be the first statement; that is why a `default` climber
still gets its port set as well as the `0.5` speed. Writing `void Climber(...)` instead would make an
ordinary method, not a constructor, and `new Climber(port)` would then not compile.
